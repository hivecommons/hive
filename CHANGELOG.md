# Changelog

Hive did not historically maintain a complete changelog. This file starts a pragmatic, forward-looking record for operators and contributors. We are not reconstructing every old change retroactively; instead, maintainers should add notable user-facing changes as PRs land.

## How we maintain this file

- Add entries under `Unreleased` for user-visible features, fixes, security changes, migrations, deprecations, and breaking changes.
- Move entries into a dated release section when a release is cut. If the repository has no release tag for the change, use the merge date rather than inventing a version.
- Link issues or PRs when useful, but keep entries readable for operators who are not following every PR.
- Do not include routine refactors, test-only changes, or dependency churn unless they affect users.

## Unreleased

### Added

- Hive quadrant: every hive is scored on four axes — trust, efficiency, satisfaction and productivity — shown as a small shape in the hub's hive table, as a labelled chart with scores when you hover it, and as a fleet aggregate above the table that follows whatever filter is applied. Scores are percentiles against the hives in the current view rather than absolute grades, so the picture recalibrates as the fleet moves, and any axis can be sorted on to pull a worklist ("weakest efficiency" first). An axis with too little evidence renders as a collapsed spoke and reports why, rather than scoring zero — a new hive is never marked down for data it has not had time to produce. Satisfaction currently reports no signal by design: nothing in the platform measures it yet, and it is left visibly empty rather than filled with a proxy ([#4384](https://github.com/kubestellar/hive/pull/4384)). Seven already-collected spoke metrics now ride the heartbeat to feed it, adding no GitHub API calls.
- User location: hub users can carry a country, shown as a flag beside their avatar. It is set from a dropdown when a hive is requested, changed later by the signed-in user, or assigned by an admin from the Users table for accounts that predate the feature; where nothing is stated it is inferred from the browser's language header, and an unknown country renders nothing rather than a guess. A deliberate choice always outranks an admin's, which outranks an inference, so nobody's stated country is quietly overwritten. The admin Users table gains a country column and a fleet breakdown that reports how many users are still unknown ([#4371](https://github.com/kubestellar/hive/pull/4371), [#4374](https://github.com/kubestellar/hive/pull/4374), [#4373](https://github.com/kubestellar/hive/pull/4373), [#4386](https://github.com/kubestellar/hive/pull/4386)).
- `bin/hive-podman-setup.sh`: a one-command standalone install for the Podman path, closing the asymmetry with Docker's `bin/hive-setup.sh`. The Podman install was a correct but manual twenty-step sequence in the README, and two of those steps are the traps that cost the most to hit by hand: `dashboard.port` disagreeing with the unit's healthcheck port buys a silent 300-second hang with no container left to inspect, and a secrets directory at the intuitive `mkdir -m 700` presents as an SELinux denial it is not. The script reads the port out of the unit that will enforce it and refuses to continue if the config does not read back agreeing, and applies the right secrets command for the root mode (`podman unshare chown` rootless, `chgrp` rootful). It installs no packages — Podman's supported hosts include image-based systems where the package manager cannot — clones nothing, and generates no deployment description; the four Quadlet units are installed verbatim. It is idempotent, never overwriting an existing config without `--force` and never touching `secrets/` at all, and it ends by confirming the gateway answers rather than that `systemctl start` returned. A failing step says which step and leaves the host as it is ([#4470](https://github.com/kubestellar/hive/issues/4470)).

### Changed

- Rootless Podman with the egress gate enforcing (`--cap-add NET_ADMIN`) is promoted from *Experimental* to **Supported** in the [Podman support matrix](src/docs/podman-support-matrix.md). The matrix named three criteria as the whole promotion bar — the `SO_MARK` exemption isolated from the owner-UID exemption under rootless, a `slirp4netns` lane measured against `pasta`, and gate re-installation observed across a container restart — and all three were measured on a live rootless SELinux-enforcing host ([#4487](https://github.com/kubestellar/hive/issues/4487)). The grade carries a footnote: a rootless install needs `loginctl enable-linger` to survive a reboot ([#4489](https://github.com/kubestellar/hive/issues/4489)); this is an availability precondition, not an enforcement gap.

### Security

- The container image now ships exactly one setuid binary. The `su-exec` helper agents' UID switch runs through was hardened to `4750 root:hive-launch` so no agent UID could exec it — but that only ever covered the helper Hive builds. `node:26-slim` and the `passwd`/`util-linux` packages left eleven more behind (`chfn`, `chsh`, `gpasswd`, `mount`, `newgrp`, `passwd`, `su`, `umount` setuid-root; `chage`, `expiry`, `unix_chkpwd` setgid-shadow), every one world-executable and so reachable by exactly the agent UIDs the 4750 mode excludes. Nothing in Hive uses any of them. They could not be neutralised from the pod, either: `allowPrivilegeEscalation: false` sets `no_new_privs`, which would disable `su-exec` too and break agent launch, so a setuid-root exec from an agent UID landed in a bounding set still holding `SETUID`, `SETGID` and `DAC_OVERRIDE` — enough to read the MITM proxy's CA private key whatever mode the `0700` directory it was moved to in [#4341](https://github.com/kubestellar/hive/pull/4341) carries, and forge certificates for `api.github.com`. The build now strips every setuid/setgid bit but `su-exec`'s, after the last install layer, and **fails** if the resulting inventory is anything else — so a base-image bump or a new package cannot quietly reintroduce one. A new boot-level check builds the image both with and without the strip and requires the un-stripped build to show the eleven, then execs `su-exec` as `dev` to confirm the surviving bit still switches UID and as an agent UID to confirm it is still refused ([#3866](https://github.com/kubestellar/hive/issues/3866)).
- Token mint: the `/mint` HTTP endpoint gains a caller-identity seam, per-caller entitlements, and per-caller audit records ([#4436](https://github.com/kubestellar/hive/pull/4436), [#3915](https://github.com/kubestellar/hive/issues/3915)). Default behaviour is unchanged (shared-secret gate, no entitlement bound — a warning is now logged for this posture); once `Entitlements` are configured the mint is deny-by-default per verified identity, refusing any subject, audience or scope outside the caller's grant, and every mint and refusal is logged with the caller's identity.

### Fixed

- The SELinux release qualification (`src/deploy/qualify_podman_selinux.sh`, #4337) no longer reports FAIL — ledger row included — on a healthy enforcing host where uutils coreutils is first on `PATH`. It read labels with bare `stat -c '%C'`, and uutils `stat` has no `%C`: it prints "unsupported for this operating system" to stdout and exits 0, so that sentence was compared against `container_file_t` and two checks failed with the kernel behaving correctly throughout — on Bluefin/Universal Blue, exactly the Fedora-atomic host class this lane targets. Both sibling scripts had already documented and hardened against this reader; that implementation is now extracted to `src/deploy/selinux_label_reader.sh` and shared, the qualification resolves its reader by probing (`stat`, `/usr/bin/stat`, `getfattr`) and validating the answer is shaped like a context, and a host with no working reader exits `78` NOT QUALIFIABLE rather than emitting a verdict — "I could not measure this" and "this host failed" no longer produce the same output ([#4490](https://github.com/kubestellar/hive/issues/4490)).
- `bin/hive-podman-lifecycle-probe.sh exercise` no longer ends with the dashboard dead while reporting "no findings". The probe drives `hive.service` through a deliberate stop/start pair, and `hive-gateway.service` — the unit holding the only published port — has `Requires=hive.service`: the stop propagated to the gateway, the later start did not bring it back (Requires= propagates stop, not start), and every assertion the probe made was about `hive.service`, all true, so it exited 0 over a deployment it had just broken. A final restore step now returns the stack to its pre-probe state — restarting the stranded gateway and confirming `:3001` actually answers, not merely that the unit is `active` — and runs even when a step fails early or the probe is interrupted. A restoration that fails is itself a FINDING with a nonzero exit, so the probe can no longer certify a host it left worse than it found it. The routine operator paths (`hive-podman-update.sh pin`/`rollback`, plain `systemctl restart hive.service`) were never affected: `restart` is one systemd job and re-starts the requiring units in the same transaction ([#4491](https://github.com/kubestellar/hive/issues/4491)).
- The Podman probes and the SELinux release qualification now measure the image operators actually run. All six scripts — the rootless/rootful/SELinux-AVC/IPv6 egress probes, the arm64 startup probe, and `qualify_podman_selinux.sh` — hard-coded `ghcr.io/kubestellar/hive:v4-latest` while the deployment assets take `ghcr.io/kubestellar/hive:stable` from `src/deploy/standalone-images.sh`, the #4206 image source of truth. The two tags are the same digest today, so every probe happened to measure the right image — but on the day the release channels split (#3702), the qualification would bless `v4-latest` while the release shipped `stable`, and the support-matrix evidence would silently be measured against code operators are not running. Each script now sources the source of truth for its default, with `--image` (and `IMAGE` in the environment) unchanged as the deliberate override; `src/deploy/test_standalone_image_refs.sh` now fails any of them that re-hard-codes a Hive reference, and no longer accepts `v4-latest` as a canonical spelling ([#4486](https://github.com/kubestellar/hive/issues/4486)).
- `bin/hive-podman-update.sh` no longer reports "rolled back … and it is serving" over a dead dashboard. Rollback is the documented recovery from a failed update, and a failed update has already taken `hive-gateway.service` down with the failing unit (`Requires=hive.service`); `systemctl restart hive.service` only re-starts dependents that are *active* when the job runs, so nothing ever started the gateway again and the published port — the only thing an operator can reach — stayed dead while the script printed PASS and exited 0. Every path that restarts hive (`pin`, `rollback`, `unpin`, `autoupdate on`) now also starts the gateway (idempotent: a no-op when it is already up) and refuses to claim success until the gateway answers `/api/health` on its published port from the host, the same end-to-end assertion `bin/hive-podman-setup.sh` already ends on. A *failed* update now also says plainly that the gateway has stopped with hive, so an operator watching the dashboard port understands why it is dark ([#4493](https://github.com/kubestellar/hive/issues/4493)).
- A standalone Hive's log is no longer dominated by six identical `permissions watcher` WARN lines every ten seconds about `/data/agents/reviewer`, a directory seeded for an agent the roster no longer contains. Two things were wrong. The image's seed data is copied into `/data` as root during entrypoint, and only roster agents were re-chowned to their own UIDs — so `/data/agents` itself and any seeded directory for a retired agent (`reviewer`) stayed root-owned, which the watcher, running as `dev` after the privilege drop, could detect on every tick but never repair (`chown` returns EPERM). The entrypoint now hands any still-root-owned agent-data entry to `dev:node` while it is still root — the one moment the chown succeeds — which fixes existing volumes on their next boot as well. And the watcher itself no longer turns any unfixable entry into an unbounded log stream: the first failure per path is logged at WARN and identical repeats at DEBUG, re-warning only when the failure changes or recurs after the path was healthy ([#4488](https://github.com/kubestellar/hive/issues/4488)).
- The Docker Compose quick start — the default path, and the first thing a new operator runs — now works as written. It was broken twice over on its own terms. It told you to write `.env` at the repository root, but `-f src/docker-compose.yaml` makes `src/` the project directory, so that is the only `.env` Compose reads: the PAT you had just pasted went into a file nothing read, and because both paths are gitignored neither git nor Compose said so — the hive came up and then 401'd on every GitHub call, which reads like a bad token rather than an unread file. And it never set `HIVE_DASHBOARD_TOKEN`, which the dashboard's auth proxy refuses to start without, so `http://localhost:3001` — the address the quick start advertises — served 503 from an upstream that never bound. The recipe now writes `src/.env`, mints the token the way the Podman quick start in the same README already did, and ends by confirming the dashboard answers rather than assuming the port does. Fixed in all three places the recipe is copied, and `src/deploy/test_compose_quickstart_contract.sh` now holds it there: it reads the required-variable set out of `src/deploy/quadlet/hive.env.example` rather than restating it, and discovers the documents carrying a recipe rather than listing them. Compose's two permanent "variable is not set" warnings for the optional ntfy settings are gone as well — they trained operators to skim past the one warning that would have revealed the unread `.env` ([#4477](https://github.com/kubestellar/hive/issues/4477)).
- A Podman or Compose deployment whose dashboard is dead no longer reports itself healthy. The Hive container runs two listeners — the Go API on 3002 and the Node auth proxy on 3001 — and only 3001 is reachable through the gateway, because `nginx.conf` deliberately dials the proxy so nothing can skip authentication. The healthcheck read 3002 alone, so the half nobody reaches certified the whole container: with `HIVE_DASHBOARD_TOKEN` missing from `hive.env` the proxy fails closed and never binds 3001, and `hive.service` sat `active` with its container `healthy` for the entire two minutes the deployment was unusable. The only red arrived 120 seconds later on `hive-gateway.service`, as an nginx connection-refused that named neither the port nor the variable — pointing an operator at the gateway when the fault was in Hive's own configuration. Both runtimes now probe both listeners, so `systemctl start` returning means the dashboard answers and the failure surfaces on the unit that owns it; `bin/hive-podman-lifecycle-probe.sh check` reports a unit installed before this change rather than trusting it ([#4476](https://github.com/kubestellar/hive/issues/4476)).
- The advisory digest no longer carries a permanent "repository worktree not provisioned" error the hive raised against itself. Two things were wrong at once. `include_repos: true` names a prompt-text option — it appends the authorized-repo list to each kick — but agents read it as a promise that those repos were on disk, so a guide agent that found its workspace directory empty filed a red infrastructure blocker saying no worktree had been provisioned for it. Nothing provisions a per-agent worktree, so the claim could never come true. And the healer that exists to retire exactly this family of self-reported access findings could not see either that finding or the quality agent's companion to it: both were worded in ways ("worktree **not provisioned**", "lacks read access **to** repository") that its patterns did not match, so no number of cycles could age them out. The kick's repo list now states that it is an authorization scope rather than a checkout, that an absent checkout is normal, and how to clone one; the healer recognises both wordings and retires them once the read path is verified, as it already did for the rest of the family ([#4464](https://github.com/kubestellar/hive/issues/4464)).
- An agent whose inference gateway refused its model no longer looks like an agent that needs to log in. Claude Code prefixes every API error with "Please run /login", so a `403 team not allowed to access model` was read as a login prompt: the agent was badged 🔑 and — because a valid token was on disk — auto-restarted straight back into the same refusal, which presented as crash-looping while the real cause (a model id that does not match what the gateway entitles, often a `.` where it wants a `-`) sat unread in the same line. A `403` is authorization and is no longer treated as a login signal; a `401` still is ([#4400](https://github.com/kubestellar/hive/issues/4400)).
- Governor threshold scaling now reaches hives that have applied an ACMM level. Applying a pack seeds explicit `surge`/`busy`/`quiet` thresholds, and because "an explicit threshold is never scaled" could not tell a pack-seeded default from a number an operator typed, scaling by repo count silently did nothing on what is the normal path — including, plausibly, the large multi-repo fleets it was built for. Config now records where the thresholds came from: pack-seeded values are treated as per-repo *bases* and scale, while anything you set yourself is still used verbatim. Existing hives are unchanged on upgrade; re-apply the level to turn scaling on, and editing any threshold hands the whole set back to you ([#4037](https://github.com/kubestellar/hive/issues/4037)).
- The agent Terminal now says when it is showing scrollback rather than live output. Scrolling with the mouse wheel puts the pane into tmux copy-mode, which stops it following new output — and because that state lives on the server, closing and reopening the terminal returned to the same frozen view, so an idle-looking agent was indistinguishable from a stuck one. The status bar now reads `[live]` or `[SCROLLBACK - not following live output - press q to resume]`, and the clock beside it is labelled `now` so it is not mistaken for a timestamp of the content on screen ([#4399](https://github.com/kubestellar/hive/issues/4399)).
- The agent Terminal's remaining unlabelled furniture is gone, finishing [#4399](https://github.com/kubestellar/hive/issues/4399). The black-on-yellow box tmux draws in a scrolled-back pane (`12:41 [812/4837]` — the write time of the *top visible line* plus a scroll counter, a reference point nothing on screen explains) is now hidden; the scroll position appears labelled in the status bar instead (`[SCROLLBACK 812/4837 lines back - not following live output - press q to resume]`). That status message itself was shipping truncated to 40 columns by tmux's default `status-right-length`, cutting off the "press q to resume" instruction — now raised. And the agent-card fields formerly labelled "last run" / "next run" are now "last kick" / "next kick" with tooltips saying a kicked work pass often runs for hours past its start — so an agent visibly working between kicks reads as the continuation it is, not an off-schedule run.
- The documented Docker → Podman migration now completes on an SELinux-enforcing host. Step 1 has Docker's rootful daemon write the export archive, so the file is root-owned and keeps the directory's `user_tmp_t` label; the `:z` on the extract in step 3 is supposed to relabel it to `container_file_t`, but relabelling needs ownership or `CAP_FOWNER` and a rootless operator has neither over a root-owned file. Podman skipped it silently and the extract died on `Permission denied` — a message that invites `chmod 777` or `setenforce 0`, neither of which is the fix and the second of which undoes what the rest of the Podman path depends on. The procedure gains the one `sudo chown` that makes the identical command work, plus why the obvious alternative (exporting as the operator instead of as root) trades the problem for a silently incomplete archive missing the `0600` GitHub App key. Two things around it are now stated rather than implied: the step 4 `hive-id` check before the step 5 `down -v` is a safety property, because a `hive-data` the denied extract left empty still starts healthy on a brand-new identity and looks exactly like a successful migration; and the same ownership trap applies to restoring any archive written by root, which the Restore section and [troubleshooting.md](src/docs/troubleshooting.md) now say ([#4497](https://github.com/kubestellar/hive/issues/4497)).
- `DASHBOARD_AUTH_TOKEN` was documented as holding a Kubernetes secret *name*; it holds the token *value* itself. An operator following the old wording would have set their dashboard token to the literal name of the Secret ([#4427](https://github.com/kubestellar/hive/pull/4427)).
- "Model removed from …" toasts no longer fire for models that are still there. The dashboard announces a removal whenever a fresh model list is shorter than the last one, so any incomplete answer from a gateway read as a mass deletion — including of the model the hive's own agents were running on. A failed probe was already excused ([#4426](https://github.com/kubestellar/hive/pull/4426)); two ways of being *partly* wrong were not, and both now count as "we do not know" rather than "they are gone": a sweep in which some of a backend's endpoints answered and others timed out or returned 403, and a `HIVE_*_MODELS` env list substituted only because a configured endpoint failed to answer. An empty list is likewise never diffed. What the dashboard did learn is still shown in the model dropdowns — a short list beats an empty one — it just no longer passes for a census. The same partial answer also reached model auto-heal, which does not merely toast: it rewrites the agent's configured model and relaunches its session, so an endpoint that briefly timed out could move an agent off a model only that endpoint serves. Auto-heal now sits out any sample it cannot trust. Toasts also now name the model's full id, provider prefix and all, so an alarming `vertex/claude-sonnet-4-6` is no longer displayed as bare `claude-sonnet-4-6`, spelled exactly like the id an agent is configured with and findable nowhere in the gateway's own list ([#4438](https://github.com/kubestellar/hive/issues/4438)).

## 2026-08-10

### Added

- Contributor onboarding, governance, templates, and local development documentation for the `v2` Go codebase.
- Timezone-aware time-of-day governor cadences so hives can vary agent activity by local operating windows.
- Merger contributor tier and configurable automerge queue/label behavior for safer merge delegation.
