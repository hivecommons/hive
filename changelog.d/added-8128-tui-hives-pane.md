- The terminal dashboard grew a **Hives pane** ([#8128](https://github.com/hivecommons/hive/issues/8128), phase 4 of [#8097](https://github.com/hivecommons/hive/issues/8097)). `hivectl tui`, then `H`, lists the hives this machine lends a CLI to — the named profiles from [#8115](https://github.com/hivecommons/hive/issues/8115), active one marked, with the same reachability probe `hivectl hives list --check` runs. `enter` switches the active hive, `a` adds one (name and hub, then the registration POST), `d` removes one after you type its name, and `r` renames. It is the same list in the same order as the CLI's because it calls the same `pkg/hivectl` functions: switching from the pane leaves `profiles.yml` and the generated `contributor.env` in exactly the state `hivectl hives use` would. As with the CLI, a relay that is already running keeps its current hub until it restarts, and the pane says so.
- The five profile mutations (`use`, `add`, `rename`, `remove`, and the "profiles.yml before its projection" commit) and the two contributor-hub calls (register, reachability probe) moved out of `hivectl`'s cobra command bodies into `pkg/hivectl`, so the CLI and the TUI share one implementation of the rules that are easy to get subtly wrong in a copy — re-electing an active profile on removal, carrying the active marker through a rename, and never leaving a `contributor.env` describing hives no file records.
