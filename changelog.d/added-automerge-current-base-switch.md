- Settings → Features → Auto-merge gains a "Merge only on current base" switch (`auto_merge.require_current_base_default`, **off** by default) and each row on the Repos tab a per-repo inherit / on / off override (`auto_merge.require_current_base` / `auto_merge.skip_current_base`); the repo card shows a `current-base` chip when the gate is on. A gated repo only merges a head that contains the current base tip — a green head whose base has moved is updated with GitHub update-branch and merges once CI is green on the new head, which would have stopped the stale-green merge that broke `v5` for every open PR for 20 minutes. Explicitly listed repos are strict; repos gated only by the default merge a head the App cannot update (fork without maintainer edits, branch protection) as tested, with one WARN per PR. The fleet default stays off while the gate soaks on hive's own hive ([#15335](https://github.com/hivecommons/hive/issues/15335)).
