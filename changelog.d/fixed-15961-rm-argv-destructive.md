- The built-in destructive-command check now reads `rm` arguments the way `rm` does, so `rm -rf --no-preserve-root /` (the spelling GNU rm actually executes against the root), `rm -rf -- /`, `rm --recursive --force /`, `rm -r --force ~` and `rm -rfv /` are flagged like `rm -rf /` instead of passing clean to the host text scanner ([#15961](https://github.com/hivecommons/hive/issues/15961)). Option order, long options and `--` no longer matter; ordinary subpaths (`rm -rf -- /tmp/x`) and non-recursive `rm` still pass.
