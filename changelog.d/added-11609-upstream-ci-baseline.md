- A fork PR that fails because its upstream project is broken is no longer re-queued as "fix before new" on every kick ([#11609](https://github.com/hivecommons/hive/issues/11609)). `hive-baseline-check.sh` now also reads the failing check on the upstream repository's default branch (the GitHub fork parent, or `--upstream OWNER/REPO`). When the check is red there and this repository's own default branch has no fresh green for it, the helper returns `DEFER_EXTERNAL` with an `external_marker` pinned to the PR head, the check and its failing check run. The agent ends its one triage comment with that marker. While every failing check run at the current head carries one, the governor sets `deferred_external` on the PR's `ci-failing.json` row, and FIX-BEFORE-NEW and CI_FAILING name the PR only as deferred. A push, a newly failing check, or a re-run of the check (a new run id, e.g. after it went green and failed again at the same head) brings it back. Batched GraphQL enrichment now carries each check run's real id (`databaseId`) instead of a positional stand-in, which the marker needs and which the CI failure-excerpt annotation lookup also uses.
