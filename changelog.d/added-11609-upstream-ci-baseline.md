- A fork PR that fails because its upstream project is broken is no longer re-queued as "fix before new" on every kick ([#11609](https://github.com/hivecommons/hive/issues/11609)). `hive-baseline-check.sh` now also reads the failing check on the upstream repository's default branch (the GitHub fork parent, or `--upstream OWNER/REPO`). When the check is red there and this repository's own default branch has no fresh green for it, the helper returns `DEFER_EXTERNAL` with an `external_marker` pinned to the PR head and check. The agent ends its one triage comment with that marker. While every failing check at the current head carries one, the governor sets `deferred_external` on the PR's `ci-failing.json` row, and FIX-BEFORE-NEW and CI_FAILING name the PR only as deferred. A push or a newly failing check brings it back.
