- A maintainer's direction on an adopted PR parked at `stage/085-needs-decision` (a dashboard direction, a delegated decision, a hand-placed `stage/072-returned-to-contributor` or `stage/071-needs-author` label, or a `/hive decision <instruction>` comment where the comment path records one, which on a PR the hive did not open is only a bare approval) is no longer undone on the next stage pass. The adoption-stall escalation used to re-derive the same stall from the same head about two minutes later and park the PR back in the Decide inbox, where it read as unanswered until the head moved: a fork the hive would not re-home went straight back to `adoption-stalled:fork-rehome-refused` whatever the person decided ([projectbluefin/utah-packages#1308](https://github.com/projectbluefin/utah-packages/pull/1308)), and an in-place adoption read the decision's own changes request as `adoption-stalled:human-changes-requested`, measured from when the head was pushed rather than from the decision ([projectbluefin/utah-packages#1309](https://github.com/projectbluefin/utah-packages/pull/1309)). A direction on the current head, given after the hive took the PR over, now releases that escalation and restarts the stall clock at the decision. A fork head the hive cannot push that the person sent back to its author stays at its author's stage (`stage/072-returned-to-contributor`, or `stage/071-needs-author` for a person's PR) on every pass, whatever the lane reads, while the refusal still stops the hive pushing or re-homing it; it goes back to a person only after the 072 dwell from the decision (a 072 dwell of zero never hands it back, as for a fork the hive declined to adopt). An in-place adoption returns to `stage/074-adopted-by-hive` for the hive's fixer, and neither escalates nor re-homes to a superseding PR until the 074 dwell from the decision has passed. When that dwell runs out on the same head and the same stall parks the PR again, the PR gets one comment saying whose decision lapsed (folded into the stall note when the stall reason is new to the head), when it was made and how long it had, instead of returning silently under the old note. A bare approval, a direction given before the adoption (for example before a maintainer's Adopt that the fork then refused), a GitHub review, a new head, a PR with no decision, and the workflow-path, child-closed, copy-failed and fixer-reverts holds all behave as before.
