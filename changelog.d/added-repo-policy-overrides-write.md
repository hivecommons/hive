- **An owner can set, change and clear one repository's Sentinel sensitive-path list and workflow fence scope without editing hive.yaml** (refs #17547). Settings → Features → Auto Merge → **Workflow fence scope per repository** and Settings → Security → Suspicious Activity → **Sensitive files per repository** list every watched repository with its value; choosing the hive-wide value clears the override. The same writes go through `PUT /api/config/auto-merge` (`contributor_lane.workflow_fence_scope_repos`) and `PUT /api/config/governor/security` (`sentinel.repoSensitivePaths`), owner only, as `{owner/repo: value}` maps where `null` clears, and through the admin MCP `auto_merge.update` and `sentinel.settings` operations, whose previews name what loosens in each repository ("workflow edits outside human-merge paths in org/a merge without an owner Approve", "Sentinel stops flagging Justfile in org/a"), remind that a repository with no `human_merge_paths` entry keeps the full fence, and refuse a stale confirm. A write changes only the repositories it names, never the hive-wide value or a policy's other fields, is validated as hive.yaml is (plus malformed globs), and is recorded in the audit log per repository. Requests without the new keys behave as before. An explicit empty per-repository Sentinel list (`[]`, flag no path) now also survives a save; before, the next save wrote it out as unset, so it came back as the hive-wide list. See [hive-merge.md](src/docs/hive-merge.md#contributor-lane-auto-merge).
