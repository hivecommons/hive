- Run checkpoint approve/reject (`POST /api/runs/{key}/checkpoint`, and the chat and mobile surfaces that use it) now acts on the checkpoint's stage instead of guessing from the epic's design metadata ([#9181](https://github.com/hivecommons/hive/issues/9181)). Previously, a design-mode run that skipped the Spec checkpoint (`runs.checkpoints.spec: false`) reached the plan checkpoint with its design still pending. Approving it returned `{"ok":true}` but left the plan in `draft` and the lease at `plan`, and rejecting it re-queued the design without touching the plan. Now a disabled Spec checkpoint auto-approves the design, and an approval that cannot move the held lease answers `409`. Spec approval moves the lease before it writes the design approval, so a GitHub error on the approved label no longer returns `502` and leaves the run stuck at `spec` where no retry could move it. The failed signal is logged, audited, and recorded on the run's timeline instead.
