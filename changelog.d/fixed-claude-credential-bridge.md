- A Claude token refresh no longer cuts an agent off from the fleet's shared login, and a dashboard Claude sign-in now actually recovers the agents it was meant to (refs [#17031](https://github.com/hivecommons/hive/issues/17031), [#17039](https://github.com/hivecommons/hive/pull/17039)). Each per-UID claude agent reaches the one shared login through a symlink, `~/.claude/.credentials.json` -> `/data/home/.claude/.credentials.json`. Claude Code refreshes its token about every 8 hours by writing a temp file and renaming it over that path, which replaces the symlink with a private `0600` copy. From then on the agent ran on its own token: a dashboard sign-in rewrote the shared file and never reached it, and once the private token was revoked the agent answered every kick with `Login expired · Please run /login` or `OAuth token revoked`, was re-paused by the login detector or restart-looped, and nothing told the owner that signing in again could not help. On one hive seven agents sat in that state through two sign-ins until the links were fixed by hand. Hive now checks every agent's link at launch, on every credential-watchdog cycle and right after a dashboard sign-in. When a regular file has replaced it, hive moves the file aside as `.credentials.json.stale-<UTC time>` (never deleting it), keeps whichever credential is newer and still usable in the shared file (so one agent's fresh refresh becomes the fleet's login instead of stranding the rest), restores the symlink, and records a `claude_credential_rebridged` Audit Log entry. A successful dashboard Claude sign-in also resumes the claude agents the login detector paused, and only those: operator, fleet-breaker, hook and other pauses stay. On the dashboard, an affected agent's card now says **credential bridge broken (private stale file)** instead of a generic "needs login", and the agent card's Claude button reads **Sign in Claude for all agents**, with a tooltip saying it is the fleet-wide sign-in rather than a per-agent login.
