- **Workflow models: GitHub Actions post-merge run observer feeds `pipeline.status`** ([#18645](https://github.com/hivecommons/hive/issues/18645), part of [#18356](https://github.com/hivecommons/hive/issues/18356)). Default-branch push runs (Main CI, deciding by the exact merge SHA when the range can't), release runs and deploy runs (per environment) of the workflows an ingested model binds are now attributed to merged PRs through the range-attribution core (`workflowmodel.AttributeRuns`), so the `pipeline.status` fact reports `green`, `red` or `running` instead of always `unknown`. Pull-request and merge-queue runs never count, a deploy run that does not report which environment it targeted credits none of them, and a run whose revision or range can't be determined leaves the status `unknown` with the reason recorded.
