- Removed the legacy standalone Node.js Discord bot (`discord/`, `systemd/hive-discord.service`) on `v6`: it had been crash-looping on a `SyntaxError` since May and predated the v6 command spine's allowlist/ioscan/outbound-scrub guards. The Go bot (`src/pkg/discord`, `notifications.discord.{bot_token,channel_id,allowed_users}`) is the only Discord bot going forward — hosts still running the old unit should run `systemctl disable --now hive-discord.service` ([#9140](https://github.com/hivecommons/hive/issues/9140)).
- Documented that the Discord bot's application requires the **MESSAGE_CONTENT** privileged gateway intent (and View Channel/Read Message History/Send Messages permissions), since without it the REST poller silently receives empty message content and commands are ignored with no error logged ([#9141](https://github.com/hivecommons/hive/issues/9141)).
- The Discord poll loop now backs off exponentially (capped, jittered) on repeated fetch errors instead of retrying at a fixed 5s cadence forever, logs 401/403 once instead of on every tick, and honors a 429's `retry_after` on both polling and outbound sends ([#9142](https://github.com/hivecommons/hive/issues/9142)).
