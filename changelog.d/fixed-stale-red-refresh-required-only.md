- The stale-red base refresh no longer merges the base into a PR when every required check passed and only non-required checks are red. Such a PR is not blocked from merging, and a base merge cannot clear an advisory check that judges the PR's own diff, so each update only restarted CI and review: [Danathar/tududi#658](https://github.com/Danathar/tududi/pull/658) had main merged in twice while every required check was green and only `Mutation check on changed lines (advisory)` was red. The pass now skips such a head (skip reason `only-non-required-checks-red`). A required check counts as passed only when it completed with success, neutral or skipped, so a head with a required check that timed out, was cancelled or is still pending is handled as before, as is a head whose required set is unknown, empty or not fully reported. Every failing check, required or not, must still be green on the base tip before the refresh acts, and a dependency bot's branch keeps its rebase request unchanged.
