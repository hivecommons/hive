- The agent config dialog no longer renders a fabricated all-zero config when the session expires ([#7405](https://github.com/hivecommons/hive/issues/7405)). On a hosted spoke an expired hub session made every `fetch()` reject — nginx turned the auth-check's 401 into a cross-origin redirect to the login page that the browser would not follow (Safari: `TypeError: Load failed`), so no `res.status === 401` branch ever fired — and `loadConfigData` answered with an empty `{}`: every field showed as `0`/blank/off with Save armed to persist exactly those zeros, while three separate toasts (`Failed to load config`, `Could not refresh terminal access`, `Could not prepare terminal access`) each said `Load failed` and none said what to do. Now: (1) a failed load leaves the config unloaded — the dialog shows *Could not load configuration — not showing values* with Save disabled (and `saveConfig` refuses) instead of rendering a tab from the placeholder; (2) a rejected fetch triggers one session probe independent of any status code, and an expired session yields a single *Your session expired — sign in again* toast with a **Sign in** action (hosted: re-enter the login redirect; self-hosted: the device flow) instead of `Load failed`; (3) the three sites share that one handler, so one expired session produces one message; (4) hosted spokes gain a `hive-api-xhr` Ingress for `/api` that keeps the same per-hive auth gate but no `auth-signin`, so an expired session answers a real `401` — routed through `hive-error-pages`, which now serves `unauthorized.json` (`{"ok":false,"error":"unauthorized",…}`) to API callers — rather than a redirect. Operators of hosted clusters re-apply `deploy/k8s/error-pages.yaml` to pick up the 401 document.
