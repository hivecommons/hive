- **A review-swarm approval no longer makes a contributor's PR merge-eligible** ([#9624](https://github.com/hivecommons/hive/issues/9624)). With `review.require_approval` on, a green, swarm-approved PR opened by a person used to land in `merge-eligible.json`, where an agent could merge it through `hive-merge`. The merge-eligibility classifier now treats any PR not opened by the hive's App bot, `project.ai_author` or a bot in `auto_merge.trusted_bot_authors` as a contributor PR: by default it is never merge-eligible and its dashboard verdict reads "contributor PR: needs a maintainer's review". A new opt-in, `auto_merge.contributor_prs: true`, lets such a PR become eligible only once a person with write access has approved its current head on the forge; the swarm verdict never counts toward that. The merge relay applies the same rule itself, refusing with that reason in the `.result.json` and a `merge_request_refused` audit entry. Hive-authored and trusted-bot PRs, and red-CI routing for every PR, are unchanged. Upgrade note: the hive attribution trailer in a PR body and other bots (`renovate[bot]` and the like, unless listed in `trusted_bot_authors`) no longer count as the hive for merging, and a hive whose agents open PRs under a personal token must set `project.ai_author` for those PRs to stay mergeable.
