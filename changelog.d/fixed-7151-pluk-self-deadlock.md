- The inception watcher no longer wedges its Pluk subscriber goroutine the first time an agent goes idle during the structure phase with buffered fact lines ([#7151](https://github.com/hivecommons/hive/issues/7151)). `handlePlukEvent` holds `plukMu` for its entire body and called `tryExtractFactsFromPluk`, which acquired the very same mutex — and `sync.Mutex` is not reentrant, so the goroutine blocked on itself and never came back. Everything downstream of that subscriber went dark for the remaining life of the process: idle detection, rate-limit tracking and bd-create interception all stopped, silently and permanently, with no error anywhere to say so. The trigger is ordinary — an agent that writes about facts instead of creating beads and then pauses — so an inception could simply stop progressing partway through. The extraction is now split into a lock-acquiring wrapper for callers that hold nothing and a core that documents `plukMu` as a precondition, with `handlePlukEvent` calling the core it already has the lock for. The branch had been impossible to test for the same reason it was broken — any test driving it hung — so it is now pinned by one that joins the call with a timeout and fails in seconds with a named diagnosis rather than hanging the package until the global test timeout dumps every goroutine in the process.
