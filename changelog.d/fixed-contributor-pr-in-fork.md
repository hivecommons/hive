- A contributor agent working from a fork could open its fix PR inside its own fork (head and base both in the fork), because the task prompt never told `gh pr create` which repository to target and a clone reused across tasks can default to the fork. The relay rightly never credited that PR, but dropped it without a word, so the issue stayed actionable with the fix invisible (projectbluefin/chairlift#798 waited nine hours behind kylerankin/chairlift#3). The prompt now names `--repo <upstream>` (and `--head <login>:<branch>` from a fork) and asks the agent to confirm the PR URL is under the upstream repo; the relay tells the agent once to reopen a PR it finds in the agent's fork, when the task would finalize or before the stall backstop fails a pane frozen after it, and logs it as a warning.
