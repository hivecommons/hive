- A `kick_template` that resolves to no file is no longer silent ([#7390](https://github.com/hivecommons/hive/issues/7390)). The scheduler's success path logged `using config kick_template` but the miss path logged nothing and fell through to the pack/convention template; the dashboard's Prompt Template tab rendered an empty editor with a repo link that 404'd, and text typed into that empty box and saved became a live override for a control that had looked broken. Now the hive warns once at boot (`config: kick_template does not resolve`) and on every affected kick (`config kick_template not found; falling back`), each naming the agent, the template, the fallback the kick actually uses, and every path tried; `GET /api/config/agent/{name}/prompt` reports the resolution (`template: {kickTemplate, resolved, source, fallback, pathsTried, embeddedDefaultExists}`) and omits the repo link for a file the repo does not ship; the editor shows `⚠ template not found: <name> (falling back to …)` with the paths tried and a note that saving creates a live override; and `PUT /api/config/agent/{name}/general` refuses to set a **new** `kickTemplate` that does not resolve (an unchanged dangling value no longer blocks unrelated edits). A `kick_template` carrying a path separator or `..` is rejected at config load and by the per-agent overlay guard.
