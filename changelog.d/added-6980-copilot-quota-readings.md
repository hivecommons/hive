- The rotation manager gains a Copilot contributor-quota adapter ([#6980](https://github.com/hivecommons/hive/issues/6980)): `CopilotProber` reads the documented enhanced-billing endpoint `GET /users/{username}/settings/billing/premium_request/usage` through `gh api` and normalizes the calendar-month premium-request window (duration, reset on the first of the next month UTC). Copilot was the one first-class backend with no prober, so once the guard flips from `unprovisioned` to enforcing ([#6967](https://github.com/hivecommons/hive/issues/6967)), Copilot contributors would have been left at "guard unavailable" — on the backend where a misread is a bill, not a wait. The endpoint reports **consumption only**, so a remaining percentage exists only when the operator states the plan's included allowance in the new `rotation.providers.<name>.monthly_allowance` config field; without it the probe reports an explicit unknown carrying the consumed count, never a guessed percentage. `netQuantity > 0` (billed overage) sets the paid-usage signal from a read-only source — `TestNoCopilotBudgetMutation` pins that no code path touches any budget-mutating endpoint. A logged-out `gh`, a token missing the Plan read scope, or an unrecognized response schema each report explicitly and hold as unknown; the emitted `monthly` kind is deliberately governed by the guard's base reserve via the unrecognized-kind path (decision recorded in `src/docs/contributor-relay.md`).
