- Kicks are no longer silently lost when a Codex agent's TUI is sitting in a menu or modal ([#13765](https://github.com/hivecommons/hive/issues/13765)). Codex menus such as `/hooks` keep a `›` selection caret that the readiness check mistook for the input prompt, so the manager typed kick after kick into the menu, each turn "ended" with no output, and the review swarm spent every retry on a pane that never received them. Before typing a kick the manager now recognises known Codex menu footers (`esc back`, `esc close`, `enter details`), sends `Escape` (up to three times, re-checking after each) and only types once the prompt is back. If the menu does not close, the kick is marked undeliverable with the reason `prompt-not-ready: menu footer "…"` — shown in the logs and the dashboard busy reason — and is not recorded as delivered. Backends without known menu footers behave exactly as before.
