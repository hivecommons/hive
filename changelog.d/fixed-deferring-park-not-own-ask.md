- A parked issue that only defers to another parked issue's decision no longer counts as its own owner ask. Danathar/tududi#512 (the upstream v2.0.0-rc.1 tag) was parked with "Answer on #511; the same choice applies here" and sat in the your-turn inbox beside #511 as a second decision. Lane policies now tell a deferring park to add `--blocked-by <N>`, and `hive-open-issue comment` accepts that flag and links the existing issue "blocked by #N". The enumeration carries the open-blocker count on parked rows, and the dashboard reads a decision park with an open blocker as waiting on that issue, not as your turn. The relay now also does this on its own: a `--needs-decision` park with no `--blocked-by` whose text defers to an earlier open decision park ("answer on #N", "the same choice ... #N", "parking this with #N", "#N settles it") or cites the same Actions run as one is linked "blocked by" that issue, with a note saying where to answer, so one decision asked by several lanes (Danathar/tududi#511, #512, #528) reaches the owner once. Only lower-numbered issues are targets, so two asks never wait on each other.
