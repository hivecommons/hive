- New `repeat_failure` config block, **off by default**, as the foundation of the monitor-only check that notices an agent repeating the same failing shell command ([#14553](https://github.com/hivecommons/hive/issues/14553), part of [#14550](https://github.com/hivecommons/hive/issues/14550)). It carries `enabled` (false), `threshold` (5), `window_s` (600), `no_data_after_s` (900) and `exclude` (default `gh pr checks`, `gh run watch`). Hive also gains a backend-neutral command record (agent, backend, time, command, exit status or failed/succeeded, producing route) and a per-agent raw record file, readable only by the agent's user and Hive, that is collected by renaming it first, scrubbed with the log scrubber and then deleted, so only scrubbed command text is ever kept. With the switch off nothing is collected and nothing is added; the backend routes, detection and dashboard note land in the follow-up issues.
