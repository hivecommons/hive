- `stage/030-pr-in-progress` now requires PR evidence. A hive-agent issue claim used to derive 030 on its own (claimswire `claimFactFor`, the `claim` issue request, and the live `hive:claim` marker on enumeration), so an issue the scanner claimed while triaging wore "PR in progress" with no PR or branch to show (hivecommons/hive#13069). Claims — agent, human, contributor, external — now derive `stage/020-claimed`; 030 is written only when the claim carries `PRStarted` (a `hive-open-pr --issues` request or a `<!-- hive:start branch=… -->` / `pr=…` marker), recorded on the ledger and the claim marker as `pr_started=true` so the sweep re-derives the same stage. Legacy `IssueStageFor` and the stage-engine adapter changed together (shadow mismatch gate stays 0); goldens regenerated with `pr_started` variants and three #13069 regression cases.
- The expected-transition table and pipeline diagram now draw `020-claimed → 010-actionable` and `030-pr-in-progress → 010-actionable` (claim released or expired) plus `020 → 040`, so claim expiry is no longer a `stage_transition_anomaly`.
