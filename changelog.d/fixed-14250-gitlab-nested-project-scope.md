- Fixed GitLab proxy repo scoping so nested group project paths (`group/sub/repo`) are no longer truncated to `group/sub`, both on `/api/v4/projects/...` and on git smart-HTTP pushes (`/group/sub/repo.git/git-receive-pack`, which previously extracted no repo and skipped the per-repo gates). The per-repo write gates (pause, agent scope, auto-merge, per-repo ACMM mode, repo filter) and the refusal audit entry now read a canonicalized form of the client's escaped path — every segment percent-decoded, with only `%2F` kept as the GitLab project separator — so `%2F`-encoded projects resolve exactly and neither escaped slug letters (`o%72g/repo`) nor escaped structural segments (`/r%65pos/`, `repo%2Egit`, `pro%6Aects`, `merg%65`) can slip past a pause, scope, allowlist or auto-merge entry. Git smart-HTTP slug extraction is also anchored to `info/refs`, `git-upload-pack` and `git-receive-pack`, so a `.git/` elsewhere in an API path no longer yields a bogus slug (#14250)
