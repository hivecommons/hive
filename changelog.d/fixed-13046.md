- Audit entries written by the outgoing pod during a hosted-spoke rolling update are no longer lost on NFS-backed `/data` ([#13046](https://github.com/hivecommons/hive/issues/13046)). With `maxSurge: 1` both pods appended to the shared `/data/audit.jsonl`, and NFSv3's client-side `O_APPEND` let the new pod's writes overwrite the old pod's — a successful-but-clobbered write that never surfaced as an error. Only the holder of a small `/data/audit-writer.lease` now appends to `audit.jsonl`; the other pod writes to its own `/data/audit-spill-<pod>-<start>.jsonl`, the outgoing pod releases the lease on shutdown, and the new holder merges spill files back into `audit.jsonl`, which stays the canonical file. The lease is stale after 90s, above the NFS client's default 60s attribute cache ([#13072](https://github.com/hivecommons/hive/issues/13072)); see `docs/audit-log.md` for the mount-option assumption. The first rollout onto this release still has an unleased old pod, so the fix takes effect from the following rollout.
