- **The PR Throughput card no longer counts each hive merge twice.** The hive's merge paths audit a merge as `owner/repo` (`path=sweep`, `queue`, `relay` or `forge`), and the PR poller audits the same merge again as the repo is configured, bare in a single-org hive, with `path=hive`. The two entries had different PR keys, so both counted. On projectbluefin's 12-hour window the card showed 51 merged ("20 hive identity · 5 human · 6 other automation · 20 auto-merge sweep") where GitHub has 31, and a 78% hive share where the real share is 65%. The card now qualifies bare repos with the hive's org before counting, so both entries share one key. When both are present it counts the merge once, under the merge path that made it rather than the poller's `hive`, so `merged_by_path` sums to `merged`, and the hive-vs-human share, the hourly bars and the repo filter use the same de-duplicated count. Existing audit entries are read this way too, so past windows correct themselves. The poller now records `owner/repo` as well. The all-time counters stop double-counting new merges, but keep the double counts they already persisted.
- The PR Throughput card's "Top repos" list counted every in-window PR action (PRs opened, reviews, comments, claims, issues created and closed) while sitting beside "Merged by agent". It now counts merges only, de-duplicated like the rest of the card, and is labelled **Merged by repo**.
