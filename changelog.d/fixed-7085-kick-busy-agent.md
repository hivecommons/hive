- Kicks no longer interrupt a busy agent ([#7085](https://github.com/hivecommons/hive/issues/7085)). Modern TUI backends (Claude Code / Claude Fable) keep the `❯` input box rendered the whole time an agent is working, so the readiness gate — which treated any `❯` as "idle and ready" — passed on a mid-task agent and `deliverKickLocked` immediately sent `Ctrl+C` + `/clear`, destroying the in-flight turn and every background sub-agent that session had dispatched. Archived kick logs on the console spoke showed sessions repeatedly truncated with `reason: kick`, and over 24h the scanner landed 1 PR to peers' 3. The readiness path now consults a new `paneShowsAgentWorking` check — mirroring the existing `paneShowsConsentScreen` guard for the same class of `❯` false positive — that classifies a pane as not-ready when the **visible** pane shows an active-work indicator (`◉ Working`, `esc interrupt`), letting `inputPromptTimeout` still bound genuinely stuck agents. The visible-only check ensures a completed task's lingering marker never wedges an idle agent, and backends with no working indicator (`goose`, `codex`) are unaffected.
