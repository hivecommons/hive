- The contributor relay no longer reports a pull request that does not exist. When an agent's `HIVE_VERDICT` line cited a pull request from another repository by number (`PR #1739`), the relay built `https://github.com/<task repo>/pull/1739` from it, could not tell GitHub's "no such pull request" from a failed lookup, and sent the URL as the task's own. The hub then answered 404, booked the completion idle as `relay reported a pull request the hub could not verify: github lookup failed`, and what the agent had actually said (for example that its push was rejected) never reached the hub. The relay now reads `gh`'s error output: "no such pull request" refutes the candidate, so no `pr_url` is sent and the agent's own verdict and reason are reported; a `complete` that claimed a pull request gets the usual one follow-up asking for it. A lookup that could not be made (`gh` missing, offline, rate-limited, not signed in, timed out) is still reported unverified as before, and a `PR #N` that does exist in the task repo is still credited from the number alone. Relay-only change: update the relay to get it.
