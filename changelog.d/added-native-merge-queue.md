- Automerge sweeps can enqueue eligible PRs into GitHub's native merge queue with the validated head pinned, report queue position and state, and withdraw Hive-enqueued entries only when the PR loses merge eligibility (a hold, a withdrawn or stale approval, changes requested, a paused or disabled repo, or a draft or closed PR) while preserving entries queued by people. The hand-off is opt-in per repo through `auto_merge.native_merge_queue.enabled` and `.repos` (default off; hives without queues see no change). On a queue-enabled base a `blocked` or `behind` PR is enqueued rather than reported `not-mergeable`; the `require_current_base` gate and the `behind` update-branch stay in force unless `auto_merge.native_merge_queue.skip_current_base_gate` is set. The `isMergeQueueEnabled` probe is cached per base branch for `auto_merge.native_merge_queue.probe_ttl` (default 30m) and the entry reconciliation runs only on opted-in repos. A mixed-authorship PR whose queue uses `SQUASH` parks at `stage/085-needs-decision` with the `merge-method` explanation, and the refusal is remembered per head for 30 minutes.
