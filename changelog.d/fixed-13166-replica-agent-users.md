- A `replicas:` copy of an agent (`<agent>-2` .. `<agent>-N`) can now read its own GitHub token on per-UID deployments ([#13166](https://github.com/hivecommons/hive/issues/13166)). Replicas exist only in memory, so the entrypoint never gave them a `hive-<agent>-N` user, private token group or pre-created token cache. The manager ran each replica as a bare `uid:node` and its cache was written `dev:node 0600`, so every `gh` call in the replica was blocked with `token_cache_unavailable` and a restart did not help. The entrypoint now derives replica names from each agent's `replicas:` setting and provisions them at boot like declared agents. Raising `replicas` on a running hive still needs a restart before the new copies can read their tokens.
