- An issue no longer stays withheld for good when GitHub fails while the hub cleans up after an unverified already-done verdict. When a contributor's relay labels an issue `hive/already-done` (or the configured `contribute_already_done_label`) and the cited PR or commit cannot be verified, the hub takes the label off and posts a comment saying the claim is unverified. Each was a single attempt: if GitHub was failing at that moment (for example a pacing deadline), the label stayed on, and because the label keeps the issue out of contributor offers and agent kicks, nothing ever tried again until a person removed it by hand. The hub now remembers the unfinished removal or comment and retries it every five minutes for up to a day, kept on disk so a restart does not forget it. It stops early once the label is gone, when a person has added the label, or when a verified merged claim now covers the issue, and a label a person added is never removed. GitHub refusing the write outright (403, 404, 410 or 422) ends the retry at once with a warning for a maintainer. A pending comment is dropped unposted once the offer hold it announces has been lifted or cleared. The retry's own writes do not lift that hold, but a comment or other change by anyone else before the retry still lifts it as before.
