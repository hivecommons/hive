- Any lane can now keep a hive-authored pull request's description true after review changes it, through a new audited `edit_pr` relay operation ([#19399](https://github.com/hivecommons/hive/issues/19399)). `hive-open-issue edit-pr --repo <r> <number> [--title t] [--body b | --body-file f]` replaces the PR's title and/or body with the App token under the same file-UID authorizer, lane allowlist (new `edit_pr` operation), repo pause, repo scope, outbound prose filter and mention sanitizing as the other relays, and audits it as `agent_pr_edited`. It edits only PRs one of this hive's accounts opened, never a person's, another bot's or a merged one, never drops a `<!-- hive:carried-fence -->` marker the current body carries (it is re-added), and needs the `ISSUES_AND_PRS` tier of the direct edit. For a lane under `write_surface.enforce`, `gh pr edit --title/--body/--body-file` is translated into this relay instead of being refused; unenforced lanes keep their direct path. The review-feedback brief now tells the agent that pushes a review fix to refresh the stale parts of the PR body itself instead of asking a maintainer. Operators who narrow lanes with `write_surface.allowlist` add `edit_pr` to each lane that should have it.
