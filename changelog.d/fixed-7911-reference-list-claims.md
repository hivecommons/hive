- The PR claim ledger now sees every issue a pull request references, not just the one it closes ([#7911](https://github.com/hivecommons/hive/issues/7911)). Two gaps compounded: the non-closing reference tier (`Refs #N`, `Part of #N`, #3980) only ran when a PR had no closing keyword at all, so a maintainer's consolidation PR reading "Closes #159. Refs #72, #74, … #197" claimed #159 alone; and neither parser read a comma list, so even a bare `Refs #72, #74, #87` yielded #72. The contribute queue therefore offered projectbluefin/server#197 to an agent while the open PR removing the very subsystem the issue describes had said "Refs #197" for twelve hours — the agent's advisor caught it and the task ended `no_work_needed`, but the issue stays offerable until that PR merges. A referenced issue now gets its weak claim alongside the closed issue's strong one (an issue both closed and referenced keeps only the strong claim, so no existing claim changes target or strength), and a reference list on one line — commas, semicolons, `and`, `&`, cross-repo elements — yields every element. Lists are read only for references: GitHub closes only the first issue of "Fixes #1, #2", and the closing parser keeps parity with that so a strong claim is never asserted for an issue GitHub will leave open. Operators should see fewer already-claimed issues dispatched behind an open supersede or consolidation PR.
