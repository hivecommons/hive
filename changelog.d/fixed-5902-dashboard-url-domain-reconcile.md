- The hub now re-derives each hive's `DashboardURL` from its cluster's current domain on every heartbeat, instead of trusting the value minted once at provision time ([#5902](https://github.com/hivecommons/hive/pull/5902)). `DashboardURL` is built as `"<hiveID>." + cluster.Domain` when a hive is provisioned and nothing ever recomputed it, so a cluster that later changed domain left every hive provisioned before the change advertising a hostname no ingress serves — 21 of 95 hives, which is what a 404 on LKE and a login bounce on OKE looked like from the dashboard. That is not cosmetic: the hub pushes `DashboardURL` down on each heartbeat and the spoke adopts it (logged as "adopting vanity dashboard URL from hub heartbeat"), so the stale hub value also overwrote each spoke's own correct local config, and correcting a spoke's PVC could not hold — it reverted on the next beat. `VanityURL` already self-healed through `reconcileStaleVanityURL`; `DashboardURL` had no equivalent, so it drifted permanently. The re-derivation is deliberately narrow, firing only when the stored host is exactly `<hiveID>.<something-else>` — the shape provisioning mints — so a vanity host (whose leading label is a different hive-facing name) is left to `reconcileStaleVanityURL` rather than being churned every beat, and empty, unparsable, or already-correct URLs are untouched. The cluster registry is the source of truth and is unchanged; affected hives reconcile to it on their next heartbeat with no migration or manual edit.
