- Reviewer autoscale (`review.reviewers.autoscale`) now scales an agent that can take the reviews it is counting, and follows a change of agent. With no `agent` named it used to pick the first agent in name order with `role: reviewer`. The L5/L6 packs ship two of those, the swarm's `reviewer` and the escalated-PR `adjudicator`, and `adjudicator` sorts first, so a hive with `review.reviewer_agents: [reviewer]` grew `adjudicator-2` against a backlog only `reviewer` could work, then reported `blocked by at-max` while the PRs kept waiting. The default is now the first `review.reviewer_agents` entry the review swarm dispatches to, or with no list the first agent its `review` keyword scan admits; if there is none, autoscale stays off and says why. A named `agent` must be one the swarm dispatches to as well: `PUT /api/config/review` refuses any other with a 400 that gives the reason, and a `hive.yaml` that already names one still loads, with autoscale off and one `reviewer autoscale: not scaling` warning. Changing the agent (or turning autoscale off and on) used to do nothing until the next scaling decision: the old agent's extra replica kept running, the new agent inherited the old one's replica count, and nothing was logged. The next governor cycle now puts the old agent back on its declared `replicas`, starts the new agent from its own declared count clamped into `[min, max]`, starts the controller's streaks, cooldown and draining state again, and logs `reviewer autoscale: lane agent changed` with both agents. `GET /api/config/review` gains a `reviewer_autoscale` block (`enabled`, `agent`, `effective_agent`, `reason`), shown under *Scale reviewers with the backlog* as *Scaling **reviewer*** and returned by `settings_read` section `review` on the admin MCP. The entrypoint pre-creates replica users for every agent that could be the lane, so moving it between reviewers needs no restart.
