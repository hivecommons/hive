- New opt-in setting `auto_merge.human_merge_owner_approval`, a list of repositories, empty by default. A listed repository lets a trusted merger's explicit approval of a pull request's current head release the hold the hive puts on a pull request that touches a path a person must merge (`auto_merge.human_merge_paths`). The approval can be a GitHub **Approve** review, a `/hive decision approve` reply or a `/hive approve` reply posted after the head. The hive then merges the pull request once CI, review, soak and every other gate pass. A new push needs a new approval, a `hold` a person added is never lifted, and one comment per head records who approved which head. On a listed repository `/hive approve` replies "released for <sha>"; other repositories keep today's rule and reply. The setting is in **Settings → Features → Auto-merge → Per-repository merge policy**, `PUT`/`PATCH /api/config/auto-merge` and the admin MCP's `auto_merge.update` (Danathar/goodreads-mcp#463).
