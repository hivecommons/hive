- The `review_rejected` hook now fires ([#6259](https://github.com/hivecommons/hive/issues/6259)). The transition, its typed payload, the model-knob deep link, and the notification rendering all shipped with RFC #4001, but no production code path ever emitted it, so an operator who configured `on: review_rejected` got a validated, registered hook that could never run. The emitter is now wired at the approval desk: when an owner denies a queued agent action (`POST /api/approvals/resolve` or `/api/approvals/bulk` with `approved: false`), hive emits one `review_rejected` per denied item after the denial is journaled, carrying the requesting agent, the target repo and PR, the resolving operator as `actor`, the stated rationale as `reason`, the agent's effective backend/model/pin, the ACMM level, and the `model_knob_url` deep link built from `dashboard.public_url` (falling back to `hub.dashboard_url`, then the request host). A replayed resolve (409) and an ID another operator already resolved emit nothing. `hooks.EmitReviewRejected` now takes a `hooks.FireFunc` rather than a `*Dispatcher`, so a surface that reaches the dispatcher through a fire callback can use the typed emitter directly.
