- **A headless Claude Code contributor that has used up its plan limit now stops asking for work until the limit resets.** When the Claude Code CLI runs out of its allowance it exits within a couple of seconds and prints one line, for example `You've hit your weekly limit · resets Dec 1, 3pm (UTC)`. In headless mode the contributor relay did not recognise that line, so it reported an ordinary failure and asked for the next task straight away: one contributor was given twelve assignments in thirty hours, each of which failed at once and put a ten-minute failure cooldown on an issue nothing was wrong with (three in a row park an issue for six hours). The relay now treats that line as the account being out of quota, the same way it already did for Codex: the task it was seen on is handed back once as an environment failure, the relay stops asking for work and declines anything pushed to it, and it tells the hub it is held. The other wordings the CLI has for the same refusal are recognised too: `You've hit your limit`, the organization and channel monthly spend limits, and `You're out of usage credits`. The relay resumes by itself at the reset the line states, even when that is several days away; a reset like this is no longer cut to the six-hour ceiling used for countdowns, which would have meant a failed task every six hours until the reset. The reset is read in the timezone the CLI printed, whether that is `UTC` (a container) or a named zone such as `America/New_York` (a workstation), and with the year when the CLI prints one (`resets Jan 2, 2027, 3pm (UTC)`). The relay log says that the account limit is reached and gives the date and time work resumes, and waits of more than a day are shown in days. When the line gives no reset the relay can read (no timezone, a reset more than eight days away, or a same-day reset time that passed within the last ten minutes), the relay does not guess a deadline: it waits fifteen minutes and tries again. If the provider is still refusing, that wait now doubles each time (30 minutes, then 1, 2 and 4 hours, up to six hours) until a task finishes, so a limit that stays out no longer costs a failed task every fifteen minutes. This back-off applies to every backend whose quota refusal states no reset time, and the relay log says how long each wait is. A long hold is also released on time on a machine that was suspended part of the way through. Interactive (tmux) Claude sessions are unchanged.
