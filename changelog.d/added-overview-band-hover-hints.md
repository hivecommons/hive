- The hover text of each row in the Overview card's band lists (Issues by band, PRs by band) now says where that row's items are and, for PRs, what several of them are stuck on. Under the row's rule, a **Where** line lists its repos, largest first, at most three, then the rest as one count ("Where: api 8, cli 2, docs 2, 3 other repos 3"); a single repo left over is named instead, and the owner is left out when every repo on the chart has the same one. When two or more PRs in the row fail the same check, or have the same number of approvals while GitHub still requires a review, a further line says so ("5 fail the same check: e2e", "6 have 1 approval; GitHub still requires a review"). The approval line does not say how many more approvals are needed, since the missing review can be a code owner's. These lines are counted from the rows the page already holds (each item's repo, its failing checks and GitHub's review facts), never from reason text, and are left out when there is nothing to say, so a one-repo band reads as its rule and one Where line. Group and total rows read the items of their bands. Nothing on the card face changes, and nothing the hive does changes.
