- The close-on-merge ledger sweep now lists each claimed repository's open issues once per pass and only reads the PR and issue for claims whose issue is still open, instead of re-reading every merged claim kept in the 30-day ledger (closed issues included). This stops the post-restart quota spike where cold ETag/PR caches let the sweep exhaust the GitHub App's 5,000/hour core quota ([#11538](https://github.com/hivecommons/hive/issues/11538)). If listing a repository's open issues fails, that repository is skipped for the pass with one warning and retried on the next.
