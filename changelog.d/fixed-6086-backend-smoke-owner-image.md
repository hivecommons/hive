- **backend-smoke's pinned lane now tests the repository's own contributor image, not upstream's** (#6086). The lane exists to run the checkout's suite against the CLI binaries the contributor image actually ships, but it hard-coded `ghcr.io/hivecommons/hive-contributor:latest`, so a fork's lane silently exercised upstream's image and stayed green no matter what the fork shipped — while `docker.yml` already derives its push targets from `github.repository_owner`, meaning a fork published one image and tested another. The pull step now derives the image from the repository owner, falls back to the upstream image with a workflow warning when the owner-scoped one is not pullable (a fork that has not published yet still gets a meaningful run), and logs which image the lane pinned either way. The owner is lowercased before it becomes an image reference: container reference paths are lowercase-only, so a fork under an org like `Tuna-OS` would otherwise build an invalid reference that podman rejects before contacting any registry — taking the upstream fallback on every run, which is the same defect by a different route. `bin/test_backend_smoke_image_owner.sh` extracts the selection step from the workflow and runs it against a stubbed podman, so the fork case, the loud fallback, the lowercasing, and "no image at all is a hard failure" are all pinned.
