- **The dashboard's ▶ terminal now shows what a `sandbox.runtime: job` agent is doing** (#14798). Job-runtime agents run each kick as a Kubernetes Job in their own pod, so there is never a `hive-<agent>` tmux session in the hive pod and the terminal sat on "tmux session not created yet" until its wait expired. `ttyd-tmux.sh` now looks up the agent's Job pods by the launcher's `app.kubernetes.io/managed-by=hive-kubejob` / `hive.kubestellar.io/agent` labels with the pod's existing ServiceAccount and streams the newest pod's log read-only — following it while it runs and printing the exit status when it finishes — picks up a Job that starts while the terminal is waiting, and says plainly when the agent has had no run yet. Tmux agents and non-Kubernetes installs are unchanged.
