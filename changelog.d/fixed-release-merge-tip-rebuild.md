- Every automated release left `v4`'s tip unbuilt: `tagged-release.yml` merges the release PR via the API with `GITHUB_TOKEN`, and GitHub's recursive-workflow guard means that merge commit never fires `docker.yml`'s `push` trigger (the same gap #5072 closed for the scratch branch). The merge commit had no GHCR image and no `docker.yml` run, so the hub's "Latest available images" flagged `v4` as `! build stale/unknown` after each release (e.g. `c7a88b8` / v4.20.1), the `candidate` and `v4-latest` moving tags stayed pinned to the pre-release commit, and the hourly release backstop stood down on the tip until an unrelated push happened to rebuild it. The release job now explicitly dispatches `docker.yml --ref v4` once the merge and tag land, and the backstop's "images published?" check accepts that `workflow_dispatch` run on `v4` alongside ordinary `push` runs.
