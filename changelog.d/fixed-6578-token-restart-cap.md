- Fixed the token-restart cap never holding, which left agents blocked on a human device-flow login relaunching their CLI roughly every 65 seconds — three hives on the fleet page were in permanent restart storms at up to ×1334/24h. `decideTokenRestart` capped attempts at 3 and latched `tokenRestartGaveUp` correctly, but the pane poller cleared both halves of the cap on *any* pane that showed no login prompt. A pane also shows no login prompt while the CLI is still booting, which is exactly the state the token-triggered restart itself creates, so the give-up latch was wiped by the boot pane of its own restart and the cap could never survive. Re-arming now requires positive evidence the CLI is up — a CLI marker in the pane tail, plus a 60s boot grace after the last token restart matching `watchdog.DefaultBootGrace` — instead of the mere absence of login chrome. Because the latch now persists, `diagnoseStuckLogin`'s operator-facing "an operator must log in" diagnosis survives too, rather than being overwritten by a restart count every cycle ([#6578](https://github.com/hivecommons/hive/issues/6578)).
