- **Automerge no longer merges PRs with failing CI into unprotected bases** ([#11489](https://github.com/hivecommons/hive/issues/11489)). When GitHub reports a known-empty required-check set (unprotected base, or protection with no required checks), the sweep treated it like an unreadable set and deferred completed failures to the merge endpoint — which enforces nothing there, so #11471 merged into `v6` with 27 failing checks. Only a genuinely unknown required set (protection lookup failed) now defers to server-side enforcement; with a known-empty set, completed non-meta, non-ignorable CI failures block locally with `check-failure` / `status-failure`, while the metadata carve-out (#11456) and the positive-evidence and fresh-head guards (#11424) are unchanged.
