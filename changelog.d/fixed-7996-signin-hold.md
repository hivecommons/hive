- A contributor whose agent CLI login has expired now stands down instead of failing every task it is given ([#7996](https://github.com/hivecommons/hive/issues/7996)). A lapsed Claude session answered each task prompt with `● Login expired · Please run /login` and returned to a healthy-looking prompt, which the relay read as a ready CLI: it reported `ready`, took the next lease, and the task died thirty minutes later on the progress watchdog as `[environment] no observed progress for 30min — the agent CLI is not visibly working`. One reported host repeated that for eight hours across nine issues, with nothing outside the container saying "log in" — the dashboard's green agent dots are the hub's own agents, which had a working login. The relay now recognises the CLI's own sign-in refusal (chrome-gated, so an agent that merely writes about `/login` cannot trip it, and a 403 or a quota banner keeps its existing bucket), hands the task back within a progress interval with a reason that quotes the CLI's line and gives the attach command, and withholds `ready` — declining pushed assignments too — until somebody has been at the tmux session, restating the reason on a fixed cadence while it waits.
