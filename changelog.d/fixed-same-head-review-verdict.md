- A second automatic review of the same PR head no longer clears the first one's `requires_human`, `changes_requested` or `reject`. The relay keeps one report file per perspective, not per run, so the review that finished last used to decide the verdict. A less strict verdict now replaces a stricter one on the same head only when the hive asked for it after the stricter verdict arrived: a `review.revise_verdicts_before` revisit, a body-edit revisit, or an expired incomplete re-review. A new head or a person's decision clears it as before. A refused review is never posted as an approve: the findings of the perspectives that were accepted go up as a COMMENT, and when there are none nothing is posted. The queue lane also skips heads the review swarm already has in flight (`[hive-reviewed: dispatched@<sha7>]`), and the planner no longer re-asks a head whose report arrived after the last verdict refresh.
