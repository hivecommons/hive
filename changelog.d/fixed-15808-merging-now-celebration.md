- Activity monitor: "⟳ Mergeable · merging now ⬡" no longer lingers for minutes — the sweep clock now marks only the PR actually under evaluation, and a merge call that returns patches the cached snapshot and nudges the SPA at once, so the row reaches ✓ within one poll. Every hive-performed merge (trusted-author, self-authored, contributor and stage-engine lanes alike) celebrates exactly once — toast with the PR number, bee flight, odometer +1 after landing — even when the row vanished before the SPA saw the merged state (reconciled by `recently_merged` / `recently_closed` on removal) — a merge whose row is not on the board (below the fold, filtered, already evicted; #15707) now flies its bee from the toast's ✓ to the counter instead of skipping bee and odometer; a row that vanishes because its PR was closed, not merged, shows a neutral "#N closed · <reason>" toast instead of disappearing silently. The merge-gate "Merging · merge landed" bridge is now a ceiling, not a fixed delay: `dashboard.stage_tracker.merged_hold_s` (default `8`, min `3`), with the celebration launching as soon as the merged fact arrives; a merge call or sweep in flight for over 60 s reads "merging · waiting for GitHub…" ([#15808](https://github.com/hivecommons/hive/issues/15808)).
