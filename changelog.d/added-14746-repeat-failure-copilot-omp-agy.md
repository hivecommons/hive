- **The repeated-failure check now sees commands run by copilot, omp and headless agy agents** ([#14746](https://github.com/hivecommons/hive/issues/14746), [#14747](https://github.com/hivecommons/hive/issues/14747), [#14750](https://github.com/hivecommons/hive/issues/14750), part of [#14550](https://github.com/hivecommons/hive/issues/14550)). These backends run shell commands where the neutral `BASH_ENV` route never reaches them, so an agent retrying the same failing command went unnoticed. With `repeat_failure.enabled` on, Hive now reads Copilot's `events.jsonl` session log (one record per shell `tool.execution_complete`, with the real exit code), loads a Hive-owned omp extension via its own `--extension` flag (one record per bash `tool_result`, fail-open), and has `hive agy-turn` record each finished `run_command` step. Nothing is written into the backends' own settings; with the check off Hive passes no flag and removes the omp extension at the next launch. copilot and omp are marked covered in the "Repeated-failure check" table of `docs/backend-support-tiers.md` with committed, re-runnable harness evidence; agy stays "not covered" there until a real-run harness can log in.
