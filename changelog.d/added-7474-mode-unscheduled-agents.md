- The dashboard now names an agent that *some* governor mode schedules but the current one does not ([#7474](https://github.com/hivecommons/hive/issues/7474)). The live shape is a reviewer whose only cadence is in `surge`: it is kicked while the backlog holds the fleet in surge, and the moment its own work drives the backlog below the threshold the fleet drops to `busy`, where it has no cadence — and none in `idle` to inherit — so it goes silent with the queue still high, while every existing signal (enabled, session up, a cadence configured, not on-demand) reports it healthy. `NoCadenceAgents` cannot see this because the agent *has* a cadence. A new `governor.ModeUnscheduledAgents` detector — the weaker sibling of `NoCadenceAgents`, following the governor's own current-mode → idle resolution chain, so an idle entry inherited by every mode is never flagged and an explicit `pause`/`off` entry stays an operator choice — drives an amber `agent-mode-unscheduled` banner (`agent(s) reviewer (cadence only in surge) not scheduled in the current busy mode — … add a busy cadence … (an idle cadence is inherited by every mode)`) and a per-agent `unscheduledInMode` flag with `cadenceModes`, so the card renders the agent in the same hollow-green "off" state as a governor-paused one, its `scheduling` segment reads `no cadence in busy (only in surge)`, and the ⚙ action opens the Cadences tab. The predicate lives once, in `config.ModeSchedulesIn`, and a test pins it against the governor's `resolveCadence` so the banner and the card cannot name different agents.
