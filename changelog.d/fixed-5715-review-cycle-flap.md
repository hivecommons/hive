- A WebSocket flap no longer aborts the contributor relay's PR review cycle ([#5715](https://github.com/hivecommons/hive/issues/5715)). After every fifth completion the relay builds a review task for *itself* — a `pr-review-…` id, `number: 0`, no `task_assign` and no server-issued lease — but the reconnect path re-asserted whatever was in `currentTask`, so it claimed a task the hub had never heard of. The hub correctly refused under the server-issued-lease rule and answered `task_revoke: no active lease for this task`; the relay treated that as terminal, stopped the agent, relaunched the CLI and asked for fresh work. The give-away was the log line naming an issue that does not exist: `Reconnected while working on kubestellar/hive#0 — resuming`. On a hive where `1006` closes are routine — 29 in under four hours in the report — a review taking a couple of minutes almost never ran to completion, so PR review coverage silently did not happen. Reproduced twice four months apart, on `claude` and on `agy`. Locally-created tasks are now marked as such: the relay withholds hub ownership frames (`task_accepted`/`task_progress`) for them, because no lease exists for the hub to confirm, and ignores a revoke that names one, because a task no hub ever owned cannot have been handed to another contributor. The review keeps running and still reports `task_complete` and `ready` when it ends. Resume behaviour for real, hub-assigned tasks is unchanged.
