- The built-in destructive-`rm` check in `crux/toolapprove` now reads a command the way bash would hand it to `rm`, without running anything, and judges what each target means rather than how it is spelled ([#16094](https://github.com/hivecommons/hive/issues/16094)). Quoting and escapes, `$'…'` strings, brace expansion (`/{,}`, `{rm,-rf,/}`), `.`/`..` components (`/tmp/..`, `$PWD/../../..`), `$IFS` splitting, subshells, command substitutions and re-quoted commands (`bash -c '…'`, `eval`) now resolve to the same verdict as plain `rm -rf /`. A recursive `rm` of the root, the home directory, the working directory or any ancestor of one is flagged. That set now includes `rm -rf .`, `./*`, `..` and `"$PWD"`, matching the existing treatment of `rm -rf *`. A new spelling-equivalence test derives about 70,000 bash-equivalent commands from destructive and safe seeds and gates every detector change on them. The analysis has explicit limits: 1024 brace words per word, nesting 32 brace groups and 8 re-read levels deep, and a work budget proportional to the command. A command past them is reported as a separate `shell command exceeds destructive-command analysis bounds` violation instead of passing clean. The `rm` branch of the old regex is retired, so its false positives no longer fire: non-recursive `rm -f /`, literal `'$HOME'` and `"~"`, and `a=rm -rf /`. An `rm` that is the subcommand of a version-control tool (`git rm -r --cached .`, `hg rm`, `svn rm`) is not the binary and is not flagged.
