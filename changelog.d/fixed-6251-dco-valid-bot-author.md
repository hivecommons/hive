- Commits agents author as this hive's GitHub App bot now pass the DCO check ([#6251](https://github.com/hivecommons/hive/issues/6251), [#6254](https://github.com/hivecommons/hive/issues/6254)). The derived git identity used GitHub's own bot address, `<slug>[bot]@users.noreply.github.com`, and probot-dco validates the sign-off email's syntax before comparing it to the author: the `[` and `]` in the local-part fail that check, so every such commit was rejected as "not a valid email address" - a matching `Signed-off-by` could not fix it, a second human sign-off could not fix it, and with no `.github/dco.yml` there was no remediation path (seen on [#6164](https://github.com/hivecommons/hive/pull/6164), which had to be re-authored by hand). The bot identity keeps its `<slug>[bot]` name but its address is now the bracket-free `<slug>@hive.kubestellar.io` (domain configurable via `HIVE_GIT_BOT_EMAIL_DOMAIN`), the same shape as the agent PRs that already pass DCO; because `git commit -s` writes that same address into the trailer, author and sign-off match. The App still owns the PR and the push. A `project.ai_author` naming a user keeps its attributable `<login>@users.noreply.github.com` address, which is already valid, and hives without a usable App are unchanged. The entrypoint regression test now asserts that every derived identity is a syntactically valid, bracket-free address.
