- Admin MCP reads no longer mask values that cannot hold a credential. A read masked everything under a key containing `token`, `secret`, `password`, `credential` or `authorization` (booleans and `*tokens` counts excepted), so `settings_read` returned `[masked:token]` for the name of the environment variable that supplies a secret (`token_env`, `gitlabTokenEnv`, `webhookSecretEnv`), which the tool promises to show; for a numeric rate (`tokens_per_coin`); for the whole per-repository self-authorization hold policy (`repoSelfAuthorizationHold`); and for a secret that is not set at all, which read the same as one that is. `contributors_list` hid `token_expires_at`, `token_issued_at` and `token_last_used_at`. These are now shown: an empty value or `null`, an empty list or object, a timestamp, a token count or rate, an upper-case environment variable name under a key ending in `env`, and the self-authorization hold settings. Everything else under those keys is masked as before, kept values are still scrubbed by shape, and the stricter rule that decides what a write preview may store is unchanged.
