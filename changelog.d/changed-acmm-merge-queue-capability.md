- The ACMM `acmm:merge-queue` check now tests the capability on the default branch instead of a file name ([#10891](https://github.com/hivecommons/hive/issues/10891), part of [#10884](https://github.com/hivecommons/hive/issues/10884)). It passes, and counts toward Level 6, when GitHub's merge queue is on ("satisfied by GitHub merge queue") or when the repo's `merge_strategy` is `hive-serialized` and the branch has a known, non-empty set of required checks ("satisfied by Hive serialized merge lane"). A pass that rests only on a marker file (`.github/workflows/merge-queue.yml`, `.github/merge-queue.yml`, `.prow.yaml`, `tide.yaml`) keeps passing, labelled "file only, not verified", so no repo loses readiness. A failing row offers an owner the action to use the serialized merge lane. On personal-account repositories, where GitHub's merge queue is unavailable, the gap ticket (single or "Open Issues for L6") explains the serialized merge lane and required checks instead of asking for a file and no longer carries `ai-fix-requested`; organization repositories get the same ticket as before. The tooltip and the Level 6 description now read "a merge queue or equivalent serialized merging".
