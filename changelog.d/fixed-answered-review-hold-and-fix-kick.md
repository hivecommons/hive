- A PR whose `requires_human` review verdict a person has answered no longer stays in the owner's your-turn queue, and the answer now reaches the author agent on hives without review approval ([Danathar/dns-failover#155](https://github.com/Danathar/dns-failover/pull/155)). After the owner's `/hive decision <instruction>`, the hive recorded the decision for the head and moved the PR to `stage/070-fixing`, but the dashboard kept the row as "Hive's review needs a human decision" for over an hour, and no fix was ever dispatched: the review planner returned before reading any answer whenever `review.require_approval` or `review.fan_out` was off. Ownership now reads the recorded answer for the current head (the decision ledger the stage engine already reads), so an answered `requires_human` or `reject` verdict reads "@who answered Hive's review on this head …; the hive is fixing it" until a new head or a newer verdict; a dispatcher hold or the fix-loop cap stays the owner's. With review dispatch off, the planner now plans only answered heads, handing each instruction to the author agent once per head exactly as with review on, and leaves every other PR's dispatch state alone.
