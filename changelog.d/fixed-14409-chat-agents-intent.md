- Hive Chat now answers agent questions instead of dumping the roster (#14409). `/agents stuck`, `/agents scanner status` and "Which agent completed last?" all used to return the identical 16-line agent list with a bare `BLOCKED` label and no reason. `/agents stuck|blocked|paused|running|idle|failed` now filter the roster, blocked agents carry the hive's recorded WHY (rate-limit cap, inference auth, policy stand-down, crash loop, failed starts) and since-when, `/agents <name> [status|why|last|history]` / `/agents status <name>` / "scanner status" return only that agent's card (state, block reason, current task, last completed turn and outcome, last kick, last PR/issue, restarts; unknown names list the valid agents), and natural-language questions — "which agent completed last", "what is scanner doing", "why is reviewer-2 blocked", "when did scanner last run", "which agents are idle" — go through a table-driven intent matcher. Unmatched agent questions reach the configured chat responder with the agent state attached rather than the roster. Bare `/agents` keeps the roster but appends the block reason inline. The reason and timestamp are exposed on `/api/status` `agents[]` as `blockedReason` / `blockedSince` (plus `kickOutcomeAt`) so chat and the Agents page agree.
