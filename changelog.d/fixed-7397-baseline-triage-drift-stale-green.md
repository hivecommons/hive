- `hive-baseline-check.sh`, the shared-CI classifier every PR-repair policy consults, no longer misroutes in either direction ([#7397](https://github.com/hivecommons/hive/issues/7397)). It trusted the default branch's *recorded* check conclusion, so a check gated on wall-clock time (a generated artifact stamped with today's date) stayed "green" for days while every fresh run was red, and the helper called a real incident PR-local — sending a scanner to repair 18 innocent PRs. In the other direction, its "red on ≥3 sibling PRs" arm counted siblings that were merely *behind* the default branch, so seven PRs six commits behind a green base were called an incident when merging base cleared them. The helper now samples whether the red siblings are behind the default branch (`repos/{repo}/compare`) and how old the base conclusion is: every red sibling behind a **fresh** green base is branch drift (`MERGE_BASE`, exit 1), every red sibling behind a **stale** green base — older than `--max-baseline-age-hours`, default 24 — is `RERUN_BASELINE` (exit 2, unknown: re-run the check on the default branch before repairing anything), and any *up-to-date* red sibling makes the check shared regardless of the base's age. It also accepts the PR number as a third argument and emits the action the agent needs — `DEFER_TO_INCIDENT`, `MERGE_BASE`, `FIX_DIFF`, `NOT_REACHABLE_FORK` (the head is in a fork; comment, never push), or `RERUN_BASELINE` — in both the human and `--json` output; exit codes 0/1/2 keep their meaning. The "Shared CI Baseline Triage" fragment in every PR-repairing policy now passes the PR number and acts on `action`.
