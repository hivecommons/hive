- **Optional GitHub API budget pacing for the governor loop.** A polling hive with many repositories could spend its whole hourly GitHub budget in the first half of the hour and then make no GitHub calls until the reset, which stopped reviews, merges, hand-offs and fix dispatches; the conserve and critical modes only react once few calls are left. The new `governor.api_budget_pacing` (default off) measures the hive's own charged core calls per minute over the last 10 minutes and, when that rate would use up the calls left above `github.api_reserve` before the window resets, lengthens the eval interval and the sweep workers' intervals by `rate × minutes to reset ÷ (remaining − reserve)`, never past `governor.eval_interval_max_s` and never past the reset. It only lengthens an interval, holds a factor until the need moves by more than 25% or clears by a 20% margin (logged once per change as `github api budget pacing changed`), and leaves webhook and review wakes alone. `/api/status` (`api_budget_pacing`) and `GET /api/config/governor/general-advanced` (`api_budget_pacing_state`) report `enabled`, `active`, `factor`, `effective_interval_s`, `burn_per_min` and `reason`; Settings → General has the toggle and the live state. The admin MCP gains `governor.general_settings`, which previews and confirms changes to the General settings (the eval interval, the loop pacing knobs and the pacing switch) through `PUT /api/config/governor/general-advanced`, sending only the fields that change and refusing a stale preview. What is and is not paced is listed in `src/docs/operator-reference/runtime-and-quota.md` (API budget pacing).
