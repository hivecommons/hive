- **GitHub webhooks now wake the governor loop and refresh the stage tracker in seconds, with fewer GitHub calls.** A verified `POST /api/webhook/github` delivery that invalidates cached state — `pull_request`, `pull_request_review`, `pull_request_review_comment`, `issue_comment`, `check_suite`/`check_run`, `push` to a PR branch, `issues` label/reopen — asks the loop for an early eval cycle, debounced by `governor.webhook_wake_debounce_s` (default `10`) and spaced at least `governor.webhook_wake_min_gap_s` (default `30`) apart; the wake cycle re-enriches only the PRs the webhooks marked dirty and serves every clean PR from cache, so `eval_interval_webhook_s` (default `900`) is now a safe base tick while webhooks are healthy. The loop re-checks webhook health when the `2 × eval_interval_s` window closes and drops back to `eval_interval_s` right away rather than at the next stretched tick, logging one line per transition (`github webhooks healthy; eval mode webhook` / `github webhooks went stale; eval mode poll`); `/api/status` reports `evalMode`, `evalIntervalS`, `lastWakeReason`, `lastWakeAt` and `webhookWakes`. Each status publish also invalidates the `/api/stage-tracker` cache and sends a `stage-tracker` SSE event the dashboard refetches on, instead of waiting out the cache TTL plus its 30 s poll. See the operator reference's "Webhook-driven PR cache invalidation" for the App event subscriptions and `GITHUB_WEBHOOK_SECRET` setup.
