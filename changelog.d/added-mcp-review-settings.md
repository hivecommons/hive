- The admin MCP can now change review settings, not only read them. The new owner-only write operation `review.settings` sends a partial body to `PUT /api/config/review`, the endpoint behind Settings → Review Gate: pass only what changes, for example `{"reviewer_autoscale": {"enabled": true, "max": 2}}`, and only those fields are sent, so a dashboard edit to any other review setting is never overwritten. The preview reads the current settings and shows each named field before and after (sub-objects such as `reviewer_autoscale`, `severity` and `backlog` field by field; for `verdict_labels` and `recommendations`, which the endpoint replaces whole, every key the change clears), discloses turning `require_approval` off, a less strict `severity.block_at` and more autoscaled reviewers as widening, and refuses an unknown field with the list of accepted ones. A test keeps the accepted fields in step with the endpoint's body. The endpoint's own checks (an autoscale `min` above `max` and the like) come back as its error, a stale preview is refused at `write_confirm`, and `write_confirm` reads the named fields back and reports them as `after`.
