- Chat replies and notifications longer than the transport's message limit are now split by the shared chat spine before they reach a backend, and rate-limited sends are retried instead of dropped ([#9127](https://github.com/hivecommons/hive/issues/9127)). Previously a Discord reply over 2,000 characters — a `!runs` listing with a few dozen runs was enough — was posted whole, rejected with HTTP 400 and silently lost, while a Slack `429` slept the uninterruptible `Retry-After` on the drain goroutine and then discarded the message anyway. `drainLoop` now cuts every queued message to the backend's configured limit (line boundaries, code fences closed and reopened across chunks); Discord and Slack return a typed `chat.RetryableError` on `429` (Discord also parses `retry_after` on message polls) and on 5xx, and the spine waits the capped, context-aware `Retry-After` before re-sending the same chunk, up to three attempts, so shutdown is never blocked on a rate-limit sleep.
