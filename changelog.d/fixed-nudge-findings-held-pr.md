- The contributor nudge now lists what the review asked for on a PR that a gate holds, and never says only "the review swarm requested changes" for a blocking verdict (follow-up to [#17906](https://github.com/hivecommons/hive/pull/17906)). A contributor PR with an open sentinel alert or a hold-class label is skipped by the contributor lane before it reads the reviewer verdict, but the stage pass still returns it to its author at `stage/072-returned-to-contributor` when the review swarm asked for changes on the head. The `hive:contributor-nudge` comment and the relay's `fix-pr` task for such a PR carried the lead line alone, with no `review finding: path:line title` line, so the author's relay was told something was wrong but not what, and could answer with a push that changed nothing the review had asked for. The stage pass now hands the findings of the verdict it routed the PR on to the nudge, so a held PR gets the same **Review asks** as any other. A reviewer can also block without a structured finding and explain itself only in its summary ("still present at this head"): the review aggregate now keeps the blocking perspectives' summaries (`block_summaries` in `review-verdicts.json`) and the nudge lists one `review summary: <perspective>: <summary>` line each when the verdict has no in-scope finding, trimmed and mention-neutralised like a finding line and capped at five with a count of the rest. Verdicts recorded before this change gain the summaries the next time their reports are collected. A verdict that does not block adds no such lines, the stage a held PR is routed to and its route reasons are unchanged, and a PR no gate holds gets the same nudge as before.
