- The contributor relay no longer reports a task as **completed** when its prompt was never submitted to the agent CLI ([#6717](https://github.com/hivecommons/hive/issues/6717)). A ~2 KB task prompt is typed into the pane as one `tmux send-keys -l` burst, and a TUI with bracketed-paste handling classifies a burst that fast as *pasted content*: codex collapsed it to `[Pasted Content 1024 chars]` in its input widget and took all three Enters as newlines inside the paste rather than as submit. The agent never ran, the pane therefore never changed, and the `chrome_idle` fallback read that stillness as a finished turn — booking the issue **done** with no commit, no branch, no PR and the checkout untouched, and removing it from the offer queue for good. A false completion is strictly worse than a false failure here, because a failure is re-offered and a completion is never looked at again. Three changes, in the order they now apply: the send path waits for the widget to finish ingesting the burst before submitting, so the Enter is a keypress and not pasted text; it then re-reads the pane and re-sends Enter while the prompt is still sitting collapsed in the widget; and `chrome_idle` may no longer complete a task at all when the prompt is *still* visibly unsubmitted **and** the pane has not changed by a single byte since delivery — that task is reported `task_failed` (`failure_kind: environment`) so the hub re-offers the issue. Both signals are required together, so a CLI that echoes a submitted paste back into its transcript cannot have working tasks failed, and an agent that finished without printing `HIVE_VERDICT` still completes on the fallback exactly as before. A `chrome_idle` completion carrying neither a verdict nor a PR is now also logged as a warning to audit, since that combination is the shape of this bug.
