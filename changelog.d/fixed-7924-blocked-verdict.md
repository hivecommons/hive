- Contribute: an agent that finds an issue blocked on something outside its repository — another repo's release or build, a dependency that has not published — can now say so with `HIVE_VERDICT: blocked — <what it is waiting on>` (or `no_work_needed — blocked: …`), and the hub stops throwing that finding away ([#7924](https://github.com/hivecommons/hive/issues/7924)). Before, such a verdict was booked as an ordinary `no_work_needed`, the issue came back on the 4h no-PR backoff, and every retry re-ran the same research to re-discover the same external dependency (projectbluefin/utah#100: ten minutes of research to find "no factory image carries the new packages yet", then the same ten minutes again on the next rung). A `blocked` completion is now held for the full with-PR cooldown from the first time, its ledger row carries the marker and the reason so an operator can see what it is waiting on, and its reason is not mistaken for a settlement. When the task credential can write issues, the relay also applies the repository's `blocked` label — the existing admission gate then withholds the issue until a human clears the label, which the relay never does itself. The assignment prompt asks the agent to leave one signed comment on the issue naming what covers or blocks it before printing either verdict, so the finding survives on GitHub and an open PR gets cross-referenced to the issue it covers; it also tells the agent never to edit someone else's PR body to add `Fixes #N`. On the wire the relay sends the marker alongside the `no_work_needed` an older hub already books, so mixed relay/hub versions behave as before.
