- `log_read` (admin MCP) and `GET /api/logs/read`: a log file whose first line is longer than 64 KiB can be paged. Paging identifies a file by a digest of its first line. The digest was taken over the whole line when a page was returned but over at most 64 KiB when the cursor was looked up, so the two never matched: following `next_cursor` into such a file always answered `cursor_expired` ("no longer retained"), and only the newest page of that file could be read. This hit `hive.log` and its rotated history when a file opened with a very long record, and the `proxy`, `litellm` and `hive-output` sources whenever a file opened with a runaway line, since those are stored in 64 KiB pieces that are each longer than 64 KiB once wrapped. The digest now covers at most the first 64 KiB of the line on both sides.
