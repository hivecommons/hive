- Adoption no longer closes and re-opens a contributor PR whose branch lives in the base repository just because the base changed a file under `.github/workflows/`. The hive used to assume the App can never push such a base-sync and superseded the PR, which dropped its approvals and number (projectbluefin/common#1689 became #1708). Now it checks the installation: when the App installation grants `workflows: write` and a trusted- or merger-tier lane serves the repository, the PR is adopted in place on its own branch. Fork PRs are unchanged, because GitHub refuses any App workflow-file push to a fork whatever the base installation grants. A refused `update-branch` during adopted-PR recovery now logs `fork-workflow-update` or `workflow-permission` instead of the catch-all `update-branch-failed`.
