- "Let hive decide" no longer promises a merge-queue merge on a repo the hive does not merge. Its approval comment said "The merge queue merges this PR once its checks are green — expected within 30 min." even where auto-merge is off (the repo's auto-merge setting, or a hive below ACMM L6), so a person had to merge the PR and nothing ever did what the comment promised ([projectbluefin/documentation#1707](https://github.com/projectbluefin/documentation/pull/1707)). The comment, the result toast ("Hive merges it on its next merge pass…") and the decision preview ("…let the merge queue merge it") now read the same per-repo auto-merge switch as the merge sweep and say a person merges the PR; the comment and the toast also say how to merge it by hand. The Activity Monitor row moves to Ready for human merge instead of "Queued for merge · next pass" and no longer turns into "no effect after 30m", and clicking "Let hive decide" again past the effect deadline is a plain no-op instead of posting a "decision-stalled" follow-up for a merge only a person can make. The mergeable-as-is rule's wording no longer says the PR goes to the merge queue, since that is true only where the hive merges.
