- The hub now records the contributor relay's lifecycle in the existing `/data/audit.jsonl` as `relay_*` rows — `relay_connected`, `relay_rejected`, `relay_disconnected`, `relay_task_assigned`, `relay_task_accepted`, `relay_task_declined`, `relay_token_minted`, `relay_task_completed`, `relay_task_failed`, `relay_task_revoked` and `relay_task_abandoned` (plus the reserved `relay_mcp_lease_issued` / `relay_mcp_lease_revoked`) — attributed to the contributor's GitHub login and session, with the task's repository and issue/PR number. Rows are written from frames the hub already receives, so an unmodified relay needs no change; progress and heartbeat frames are not audited and no token is ever written. `relay_token_minted` (which carries the `installation` id) and `relay_task_revoked` are sensitive actions and raise `sensitive_24h` on hives with active contributors; `relay_connected` is not sensitive and omits the remote address. Documented in `audit-log.md` and `contributor-relay.md` ([#13453](https://github.com/hivecommons/hive/issues/13453), part of [#13441](https://github.com/hivecommons/hive/issues/13441)).
