- **GitHub webhooks now move the Hive activity monitor row for just the PR or issue that changed, in seconds.** A verified `POST /api/webhook/github` delivery that names an item this hive tracks (`pull_request*`, `check_suite`/`check_run`, `status`, `push` to a PR branch, `issue_comment`, any `issues` action) drops the `/api/stage-tracker` cache at once and queues a targeted re-read of that one item — a single `GET`, debounced by `dashboard.stage_tracker.webhook_refresh_debounce_ms` (default `2000`) and coalesced per item so a check fan-out costs one request — then patches its row in the status snapshot (labels, title, draft flag, last activity; closed or merged items leave) and sends the `stage-tracker` SSE nudge. Before, a webhook only invalidated caches and the tracker waited for the next eval cycle (120 s today, up to `governor.eval_interval_webhook_s` = 900 s in webhook mode), so webhooks made the tracker slower rather than faster. No repository is re-enumerated; the read uses the paced REST transport and is skipped while the API budget is critical. `dashboard.stage_tracker.webhook_refresh: false` turns it off. `/api/status` and `/api/gh-rate-limits` `webhooks{}` additively gain `targeted_refreshes_1h` and `tracker_invalidations_1h`.
