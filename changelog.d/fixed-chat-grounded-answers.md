- Hive Chat now answers the question it was asked instead of a canned dump. The server used to tokenise every message into a bag of words and match on keywords alone, so `/agents stuck`, `/agents scanner status` and "Which agent completed last?" all returned the full agent roster and `/prs waiting on review` returned per-repo PR counts, with the arguments silently discarded. A new router keeps the arguments: a bare `/agents`, `/prs`, `/beads` or `/status` still prints its summary, while a command with arguments or a plain-words question is answered by one read-only model turn over a compact, scoped snapshot of the hive state the dashboard already holds (agents with blockers, last kick and last completed action; open PRs with stage labels, review state, CI and age; actionable issues; items awaiting a decision; governor; alerts; version and last upgrade), instructed to say "I don't have that data" rather than guess and to cite the items it used. The turn runs on the governor reviewer endpoint with a timeout and in-flight cap, writes one `chat_grounded_answer` audit line, and can never trigger an action. When grounding is unavailable a scoped question gets the command's usage, never the bare dump. New setting `chat.grounded_answers.enabled` (default on) and `chat.grounded_answers.model`.
