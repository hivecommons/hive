- Sentinel no longer re-flags a PR a maintainer already cleared when a later push leaves every flagged change exactly as reviewed, such as a merge of the base branch from the hive's keep-mergeable step or "Update branch". Each alert now records a digest of what it flagged (each finding's rule and paths, and every flagged file's status and patch against the merge base, read from GitHub's PR files API). A new head with the same digest, after a human (not a Hive account, not a bot) removed the label, counts as cleared: the label is not re-applied and the marker comment is rewritten for the new head. A push that changes a flagged file's patch, flags something new, or returns a flagged file without a patch still re-alerts, as does any alert written before digests existed. This extends the clearance-on-a-newer-head rule from [#13602](https://github.com/hivecommons/hive/issues/13602) to removals made before the push.
