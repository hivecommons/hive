- A single invalid per-agent overlay file no longer bricks the whole hive ([#6024](https://github.com/hivecommons/hive/issues/6024)). A hosted spoke crash-looped for eight hours on `agent supervisor: backend "copilot" contradicts launch_cmd "bob --model auto"`, and the contradiction was not in `hive.yaml` at all - it came from `/data/agent-configs/supervisor.yaml`, which `LoadAgentOverrides` merges over the config after it loads. Because the process exits before the dashboard binds, the documented fix (`PUT /api/config/agent/{name}/...`) was served by the very process the config was killing, so there was no supported way back in short of scaling the Deployment to zero and hand-editing the PVC from a maintenance pod. Invalid overlays are now rejected individually: the offending file is skipped, the agent falls back to its main-config entry so the running roster does not change, the skip is logged at ERROR naming both the agent and the file, and the hive boots with its dashboard reachable.
- Config validation errors now name the file an agent came from - `agent supervisor (from /data/agent-configs/supervisor.yaml): ...` instead of just `agent supervisor: ...` ([#6024](https://github.com/hivecommons/hive/issues/6024)). `hive.yaml`, the ConfigMap seed, the dashboard overlay and the per-agent overlay directory all feed the same agent map, and naming only the agent sent an operator editing three files that were never the problem.
- New `hive validate` (alias `hive --config-check`) loads the config exactly the way a real boot does - per-agent overlay files included, since that is where the #6024 contradiction lived - prints any error and exits non-zero, without starting anything ([#6024](https://github.com/hivecommons/hive/issues/6024)). Previously the only way to learn a config was invalid was to apply it and watch a pod crash-loop.
