- `hive-deploy.service` no longer trusts an unverified `/tmp/hive` checkout as the source of its `sudo` sync into `/usr/local/bin` ([#5936](https://github.com/hivecommons/hive/issues/5936), same class as [#5435](https://github.com/hivecommons/hive/issues/5435)/[#5483](https://github.com/hivecommons/hive/issues/5483)). `bin/hive-deploy.sh` `cd`s into `/tmp/hive` checking only that `.git` exists, runs git inside it (executing the checkout's own hooks), and `sudo cp`s every changed `bin/*.sh` over its `/usr/local/bin` counterpart — including `bin/hive.sh` → `/usr/local/bin/hive` and `bin/gh-wrapper.sh` → `/usr/local/bin/gh`, which fronts `/usr/bin/gh` in PATH for every user. `/tmp` is cleared on reboot and its sticky bit does not stop a local user *creating* `/tmp/hive` before the checkout is restored; with `hive-deploy.timer` firing at `OnBootSec=60`, the winner of that race had their scripts root-installed host-wide within a minute of boot — a strictly larger payoff than the `dev`-execution races already fixed in the discord and snapshot units, yet this was the one unit in the class left unguarded. The unit now runs `ExecStartPre=hive-checkout-guard.sh /tmp/hive/bin hive.sh gh-wrapper.sh hive-deploy.sh hive-checkout-guard.sh` (the #5481 guard generalizes without modification), refusing to start when any path component or pinned file is attacker-owned, writable by others, or a symlink; a missing checkout is a refusal, matching the script's own "not a git repo" bail-out. The #5481 hardening directives are deliberately *not* applied — `NoNewPrivileges` would break the script's `sudo` sync and any `ProtectSystem` level mounts `/usr` read-only, the very place this unit installs to — and `src/deploy/test_hive_deploy_unit_contract.sh` pins the guard wiring, those exclusions, and the guard's refusal of each attack shape by executing it against real trees.
