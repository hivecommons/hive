- A contributor task that read an older pull request before opening its own no longer loses credit for the one it shipped ([#7789](https://github.com/hivecommons/hive/issues/7789)). The relay verified only the first PR URL on the pane, and when that one was refuted as "researched, not this task's work" (#6662) it stopped there — so an agent that checked prior PRs first, as the task prompt tells it to, and then opened its own PR further down was booked as `verdict=idle` with no `pr_url`; observed live when utah#131 shipped utah#205 and the hub credited nothing. The relay now collects every distinct PR URL for the task's repo, ranked with the URL named on the agent's `HIVE_VERDICT` line first and then newest-printed first, and verifies them in that order until one is not refuted; each refuted candidate is still logged as before, and at most eight are looked up per completion so a pane full of researched PRs cannot stall the tick loop.
