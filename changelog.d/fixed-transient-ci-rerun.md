- A red hive pull request whose failure an agent triaged as infrastructure is now re-run instead of sent back to a fixer. On [projectbluefin/common#1647](https://github.com/projectbluefin/common/pull/1647) the agent said "infrastructure, not this change" four times, the fix loop still counted six fix re-dispatches on that one commit and escalated the PR to a person, and a lane then pushed an empty "retrigger CI" commit. When every failing check run on the head carries a `hive-ci-transient` marker, Hive now re-runs the failed jobs once for that head (`rerun-failed-jobs`, through the write-back gate as `ci_rerun`) and sends no fix kick while that re-run is owed. A head still red after the re-run goes back to the normal fix loop. The fix kick now tells the agent to stamp the marker and never push to retrigger CI, and the reviewer lane's DE-ESCALATE verdict no longer asks for a push when the branch is already current.
