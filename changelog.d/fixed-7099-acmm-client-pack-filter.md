- The dashboard no longer hides a running, enabled agent that the API deliberately surfaces ([#7099](https://github.com/hivecommons/hive/issues/7099)). The ACMM pack-roster filter was applied twice — once server-side in `buildAgentsWithHidden`, which honours the documented "active outside pack" exception (a custom agent, or one explicitly enabled in YAML, legitimately runs beside the level's default roster), and again in the browser's `applyACMMVisibility`, which re-derived the same set membership with **no** escape hatch. The client re-hid the agent on every status render — its sidebar entry **and** its card, so the terminal link, Login button, restart and config gear were all unreachable. Observed live at ACMM L5 with a custom agent `review`: `/api/status.agents` returned 7 agents, the UI rendered 6, and the watchdog was simultaneously raising `watchdog-auth-review` ("needs re-authentication") — the dashboard was hiding the exact controls needed to clear the alert it was showing. Because the suppression happened client-side, `hiddenAgents` stayed empty, reopening the diagnostic gap #6581/#6652 closed. The redundant client filter is removed: `status.agents` — already gated server-side with the exception — is authoritative, so the two filters can no longer disagree.
