- The Governor cadence-matrix tooltip and the agent card no longer disagree about when an interval agent is next kicked ([#7109](https://github.com/hivecommons/hive/issues/7109)). The card anchored an interval cadence's "next" on the agent's `LastKick` (`lastKick + interval`) while the tooltip called `NextAfter(time.Now())` and never consulted `LastKick`, so the tooltip rendered `now + interval` — wrong by exactly the time already elapsed since the last kick, at its most misleading in the final minute before a kick fires (a `1h` scanner read at 3:37 PM showed `next: 4:37 PM` when the card correctly showed `3:38 PM`). Rather than copy the three-line anchoring rule into `cadenceTooltip` — which would just re-introduce the same dual-source drift — the tooltip now calls the card's existing `computeNextKickFromCadence(lastKick, cadence)` helper directly and only prepends the `HumanSummary() + " — next: "` label, so the two surfaces cannot diverge by construction. `LastKick` and the governor's active mode are threaded through from `buildCadenceMatrix`. Cron cadences are unaffected: both paths already pass `time.Now()` into `schedule.Next`. The cadence matrix shows a cell per mode (idle/quiet/busy/surge), but only the **active** mode's cell has a real "next" — for the others `lastKick + thatInterval` is a kick that never happens while the mode is inactive — so only the active cell now renders `next:`; the non-active cells show the human summary alone instead of three future times that will never occur.
