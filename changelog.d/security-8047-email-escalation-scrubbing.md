- Email escalations now pass every operator-visible field through the shared secret/canary scrubber at the surface boundary, instead of relying on each caller to remember to scrub first ([#8047](https://github.com/hivecommons/hive/issues/8047)). A GitHub token, JWT, AWS key, private key, or `ioscan` canary that reached an escalation body used to be mailed out intact for any caller that dispatched unscrubbed text — the three call sites in `cmd/hive` scrubbed, and nothing made that a property of the surface. The digest path made the window longer still: `info` and `decision` events sat unscrubbed in the digest buffer until the configured send time, up to a day later. Scrubbing now happens on the way into `Deliver` (so the buffer holds scrubbed text) and again where every immediate and digest mail is composed. The `From`/`To` addressing and the provenance footer are untouched: they are operator configuration, not event text. A v6 guard-invariant conformance suite (`src/pkg/escalate/conformance_v6_email_test.go`) pins this across the whole SMTP session — envelope, headers, and body — and fails if the email surface grows the pieces of an inbound reply-to-act path (a mail-reading dependency, a poller or reply entry point, inbound `EmailConfig` fields, or a locally-invented sender allowlist) without the `ioscan`, `Converse`, role-floor, and mode-ladder guards that path requires.
