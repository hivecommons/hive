- Hold-gated agents are now told, before they choose work, that they cannot push a change to `.github/workflows/**` ([#6681](https://github.com/hivecommons/hive/issues/6681)). An `ISSUES_AND_PRS` agent mints its token at the `contributor` tier, which does not carry the Workflows permission, so GitHub rejects such a push server-side — and when the agent is sandboxed the push broker rejects it first. Nothing said so: an agent that found a security fix belonging in a workflow file wrote the exact replacement into an issue and opened no PR, which is the only outcome available to it but is indistinguishable, to the operator, from an agent that chose not to fix it. The kick now states the ceiling and what to do instead, and the `ci-maintainer` and `sec-check` hold-gated policies no longer advertise workflow edits that mode cannot land — `ci-maintainer-holdgated.md` listed `.github/workflows/*.yml` changes as its first capability.
