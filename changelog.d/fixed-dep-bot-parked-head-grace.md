- **A parked dependency-bot PR's newer red head no longer waits the red-CI grace over and over.** With `auto_merge.dependency_bot_red_issue` on, a newer red head of a PR still parked by the sweep's own red-CI hand-off waits 4 hours before the repository issue check. That wait counted only from the hive's own first sighting of the head, a clock dropped on any pass that did not wait, so after a hive upgrade reopened the head for newer rules, or after any one pass that skipped the PR, a head whose required check had been red for days waited another 4 hours, silently, and could restart again. The wait now starts at the earlier of that first sighting and the latest time the head's failing checks last failed, read from the check runs the sweep already has (no new GitHub calls). The earlier time counts only once the first sighting is 30 minutes old, so a head first seen already red still gives the transient triage and the hive's re-run time to land, and a check failing again later never lengthens the wait. The wait is logged as `dependency-bot red CI: parked head waiting before the repository issue check` with `why` (`grace` or `transient-rerun`) and `remaining`, once, and again whenever its head, reason or start changes.
