- The dashboard metrics collector now caches its GitHub Search-API count queries (hive-attributed merged PRs / closed issues per repo, outreach PR counts) for `HIVE_FORGE_COUNT_CACHE_TTL` (default `20m`) instead of re-asking on every collect, serves the last-good counts (marked stale) with a 10-minute retry backoff and a rate-limited warning when a refresh fails, and stands down while the GitHub slow-start caution window is engaged. Re-asking every cycle tripped GitHub's secondary rate limit on the hosted hive (2026-10-21) and darkened the automerge sweeps and advisory lookups behind it. Follow-up to the faster eval cycles from #13319.
- `EnumerateActionable` no longer publishes a repo as empty when GitHub refuses its fetch transiently (secondary/primary rate limit, 429, 5xx, pre-emptive refusal): the repo's last successful enumeration is substituted for up to two hours and listed in `ActionableResult.stale_repos`; the repo card carries `countsStale` and the Overview KPI snapshot is marked incomplete so history skips it. The dashboard previously showed TOTAL OPEN ISSUES 0 and a one-row activity monitor during such a refusal while the repo had 19 open issues. Webhook per-row tracker refreshes also skip their GET while the caution window is engaged.
- Webhook, review and continuous-agent wakes no longer re-list every tracked repository: the cadence tick (`eval_interval_webhook_s`, 900s while webhooks are healthy) is the authoritative reconcile pass, each webhook delivery's targeted re-read now upserts/moves/removes that one item in the governor's cached actionable snapshot (not just the activity-monitor row, so newly opened items no longer wait for a cycle), and wake cycles plan from that cached snapshot (`source=cached`, `/api/status.cachedCycles` / `webhookPatches`). A reconcile pass that fails outright keeps the previous snapshot published and marked stale instead of dropping to zero.
- The webhook patch path treats the delivery as a hint and re-reads the item before upserting, applies upserts monotonically by `updated_at` (recording the `X-GitHub-Delivery` id, fetch time and head SHA in `item_patches` for audit), removes closed/merged items and re-adds reopened ones after the confirming GET, and bounds irreversible actions: `CloseIssue`/`MergePR` planned from a snapshot refuse while the repo is stale and re-read an item older than 60s first. A reconcile that fails outright (or a cold start whose GitHub share failed) publishes the last-good figures with `staleSince` / `countsStaleSince` and an Overview "stale · as of" badge instead of zeros.
- The slow-start pacer now prioritises by caller: the governor's enumeration runs high priority, periodic housekeeping (automerge sweeps, review-request watcher, advisory lookups, metrics/fleet-stats collectors) is shed instead of queued when the caution-window queue is deeper than it could wait, the self-authored automerge sweep backs off to a 60s floor while cautious, and GitHub App installation-token mints bypass the pacer entirely — so a secondary-limit 403 no longer starves the eval cycle and token refresh behind housekeeping (`slot would miss request deadline`).
