- The backend support-tier document (`src/docs/backend-support-tiers.md`) is now the acceptance bar for adding a CLI backend rather than a planning draft ([#6231](https://github.com/hivecommons/hive/issues/6231)). It names the three tiers (core/headless-pod, supported/confined, experimental/unconfined) and, for each criterion a backend PR must meet, the exact file or test to touch: `KNOWN_BACKENDS`/`CLIBackends` parity, the declared posture in the local-mode matrix test, the flag-honoring transcript, `detect_cli`, pinned image installs, the #4918 refusal gate, the sandbox or deny-list floor, the relay's `HEADLESS_BACKENDS` entry, the `contribute-k8s` credential preflight, and the three headless allowlists. The next third-party backend PR can cite the criterion instead of reconstructing the policy, as #6222 had to.
