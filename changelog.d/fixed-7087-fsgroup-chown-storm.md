- Kubernetes deployments no longer flood the log with `permissions watcher: chown failed` ([#7087](https://github.com/hivecommons/hive/issues/7087)). The standalone Deployment sets `fsGroup: 1002` so the projected GitHub App PEMs are readable by `dev`, but `fsGroupChangePolicy` defaulted to `Always`, which made kubelet recursively re-group the entire `/data` PVC on every mount. The permissions watcher wants those trees in `node` (GID 1000) and runs as uid 1001 without `CAP_CHOWN` after the entrypoint's privilege drop, so it could not undo the re-group; it retried every 10 seconds and warned once per path. On a pod with a single ~27k-path agent checkout that measured roughly 1,300 WARN lines per second — about 58 GB of log volume per day, and a four-figure monthly Log Analytics bill for one operator before they noticed. The Deployment now ships `fsGroupChangePolicy: OnRootMismatch`, so kubelet only re-groups when the volume root is actually wrong, and `fsGroup: 1002` (and with it the CWE-732/522 split that keeps agent UIDs away from the org App key) is unchanged.
- The permissions watcher's warning deduper is no longer defeated by large unrepairable trees ([#7087](https://github.com/hivecommons/hive/issues/7087)). It kept one entry per failing path and, on reaching its 4096-key cap, discarded the whole map — so any tree bigger than the cap reset it on every tick and re-warned about every path forever, which is precisely the case the deduper was added for. Past the cap it now degrades to one warning per (operation, errno) class instead of forgetting what it already knows, keeping an unfixable tree of any size down to a handful of WARN lines. The class is keyed on the errno rather than the error text because the text embeds the offending path and would otherwise mint one class per path.
