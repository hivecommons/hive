- `hivectl hives` saves the hives you lend a CLI to as **named profiles**, so switching between them no longer means hand-editing `~/.config/hive/contributor.env` or re-running `contribute-setup` ([#8097](https://github.com/hivecommons/hive/issues/8097)). `hivectl hives list` shows every hive with its contributor id and an active marker (`--check` also probes each hub); `add`, `use`, `rename` and `remove` manage the set. Profiles live in `~/.config/hive/profiles.yml` (mode 0600) and `contributor.env` becomes a generated projection of them, with the active hive first in the `HIVE_HUB` / `HIVE_REGISTRATION_TOKEN` / `CONTRIBUTOR_ID` lists — the hub the relay solicits from at startup. The relay, Compose and `contribute-k8s` read exactly the variables they always have. The first `hives` command on a machine with the old positional file migrates it, naming entries after their hub host and keeping the first hub active so a running relay is unaffected; a file whose three lists disagree in length is refused rather than guessed at, because pairing a token with the wrong hub points a live credential at the wrong hive. Registration tokens are never printed in any output format, and `remove` requires you to type the hive name because the hub cannot reprint the token it discards. Switching a *running* relay without a restart, `export`/`import`, and the TUI pane are the later phases of the same issue.
