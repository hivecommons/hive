- `hive-open-issue` (the `gh issue create`/`comment` relay every agent's `gh` is redirected through) now honours `--dry-run` and refuses flags it does not understand instead of silently dropping them ([#7400](https://github.com/hivecommons/hive/issues/7400)). Its parser swallowed any unrecognised flag on the way to writing the request, so a scanner probing its access with `gh issue create --dry-run` filed a real issue whose body was `placeholder` (#7393) — and, because the agent's scoped token can create issues but not edit or comment on them, could not retract it. `--dry-run` / `-n` on every shape (`issue`, `comment`, `claim`, `close`) now validates the arguments, prints the exact request JSON that would have been queued, and exits `0` without writing anything; any other unknown flag exits `2` with an `unsupported flag: …` error naming it and confirming nothing was created. The documented gh no-op flags (`--assignee`, `--milestone`, `--project`, `--template`, `--web`, `--editor`) stay accepted and ignored. To retract an issue filed by mistake, `hive-open-issue close --repo <owner/repo> <number>` goes through the watcher with the App token and needs no edit scope.
