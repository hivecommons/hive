- Fixed abandoned tmux clients permanently disabling every keyboard-based self-heal for an agent. `SessionAttached` exists so hive never types into a session an operator is using, but it asked tmux only how many clients were attached — and a client that dies without detaching (an SSH drop, a closed `kubectl exec`, a browser tab shut on a terminal view) stays attached forever. On a hosted spoke two such clients sat on the scanner session with `client_activity` frozen at `client_created` and no process owning either pty; scanner then hit a transient model error, dropped to an idle prompt, and sat there for 13.5 hours because the retry nudge kept vetoing itself on a terminal nobody was looking at. Attachment is now judged by client activity, so clients silent past a 30-minute grace no longer block healing. Every uncertainty still fails open, an active client still blocks, and a single active client among abandoned ones still blocks.
