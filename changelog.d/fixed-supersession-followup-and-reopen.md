- Supersession sweep: a pull request opened after the merged pull request landed, and whose own title or body names that merged pull request, is no longer treated as superseded by it. Such a pull request was written knowing the issue was already closed: it reverts, extends or finishes the merged change. Before, wording about the closed issue could read as the pull request's own claim (a body saying `the pin PR is #300 (it closed issue #299)` parses as a closing claim on that issue), the merged pull request resolved as the closer, and a hive-authored follow-up that touched the same files was labelled `hive/superseded` and closed minutes after it opened. A pull request opened before the merge, or one opened after it that does not name the merged pull request, is superseded as before. The dashboard's close-superseded decision and the pre-review and close-on-merge auto-close read the same answer.
- Supersession sweep: an open pull request that still wears `hive/superseded` but that the sweep no longer finds superseded (it was reopened with its body corrected, or its issue was reopened) now loses the label, and the sweep's notice is rewritten in place to say the pull request is open again and not superseded. The audit log records `supersession-sweep-cleared-superseded`. Before, a reopened pull request kept the label and the "Closing this hive-authored PR" notice until it merged. Only a label next to the sweep's own notice is removed; a held pull request, a paused repository and a contributor's pull request the write-back gate refuses keep it.
