- A contributor-lane pull request whose required check GitHub still shows unfinished after its Actions job finished now reaches a person. When the contributor lane refuses the merge relay on a confirmed `ci-reporting-stalled` observation ([#15941](https://github.com/hivecommons/hive/pull/15941): past the propagation grace, on the head the verdict judged), the merge verdict now carries that observation as `ci_reporting_stall`, and the your-turn decision holds the PR for a person (`ci_reporting_stalled`, verb `REVIEW`). The Overview card shows it under Needs a person on the Other reason row, `prs_by_band` returns it with `your_turn: true`, and the Activity monitor lists it in Waiting on you (`needs_human_why.source: ci-reporting-stalled`) with the whole instruction on the row. The reason names the check, the run and the attempt, links the run, and gives the `gh run rerun <run> --job <job> -R <owner/repo>` command. The decision reads only that structured observation, never reason text, so a check name a contributor chose cannot fake the row. Hive-authored, trusted-bot and trusted-author PRs do not take this path, so they get no row, and a PR that already had a your-turn decision (a hand merge where auto-merge is off, for example) keeps it. Before this, #15941 showed the owner ask only in the reason tooltip, so such a PR sat under "Agents are working it" until someone opened it. This is display only: the stage stays CI-pending, every gate and the merge bucket, state and reason are unchanged, the hive re-runs nothing, and `ci-reporting-unverified` or a mismatch still inside the grace adds no row. The row clears by itself once a verdict no longer reports the stall (a new attempt, a new head, or the check finishing).
