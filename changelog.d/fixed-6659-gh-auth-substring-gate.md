- A contributor agent can again open a PR whose body mentions authentication ([#6659](https://github.com/hivecommons/hive/issues/6659)). `bin/gh-wrapper.sh`'s contributor-mode `gh auth` gate matched the substring `auth ` anywhere in the flattened argument string rather than the subcommand, so any `gh` call whose arguments merely *mentioned* authentication was refused — PR bodies, issue titles, commit messages. The trailing space was load-bearing in the worst way: `authfile` passed, `auth file` did not. The reported failure is the shape that matters: a codex contributor finished a `[sec-check]` task about keeping a registry token out of skopeo's argv — the fix replaces `--creds` with an auth *file* — and could not open the PR, because the body said "auth file". Security fixes are exactly the PRs whose bodies discuss authentication, so this systematically killed the last step of the tasks it could least afford to lose: work done, tested, committed and pushed, the slot held, nothing landed. The gate now keys on the parsed `$subcmd` (the same flag-aware parser the merge and mode gates use), so it is exactly as strict as intended and not one argument wider; every `gh auth` form stays blocked, including behind a value-taking flag. `bin/test_gh_wrapper_gates.sh` also now runs against a marker-redirected copy of the wrapper, so it no longer mis-reports eight unrelated cases when run inside a contributor container, where `/etc/hive/contributor-mode` exists and silently turned every "staff agent" case into a contributor one.
