- `auto_merge.dependency_bot_red_issue` now files in the ordinary cases it used to refuse, without trusting a check name or a job log. Another open PR failing a check of the same name no longer blocks the issue by name alone, because a catch-all check that runs a whole test suite is red on unrelated PRs for unrelated reasons. The other PR counts as a shared cause when both PRs run without the repository's secrets (a fork's PR, a Dependabot PR), whatever their messages say, or when both carry the same failure-level annotation message, ignoring warnings, generic lines such as "exit status 1", and PR-specific numbers, hex ids and UUIDs. With no message on one side, the filer compares the two failed jobs' logs at filing time, for at most 2 other PRs and within 60 seconds, using the last error lines of each log in memory only: the same error line, no error line on one side or both, or a log it cannot read or that broke off means no issue. A failed shell step that leaves only "Process completed with exit code N" no longer refuses the issue either. The issue quotes failure annotations only, masked before they are cut, and never a job's log. For such a job it names the job and its failed steps and points at the job's log, and for a Dependabot or fork PR it names a missing secret as a possible cause. The base proof now needs a base run that started after the failure when the head is behind the base tip; a head that contains the tip keeps the finished-after rule. An open issue that a member other than the PR's author filed about the PR since it opened, naming it, is named in the hand-off instead of filing a second one, until that issue closes with the PR still red. Heads refused under the old rules are judged once more after the upgrade.
