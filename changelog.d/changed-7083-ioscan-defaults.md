- `ioscan` hardening defaults changed for hives that never set them explicitly ([#7083](https://github.com/hivecommons/hive/issues/7083)). **`ioscan.canaries` now defaults ON** (was off): per-kick exfiltration canaries are planted and outbound bodies scanned by default, because `CanaryRegistry.Scan` is now encoding-aware and decodes base64/hex/URL/reversed/split spellings before matching ([#6701](https://github.com/hivecommons/hive/issues/6701), [#6720](https://github.com/hivecommons/hive/issues/6720)) — the asymmetry that justified the old default ([#6686](https://github.com/hivecommons/hive/issues/6686)) is fixed. **`ioscan.fail_mode` now defaults to `closed` at ACMM L5 and L6** (the levels where agents can merge), via the L5/L6 packs; L1–L4 stay `open`. Under `closed`, a Critical injection finding **blocks the kick** and records `ioscan_fail_closed` instead of redacting the offending text and continuing. Operators upgrading an L5/L6 hive will see Critical findings stall the affected queue item until a human intervenes — every Critical false-positive becomes an operator task — so both defaults remain fully overridable per hive (`ioscan.canaries: false`, `ioscan.fail_mode: open`).
