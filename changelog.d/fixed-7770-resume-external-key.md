- A contributor that reconnects while working a Linear or Jira item no longer loses that item's identity on the hub: the resumed task now carries the lease's canonical key, so the item stays in the double-assignment guard instead of being offered to a second contributor, and completing or failing it books its cooldown against the real key rather than against nothing. The reconnect-window hedge is booked for external items too, as it always was for GitHub issues ([#7770](https://github.com/hivecommons/hive/issues/7770)).
