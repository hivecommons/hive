- Blocked sweep: a hold now follows a dependency that was replaced instead of being released when the original closes. Two cases. (1) A pull request held on `Depends-on: #A`: when #A closed without merging and was superseded by a pull request that is still open (a maintainer re-did a contributor's PR on another branch), the dependent PR used to lose `blocked` and could merge before its real prerequisite, until a person noticed and edited the `Depends-on:` line. It now stays `blocked` on the successor: the sweep posts one comment with the successor's `<!-- hive:blocked-on pr=owner/repo#B -->` marker and a `<!-- hive:depends-on-successor pr=… replaces=… -->` marker, never edits the PR body, and lifts the hold when the successor merges or closes, with a note that names both. (2) An issue blocked on another issue (`<!-- hive:blocked-on issue=… -->`): when that issue is closed as a duplicate of an open issue (also in another repository), or replaced by one, the block moves to the open issue with one `Re-targeted:` comment instead of lifting. For these two paths a "Superseded by #N" line counts only from the closed item's own body, the hive, the closed item's author, or a commenter whose association is `OWNER`, `MEMBER` or `COLLABORATOR`; GitHub's own duplicate closure is trusted as it is. Anyone else's line is ignored and the hold is released as before. The existing path, an issue blocked on a pull request, is unchanged and still accepts the line from any commenter. Limits: only a successor already declared when the sweep sees the blocker closed is followed; a chain is followed for at most three replacements; a merged dependency, and a closed one with no open successor, release exactly as before. No new setting; the new comments go through the write-back gate as `gate_comment`.
