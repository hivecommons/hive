- A dependency-bot PR from `auto_merge.trusted_bot_authors` that an agent triaged as a transient CI failure (`hive-ci-transient` markers on every failing run) now gets the same one re-run of its head that a hive PR gets, instead of going straight to a person. The re-run is write-back kind `ci_rerun`, which on a bot PR needs the opt-in label unless `writeback.kinds.ci_rerun.unlabeled_min_level` is set. The red-CI hand-off waits while that re-run is owed or running, and then says what happened: the re-run failed again, or it was not allowed (with the write-back gate's reason), so a refused re-run still reaches a person. The stranded-branch sweep also stops commenting `@dependabot recreate` as the hive's App, because Dependabot answers every command from a GitHub App with "only users with push access can use that command" ([dependabot/dependabot-core#9147](https://github.com/dependabot/dependabot-core/issues/9147)). A stranded Dependabot PR now goes to a person at once, and the comment asks someone with push access to post the command. Renovate PRs still get their rebase/retry box ticked first.
