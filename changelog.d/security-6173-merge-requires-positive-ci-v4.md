- The merge-request watcher no longer merges a PR without independently verifying CI, and absent check runs are no longer treated as passing ([#6173](https://github.com/hivecommons/hive/issues/6173)). `handleOneMergeRequest` used to call `MergePR` unconditionally and relied on GitHub's branch protection to refuse a red PR; on a base branch with no protection rules nothing refused it, and a fork PR whose four workflows had all died at startup with zero jobs (so zero check runs and an empty status rollup) was merged 13 minutes after opening. The watcher now requires positive confirmation on the pinned head SHA before any merge: at least one commit status or check run exists, every gating one concluded success (`neutral`/`skipped` accepted, the existing non-required ignore list and `auto_merge.required_checks` set still apply), every config-declared required check has actually reported, and no workflow run on the SHA failed without producing a job. Zero evidence is refused as unverified; queued/in-progress CI parks the request (`ci_waits` in the result file, no retry consumed) for up to one hour; a red verdict is a failed attempt that re-engages the fix loop exactly like a branch-protection refusal; an API error while gathering evidence is a failed attempt, never a pass. The self-merge sweep's `commitGreen` is unchanged in behavior and now shares its evaluation core with the gate. This is the v4 port of [#6279](https://github.com/hivecommons/hive/pull/6279).
