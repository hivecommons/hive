- Activity monitor row actions now show progress and never fail silently (hivecommons/hive#15436). **Close (read)** on an advisory row did nothing — an advisory is not a decision park, so the `decide:*` target mapping came up empty and the click returned without a request, a dialog or a toast. It now acts on the advisory row itself and really closes the issue (acknowledgement comment, closed as completed); an empty target list toasts a warning instead of returning silently. Every mutating row action (close-read, close-superseded, won't-fix, hold, approve, merge, decide) puts the chevron into the striped busy state with the verb as caption from the first byte sent, shows *Closed · leaving list* / *Merged · leaving list* once the server answers, and the server drops an operator-closed item from the tracker for `HIVE_OPERATOR_CLOSED_GRACE` (default 15m) so the row cannot come back before GitHub's list catches up. A close on an operator-paused repo is refused with the reason and writes nothing; refused, failed and network-errored actions restore the chevron, toast the reason and put it on the row's history badge (red, hover's first line), and the ledger records refused answers as `failed` with the one-line why.
