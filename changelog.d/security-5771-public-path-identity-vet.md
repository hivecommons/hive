- **Forged identity headers no longer trusted on public dashboard paths** (#5771). `authenticate` dispatched every `isPublicPath` route before its identity-header strip and the F2 `X-Hive-Proxy-Auth` proof check, so public handlers that read `X-Hive-User` / `X-Hive-Role` as hub-injected identity received the client's raw headers. An anonymous caller reaching the dashboard port directly (OpenShift Route, in-cluster) could forge `X-Hive-Role: owner` and park, un-park, or reorder the entire ready-work queue via the public `/api/contribute/queue/*` controls (persisted to `hive.yaml`), mint attributed invite links as a trusted contributor, or overwrite another contributor's interests/dossier. Public paths now run the same proxy-proof trust decision (`vetPublicPathIdentity`) as authenticated routes: identity survives only with a valid hub proof (or the legacy no-proof rollout window, never owner-verified), and direct-route spokes never trust hub headers. Hub-proxied and local-gateway deployments are unaffected.
