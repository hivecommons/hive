- Standalone deployments (Docker Compose, Podman Quadlet, LXC): the hive's two MCP endpoints now work through the bundled gateway on port 3001. The dashboard auth proxy answered `401 Unauthorized` to the task MCP (`POST /api/contribute/mcp`) before the hive could check the caller's own credential, so hub-launched agents and remote contributors could not use it whenever their task MCP URL went through the gateway (`dashboard.public_url` or a hub-assigned dashboard URL). It also answered 401 to anonymous calls to the public knowledge MCP (`POST /mcp/knowledge`) and had no route for that path at all, so the endpoint was unreachable even after the owner switched it on. The proxy now forwards exactly these two paths to the hive: the hive still verifies the task MCP caller's launch token or lease, and still serves public knowledge only while the owner's switch is on. A request let through this way gets no gateway credential (`X-Hive-Internal`), other methods on `/mcp/knowledge` are answered `405`, and every other unauthenticated write is refused as before. Kubernetes deployments and the default `http://localhost:3002` task MCP URL were not affected.
