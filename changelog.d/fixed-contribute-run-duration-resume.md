- Contributor run records now keep their `duration_s` when the relay's connection drops and the task is resumed, including across a hub restart. A resumed task runs on a new connection that never saw the assignment, so the hub had no start time and booked the run with no duration; the runs view then showed nothing or `0s`. On projectbluefin on 2026-11-09, a task held across the 16:46Z restart failed at 17:16Z after about two and a half hours with no duration, and a task whose socket flapped two minutes in shipped about 14 minutes later with none either. The task lease now stores the original assignment time (`assigned_at` in `task-leases.json`, optional, so older registries still load), and the run log measures from it. When the start is unknown, for a lease written before this change, the field is left off rather than guessed, and a duration that would be negative or longer than seven days is never written. Only the run record and its audit row change: the fast-failure streak and other readers of the assignment time behave as before.
