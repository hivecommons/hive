- A task that was revoked or aborted mid-edit no longer leaves its half-done changes for every later task on that repo to start from ([#7790](https://github.com/hivecommons/hive/issues/7790)). The contributor relay works every task on a repo out of one persistent checkout under `$HIVE_WORKSPACE_DIR`, and stopping an interrupted agent never touched the tree: on projectbluefin/utah one revoked task left three modified files on its branch and the next four tasks all began from them, one `git add -A` away from shipping another task's work under this contributor's name. The relay now sweeps the task's checkout on every exit — completion, failure, revoke, shutdown — after the agent is stopped, setting aside anything uncommitted (untracked files included) with `git stash push --include-untracked -m "hive leftover <task_id> …"`, never resetting or cleaning, so an operator can recover the work from `git stash list`; it only ever touches a directory it can prove is the task's checkout, and never the relay's own cwd. The assignment prompt now also tells the agent to run `git status` before branching, stash rather than discard or commit anything it did not write, confirm the tree is clean, and prefer `git worktree add` — the half that covers a contributor whose relay never sees the checkout.
