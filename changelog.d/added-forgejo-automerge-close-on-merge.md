- **Forgejo repos get automerge and close-on-merge** ([#19671](https://github.com/hivecommons/hive/issues/19671)). The GitHub sweeps still skip every non-GitHub repo; a Forgejo repo now has its own sweeps, run every two minutes and with no GitHub client needed. Automerge merges an open, non-draft pull request through Forgejo's merge API, pinned to the head it judged (`head_commit_id`), only when auto-merge is on for the repo (off below ACMM L6, as on GitHub), it carries `governor.labels.automerge` (default `lgtm`) last added by someone other than its author who has write access, it carries no `hold`, sentinel, decision-needed or exempt label, Forgejo reports it mergeable, and the combined commit status at the head is `success` with at least one status. Close-on-merge relies on Forgejo closing the issues a pull request names with a closing keyword when it merges into the default branch, and closes, with a marked comment, the ones still open two minutes to seven days after a merge by the hive's own Forgejo user or a writer (for example a merge into another branch). It honours `hive: needs-confirmation` and `issues.close_on_merge`, and never closes again an issue a person reopened. GitLab and Gitea repos still get neither sweep.
