- ioscan's hidden-markup and data-carrying-URL rules no longer flag ordinary content ([#19452](https://github.com/hivecommons/hive/issues/19452)). Fill-in markers are matched against decoded query values, so bracketed parameter names such as `filter[key]=1` and words such as `yourself` or `insertion` no longer count, while placeholders such as `YOUR_TOKEN` or `{{secrets}}` still do; keys are checked for the unambiguous forms only (`{{secrets.TOKEN}}=1`, `<your_data>=1`, `YOUR_API_KEY=1`). A signed AWS, GCS, CloudFront or Azure SAS image URL whose only long values are its signing parameters is now reported as a Medium `dangerous.exfil_image_url` instead of High. This applies only when the URL is on the provider's own host, carries a well-formed signature, and each signing parameter has its scheme's exact shape and appears once. Medium does not block agent output, but untrusted input still blocks at the default Medium line, because anyone can own a bucket or distribution on these hosts and read its access logs. Free-data parameters such as `X-Amz-Security-Token` or CloudFront `Policy`, and any other data in the URL, still give High. A `jwt` value is fully exempt, but only on GitHub's private-user-images host. A Medium phrase inside a `<details>` section stays Medium; only HTML comments and CSS-hidden elements still raise it to a blocking High.
