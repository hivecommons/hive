- ioscan's hidden-markup and data-carrying-URL rules no longer flag ordinary content ([#19452](https://github.com/hivecommons/hive/issues/19452)). Fill-in markers are matched against decoded query values only, so bracketed parameter names such as `filter[key]=1` and words such as `yourself` or `insertion` no longer count, while placeholders such as `YOUR_TOKEN` or `{{secrets}}` still do. Long values of AWS, GCS, CloudFront and Azure SAS signed image URLs are no longer read as exfiltrated data when the URL carries a well-formed signature and each exempt parameter has its scheme's exact shape; free-data parameters such as `X-Amz-Security-Token` or CloudFront `Policy` still count. A `jwt` value is exempt only on GitHub's private-user-images host. A Medium phrase inside a `<details>` section stays Medium; only HTML comments and CSS-hidden elements still raise it to a blocking High.
