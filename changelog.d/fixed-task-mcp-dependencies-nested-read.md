- Task MCP: the `dependencies` tool (and `context_bundle` when it includes `dependencies`) can no longer deadlock a bead store. For a task whose issue has a planned epic, it looked the epic's children up from inside a read of that same store. The store's lock is not reentrant, so if anything wrote a bead between the two reads (a claim, a status change, the planner creating children), the inner read waited for the writer and the writer waited for the outer read. From then on every read and write of that agent's bead store blocked until the hive restarted, and the contributor admission gate, which reads every bead store on each pass, hung with it. The children are now found in the single pass that already walks the store. A child created before its epic is also no longer listed twice in `suggested_plan`.
