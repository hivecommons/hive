- Superseded hive PRs no longer park on a person. A **hive-authored** PR whose closing targets are all closed, one of them by a different merged PR, and whose head conflicts with the base (or whose files that PR already covers) is closed by the hive itself as `hive/superseded` with a notice naming the superseding PR — in the self-authored auto-merge lane before any review is dispatched, in the supersession sweep when GitHub refuses the rebase for a conflict, and in close-on-merge of the superseding PR — under the new `governor.auto_close_superseded` knob (default on; human-authored PRs are never auto-closed). A contributor PR adopted in supersede mode (stage 074) now leaves `stage/085-needs-decision` in the adopting pass when the park was only the review swarm's `requires_human`: the original renders in the CI/Review column with an "Adopted → #N" pill instead of "Needs human decision", and the duplicate-fix sweep no longer closes the superseding App PR as a duplicate of the PR it supersedes. Evidence: #14965 (closed by #14957 for #14952, parked >1h), #14975 → #14980, #14947 → #14977.
