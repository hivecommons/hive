- Settings → Hub no longer shows `DASHBOARD URL` as an editable setting on a hub-managed spoke ([#7451](https://github.com/hivecommons/hive/issues/7451)). `hub.dashboard_url` is owned by the hub: the heartbeat's project-config push adopts the hub's value whenever it differs and persists it (both the URL-only push and the full project reconcile in `cmd/hive/main.go`), so an operator's edit was reverted on the next beat — and before it was reverted it was not inert, because that field is the second-choice source for the OAuth callback origin after `dashboard.public_url`, so a typo could redirect the authorization code to a host that is not this server and lock the operator out of the dashboard they were editing from. It also feeds the hub's webhook target and Discord message links. The field is now rendered read-only while `hub.enabled` is true, with the same provenance wording the auto-update block uses ("Policy source: the hub (heartbeat)") and a pointer to `dashboard.public_url`, which is the local override that actually wins for OAuth and is never overwritten by the heartbeat. `PUT /api/config/governor/hub` enforces the same rule server-side — a differing `dashboard_url` is rejected with `409` while the hub is enabled, an unchanged resubmit of the whole form is a no-op — so the read-only input cannot simply be bypassed with `curl`. An unmanaged spoke (`hub.enabled == false`) keeps the editable field, since nothing overwrites it there.
