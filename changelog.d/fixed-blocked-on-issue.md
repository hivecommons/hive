- **Blocked on an issue, not only a PR.** The blocked-on marker now has an issue form, `<!-- hive:blocked-on issue=owner/repo#N -->`, read from the issue body or its newest marker comment: the blocked sweep keeps `blocked` while that issue is open (stripping only `help wanted`), lifts it with one `<!-- hive:unblocked -->` note once it closes, and never lifts it as marker-less; a malformed issue marker counts as no marker and PR markers behave as before. The contributor prompt asks an agent that prints `blocked` on a GitHub issue to put that marker on its comment. Before, a hive-applied `blocked` for an issue dependency was lifted as marker-less, so projectbluefin/utah#10 and #855 went back to triage and were re-verified "still blocked" again and again.
