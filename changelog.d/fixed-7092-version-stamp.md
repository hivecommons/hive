- Hive builds now report a real minor/patch version instead of the static `0.0.0-dev` in `hive --version`, hub heartbeats, and dashboard registration ([#7092](https://github.com/hivecommons/hive/issues/7092)). `src/Dockerfile` and `src/Dockerfile.hub` already accepted a `VERSION` build-arg wired to an `-X main.version` ldflag, but no build path ever fed it, so every image — release and branch alike — self-reported `0.0.0-dev`, and an operator running a hosted spoke saw only the branch (`v4`) with no way to reference a minor or patch level in release notes or support. The Dockerfiles now derive `VERSION` from `git describe --tags --always --dirty` against the `.git` they copy in whenever the build-arg is unset, so an image built at tag `v4.34.0` self-reports `4.34.0` and a branch build a few commits ahead reports `4.34.0-7-g43a51078` (nearest tag + commits-ahead + short commit); `main.go` strips a leading `v` so the reported string stays digit-leading semver. `docker.yml`'s image-build jobs check out with `fetch-depth: 0` so the tag history `git describe` needs is present. The retag-not-rebuild release model is untouched: the version is embedded at the original `docker.yml` build, which is exactly why `tagged-release.yml` can keep shipping the tested digest byte-for-byte instead of rebuilding. A bare local `go build` with no ldflag still falls back to `0.0.0-dev`, never an empty string.
