- The chat spine (dashchat, Slack, Discord, Telegram, Matrix, MS Teams) now authenticates to the local dashboard API with the server-to-server `X-Hive-Internal` header instead of `Authorization: Bearer` ([#9134](https://github.com/hivecommons/hive/issues/9134)). On a standalone or heartbeat-only spoke with an `authorized_users` allowlist (a direct-route spoke) the bearer path is deliberately disabled, so every `!runs`, `!status`, `!kick`, checkpoint fetch and the `/api/events` SSE stream answered 401 and the spine logged `SSE disconnected … SSE status 401` at capped backoff forever; the earlier `chatDashboardToken` fix only helped hub-proxied hives. Wrong-token requests are still refused on both deployment shapes. Command-triggered requests keep their `X-Hive-Chat-Actor` audit attribution (#9125): the dashboard now honors that header on the `X-Hive-Internal` path too, only when no session identity exists and without changing the granted role.
