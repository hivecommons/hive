- A repository can now be paused on its own, quieting one repo without stopping the hive ([#6203](https://github.com/hivecommons/hive/issues/6203)). Until now an operator could stop one *agent* (everywhere) or stop *everything* (the fleet breaker); a release freeze, an incident, or one repo whose CI was red for an unrelated reason therefore cost the whole fleet — or cost the repo its place in `project.repos`, which loses its dashboard card and its ACMM eval, records nothing about who removed it or why, and reads as permanent. Pause is a run-state instead: the repo stays configured, scored and visible, and only agent activity stops. Set it from the new ⏸ button on each REPOSITORIES card, from `POST /api/repos/pause`, or as `project.paused_repos` in config; each pause records who, when and why (#4055's provenance, now for repos) and survives restarts. Enforcement is deterministic rather than a prompt instruction — the MITM proxy answers every agent write to a paused repo with a 403 whatever ACMM mode the agent holds, the `hive-open-pr`, `hive-merge`, `hive-open-issue` and `hive-review` relays refuse agent requests (including issue/PR comments, claim labels and every review event, because the hive's own fulfilment never traverses the proxy), work enumeration yields nothing for the repo so no kick can hand an agent work on it, and the auto-merge sweeps skip it. Reads stay open on purpose, as do the hive's own control-plane calls and anything a human does. Additive: a hive with no paused repos behaves exactly as before.
