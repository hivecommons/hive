- A spoke landing on a node whose kernel lacks the netfilter modules the forced-egress gate needs now says so in one line and exits with the documented preflight code 77, instead of dying at exit 4 on whichever iptables append happened to run first ([#6003](https://github.com/hivecommons/hive/issues/6003)). `entrypoint.sh` probes the `REDIRECT` target and the packet-mark match in a throwaway chain before it builds `HIVE_PROXY`, and a failure names `xt_REDIRECT` / `xt_mark` explicitly and points at the durable fix - a MachineConfig writing an `/etc/modules-load.d/` drop-in so the modules survive a node rebuild. `xt_owner` stays optional, since OpenShift/OVN runs without it. Behaviour for who runs where is unchanged: such a node still refuses to start, because it cannot enforce egress there. What changed is that the operator is told which module to load. The alternative - guarding the appends with `|| true` and continuing - was rejected: it would boot a spoke with a `HIVE_PROXY` chain that redirects nothing, which is the silent-bypass failure that got `bin/setup-proxy-iptables.sh` deleted in #5949. That is not hypothetical: one spoke survived these same failed appends with a half-built chain and went mute for hours - 104 proxy read timeouts, 34 heartbeat collect timeouts, zero successful collections, no git_hash reported - so the hub never upgraded it while it reported healthy.
