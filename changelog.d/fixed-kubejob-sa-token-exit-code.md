- Sandbox Job pods no longer receive the ServiceAccount token and now run with a restrictive security context, and an unreadable completed pod no longer reports a guessed exit code 0 ([#17021](https://github.com/hivecommons/hive/issues/17021), [#17022](https://github.com/hivecommons/hive/issues/17022)). Previously the kubejob manifest left `automountServiceAccountToken` at its default and set no `securityContext`, so a contained run could read the cluster token; it now sets `automountServiceAccountToken: false`, `allowPrivilegeEscalation: false`, drops all capabilities and uses the `RuntimeDefault` seccomp profile. When a Job completes but its pod can no longer be read, the result keeps the unknown exit code (`-1`) instead of claiming 0; the kick log shows `exit_code: unknown` and the PR is not withheld for it.
