- Stop calling a PR merge-eligible while GitHub holds it for a code owner's review. A ruleset `pull_request` rule with `require_code_owner_review: true` and `required_approving_review_count: 0` (or classic protection's `require_code_owner_reviews`) makes GitHub report `reviewDecision: null` on a `blocked` PR, so Hive read it as "required checks green; ignoring non-required GitHub blockers" and the serialized lane cycled such PRs through the front for the full front timeout without ever surfacing them. The protection facts now record the code-owner rule for a blocked PR with no review decision, and `HumanReviewBlocksMerge` reports `code-owner review required by ruleset "<name>"`: the merge verdict skips the PR and the your-turn inbox shows it as a review for a person, as for `REVIEW_REQUIRED` (hivecommons/hive#12953).
