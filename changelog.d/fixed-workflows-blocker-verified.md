- An agent's "the App cannot push `.github/workflows/`" is checked before it parks anything. On projectbluefin/testsuite#1059 and #1073, scanner (ISSUES_PRS_MERGE, whose token asks for the Workflows permission) parked a workflow fix the same day the App pushed `e2e.yml` in #1089, and the issues showed "Blocked · App lacks workflows permission" for four days. Now the relay refuses that park when the parking lane's tier pushes workflows and the App installation grants `workflows: write` (read at most every five minutes), and hands a contributor-tier park to the workflows lane only when the installation is not known to lack the permission. The blocker ledger records a workflows blocker only when no lane can push workflow files on that repository or the item is a fork PR (a fork branch takes no workflow push from the App), and a re-check that runs with the un-park sweep releases existing ones and routes them to the workflows lane. Merger- and trusted-tier kicks now say their token can push `.github/workflows/**`. A park that quotes GitHub's own rejection of the push still stands, and that evidence is kept across later unquoted re-reports; a contributor-tier lane's quote is not treated as evidence about the App.
