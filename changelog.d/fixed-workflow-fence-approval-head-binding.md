- The contributor lane now binds an unmarked owner approval (a typed `/hive decision approve`, or a dashboard `/approve` posted without a head marker) to the time GitHub first showed the PR's current head, never to the head commit's committer date. That date is written by the pusher's git, so a later push carrying a backdated commit could inherit an approval given on the head before it and release the workflow-path fence for a diff the approver never saw. An approval older than the observed head now leaves the fence armed, exactly like an APPROVED review on a stale commit; the approver re-approves the new head to release it. This is deliberately fail-closed and slightly narrower than before: the observed time is pinned on the hive's first sweep of the head, and any comment or label that lands between the push and that sweep moves it later, so an approval typed in that gap is also treated as stale and has to be typed again. A head with no pinned time yet binds nothing.
