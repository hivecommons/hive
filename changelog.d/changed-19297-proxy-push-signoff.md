- The egress proxy now applies the push broker's sign-off rules to in-pod agent pushes: a lane-authored commit without the lane's `Signed-off-by`, or a lane `Signed-off-by` on a commit the lane did not author and commit, is refused with reason `push_signoff` (#19297). A commit is the lane's when its name is the lane and its email is either identity the pod can be given: `<lane>@HIVE_GIT_BOT_EMAIL_DOMAIN`, or on App-authored hives the App bot's `<id>+<login>@users.noreply.github.com` address. This is a best-effort guard against accidental sign-off mistakes, not the enforcement point: a crafted thin delta that starts with a copy op, and commits made through the REST git/commits API or GraphQL `createCommitOnBranch`, are not inspected. GitHub-side DCO remains the enforcement. The guard runs only where the proxy decrypts github.com traffic (`HIVE_PROXY_INJECT_GH_AUTH=true`); elsewhere in-pod pushes are tunneled unread. Forgejo hosts are not checked, and commits GitHub created server-side (committer `noreply@github.com`) are skipped.
