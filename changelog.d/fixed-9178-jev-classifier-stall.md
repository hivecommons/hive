- The optional Jev smart classifier (`classifier.backend: jev`) can no longer stall scheduler sweeps when its provider is down, rate-limiting, or slow ([#9178](https://github.com/hivecommons/hive/issues/9178)). Previously every uncached issue paid the full `classifier.jev.timeout` serially — twice per sweep, once for classification and again for run triage — so a 150-issue queue against an unreachable endpoint delayed kicks by about 10 minutes every eval cycle. Failed issue revisions are now not retried for 5 minutes, 3 consecutive failures open a 5-minute circuit breaker that recovers through a single probe call (logged as `classify: jev: … skipping Jev until …` with only the failure class, never provider response text), and each sweep or manual kick runs classification and run triage under one `max(10s, timeout)` deadline; skipped calls count as `fallback`. The Jev guide now also documents that each request sends the issue's title, full body, labels, author, repository, number, and `updated_at` to the configured provider, including for private repositories.
