- Hive-authored issue provenance now lives in one label family, `origin/<source>`, so operators can tell "where did this come from" apart from `agent/<lane>` ("who works it", a routing signal) and the `stage/*` pipeline labels. Every hive filing path stamps exactly one origin label centrally, in code rather than in a prompt (`pkg/originlabel.With`): `origin/<agent-name>` (e.g. `origin/scanner`, `origin/sec-check`; `origin/agent` only when the filer is unknown) for anything an agent files through the `hive-open-issue` relay, `origin/review` for review-swarm backlog findings (replacing `from-review`), `origin/advisory`, `origin/recommendations`, `origin/selfreport`, `origin/feedback`, `origin/upstream`, `origin/audit` and `origin/dashboard` for the hive's own reports, feedback, upstream-port, audit and dashboard filers. All share one neutral colour (`#8250df`), the ensure-label helper creates or recolours them idempotently, and the label relay refuses agent edits to `origin/*`. A one-time startup reconciler swaps `from-review` → `origin/review` on open items (report at `/data/origin-label-migration.json`, audited as `origin_label_migrated`), and `review.backlog.labels` still accepts `from-review`, mapping it to `origin/review` without double-labelling. Labels that look like provenance but are read as signals (`hive/selfreport`, `hive/advisory`, `hive/<hive-id>`) are deliberately unchanged and documented under "Label axes" in `labels-and-control-signals.md`.
