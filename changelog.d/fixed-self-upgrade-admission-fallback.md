- A spoke whose self-upgrade `PATCH` on its own Deployment is rejected or timed out by a cluster admission webhook (a failing Kyverno webhook on vllm-d blocked every patch) no longer reports the upgrade as **failed** when a plain restart will land it anyway. The patch deadline is raised from 10s to 45s (above the 10s webhook default, so the apiserver can return the real webhook error) and retried once; when the patch still fails and the Deployment tracks a floating tag that the kubelet re-pulls (`imagePullPolicy: Always` or unknown), the spoke exits immediately with a distinct exit code and reports **pending-restart**, so the hub keeps the in-flight latch instead of counting a failed attempt. The hub's stuck-upgrade alert and the orphan-sweep give-up message now carry the spoke's classified cause ("cluster admission webhook (e.g. Kyverno) is rejecting or timing out Deployment patches — a cluster admin must fix or exempt the webhook") instead of the misleading "Deployment tracks a floating tag" guess ([#14385](https://github.com/hivecommons/hive/issues/14385)).
