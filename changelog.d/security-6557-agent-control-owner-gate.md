- **Agent-control API mutations are now owner-gated** (#6557). `POST /api/kick/{agent}`, `/api/switch/{agent}/{backend}`, `/api/model/{agent}/{model}`, `/api/restart/{agent}`, `/api/reset-restarts/{agent}`, `/api/pin/{agent}/{dimension}` and `/api/unpin/{agent}/{dimension}` carried no `requireOwnerRole` check, so the only defense was the global read-only write-gate — any hub-authorized **read-write or merger** user could kick an agent with an arbitrary 10,000-char prompt (typed verbatim into a CLI session that runs shell commands with App-scoped credentials), switch its backend or model, restart it, or clear its crash-loop counter, while the strictly weaker `handleEffortSet` and `handlePause` were owner-only. All seven now require the server-verified owner marker, matching their siblings; internal automation, shared-token operators and hub-verified owner sessions already carry it, so no legitimate caller loses access. A source-invariant regression test (same pattern as the F14 contributor-gate test) pins the gate against silent merge drops.
