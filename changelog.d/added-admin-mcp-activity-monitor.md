- Admin MCP reads and acts on the Activity monitor: `stage_tracker_read` returns the board (stages, what each item waits on, decision options, linked items, blockers) with the monitor's filters and search, `delegated_decision_status` reads a "Let hive decide" job, and the `repository.rescan` and `repository.item_*` write operations are the monitor's row actions (accept triage, needs-human, blocker re-check / hand-off / partial close, Decide answers, Let hive decide) — never the merge answers, and a delegated decision sent through admin MCP never queues an auto-merge. On the HTTP endpoint a confirmed write now runs as the caller the hive verified (session or hub proxy), bound to whoever previewed it, so hub-proxied callers can write and their writes are attributed to them.
