- The repair queue now knows which PRs come from forks ([#7386](https://github.com/hivecommons/hive/issues/7386)). The hive's App token can push only to the base repository, but nothing marked cross-repository PRs, so on the projectbluefin spoke a scanner was handed 107 CI-failing PRs of which 66 had their head in a contributor's fork; it found out by pushing, burned its session on an unreachable queue while 120+ issues sat idle, and the push created a stray `sec-check-dashboard` branch on the base repo under the fork's head-ref name. `fetchPRs` now records each PR's `head_ref`, `head_repo` and `from_fork` (GitHub's `isCrossRepository`, with a deleted fork counting as unpushable), `ci-failing.json` carries them plus an explicit `reachable_action` of `push` or `comment-only`, the `CI_FAILING` work list renders fork PRs in a separate `FORK PRs (review/comment only, you CANNOT push to these)` section with the head repository and an explicit warning never to `git push origin HEAD:<head_ref>`, every actionable-PR list annotates them inline as `[fork: <owner/repo> — comment only, cannot push]`, and the `FIX-BEFORE-NEW` gate never lists a fork PR as the agent's own — previously an unattributed fork PR defaulted to the scanner, so the directive ordered repairs on PRs that could not be repaired.
