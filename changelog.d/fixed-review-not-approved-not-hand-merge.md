- **Dashboard: a PR whose head the hive's review returned for changes is no longer offered as a hand merge in a repo whose auto-merge is off.** The merge verdict read "awaiting review approval" both for a head the review had not judged yet and for one it had asked to change, and the auto-merge-off rule then marked both as "a person merges it", so the your-turn inbox and the Overview card's Merge by hand band asked a person to merge PRs the review asked to change. With `review.require_approval` on, the verdict now carries `review_changes_requested` for a current head whose review verdict is `changes_requested` (and not also held for a person), whichever gate stopped it first, and that head is never a hand merge; when the review gate stopped it, the reason reads `the hive's review did not approve this head (changes requested)`. A head the review has not judged yet, and a `requires_human` or reject head (which reaches a person through the review's own hold, and is a hand merge once that hold is released), keep the hand merge and the `awaiting review approval` reason. In a repo whose auto-merge is on there is no hand merge to drop, so this verdict change only alters the reason text; the two placements below apply in every repo. No merge bucket changes.
- **Dashboard: a person's or a contributor agent's PR with no stage whose head the review returned for changes waits on its author.** The Overview card places it in Author to update the PR (`flags:no_stage:review_changes`) instead of Agents are working it, and on a repo whose auto-merge is off the Activity monitor's new-PR narration names the author as the next mover (`next_mover: author`) instead of the hive.
- **Dashboard: another bot's PR the hive's review asked to change, which the hive will not push fixes to, is your turn.** When the review dispatcher withheld the fix for the PR's current head because another bot owns the branch (`review.bot_authors`; an in-place adoption is not withheld), and that head's review verdict is `changes_requested`, the PR is your turn as `bot_pr_review_changes` ("Hive's review asked for changes on a bot's PR, and the hive will not push fixes to it. The repo's maintainers decide: close it, or wait for the bot's next version.") and sits on the Overview card's Other row, instead of reading as Agents are working it. A sentinel flag, a hold and supersession still come first; a person's answer or a hold release does not take it off the list, since the hive does not carry out an answer on another bot's branch and a release applies only to a `requires_human` or reject hold. An in-place adoption (`stage/074-adopted-by-hive`) or a fix pending for the head means the hive's fixer does push, and the PR is not listed. Withheld-fix records now carry the exclusion code (`excluded`); a record written before reads the same when it cites `review.bot_authors`.
