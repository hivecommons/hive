- The API proxy's per-agent GitHub API hourly cap can now be changed without editing `hive.yaml`, so an operator on a hub-managed spoke can give one agent more room. Settings → Forge App sets the fleet default (`agents.github_api_hourly_cap`: a number, `0` for no cap, blank for the default of 300) next to the agent reserve floor, and each agent's General tab sets its own value (`agents.<name>.github_api_hourly_cap`: a number, `0` for no cap, blank to inherit). The admin MCP gets the same two writes, `agent.github_api_hourly_cap` and `github.agent_api_hourly_cap`, whose preview discloses a raised or removed cap as widening. A save applies to the proxy at once, is saved to the dashboard overlay and audited; replicas and review heads follow their base agent, and the agent reserve floor still applies. Debug → GitHub API budget now lists each agent's cap and its calls in the current hour, and `config_effective_read` shows both values and each agent's effective cap. See [Changing the agent caps](src/docs/operator-reference/runtime-and-quota.md#changing-the-agent-caps).
