- **Go and other compiled builds now work in `just contribute-hive claude local`** ([#6100](https://github.com/hivecommons/hive/issues/6100)). The local-mode OS sandbox confines writes to `HIVE_WORKSPACE_DIR`, and every compiled toolchain writes its cache under `$HOME` — `GOCACHE` at `~/.cache/go-build`, `ccache`, `$TMPDIR` — so `go build`, `go test` and `go vet` failed on a hive contributor task, in hive's own Go repo, with an error naming a cache file rather than a sandbox boundary. Observed in 8 separate sessions over 2026-08-31 to 2026-09-05 on one host, each rediscovering the problem and inventing its own `GOCACHE` redirect because nothing told it to. The launcher now creates one hive-owned cache root (`${XDG_CACHE_HOME:-~/.cache}/hive/agent-build`), exports `GOCACHE`, `GOMODCACHE`, `GOTMPDIR`, `TMPDIR` and `CCACHE_DIR` into it on the agent's launch line, and the sandbox grants it as a write root — strictly narrower than widening the sandbox, since it is one directory hive owns rather than `$HOME`. It is a write root **only**: deliberately not in `permissions.allow` and not an `--add-dir`, because Bash is what compilers run under, an agent has no reason to `Edit` a build cache, and adding it as a working directory would put megabytes of object files in the agent's view of the tree. Callers that do not set the variable — every non-local path — keep the workspace as their only write root, and both directions are pinned by tests.
