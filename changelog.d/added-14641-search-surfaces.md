- `hivectl search <query>` and `hivectl repo health <owner/repo>` ([#14641](https://github.com/hivecommons/hive/issues/14641), part of [#14491](https://github.com/hivecommons/hive/issues/14491)): operator commands over the spoke's `GET /api/search` and `GET /api/repos/{owner}/{repo}/health`. `search` takes `--kind`, `--repo`, `--from`, `--to` and `--limit`, prints kind, repo, date, title and link per hit (or the full response with `-o json`) and warns about repos whose index is unreadable; `repo health` prints the report-only score with each component's weight, n and contribution. When the hive runs with `search.enabled` off, both say so plainly instead of returning a bare 404/503. New `docs/search.md` documents `search.enabled` and every `search.*` config key.
