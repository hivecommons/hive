- GitHub `@hive` mentions: a follow-up mention on an issue or PR is no longer silently declined after the hive's own reply ([#9164](https://github.com/hivecommons/hive/issues/9164)). The per-thread cap aliased `classification.review_bots.max_attempts_per_thread` (default 1) and counted every App-authored comment on the conversation, so one completion reply — or any stage comment, review summary or escalation the hive had ever posted there — declined every later mention as `guard=rate-limited`. Mentions now have their own key, `github.mentions.per_thread_max` (default 3); only the App's own mention completion replies, which now carry a hidden `<!-- hive:mention-reply -->` marker, count toward it; and a mention past the cap is audited as `guard=thread-cap, detail=count=N max=M`. Completion replies posted before this change carry no marker and are not counted.
