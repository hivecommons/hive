- Dashboard: a green ✓ on a REPOSITORIES PR pill now means exactly "the auto-merge sweep would merge this now" ([#7478](https://github.com/hivecommons/hive/issues/7478)). It used to mean GitHub's `mergeable_state ∈ {clean, has_hooks, unstable}`, and `unstable` — no conflicts, nothing *required* red — on a repo without branch protection includes PRs with failing CI and no review that the sweep will never merge; an operator saw a green pill sit for days with nothing on the card saying why. The pill is now painted from the governor's own merge-eligible classification — the rule that writes `merge-eligible.json` — carried per PR on the status snapshot as `merge_verdict` (`state` + `reason`). Three states: **green ✓** for eligible; **amber ◐** for "mergeable on GitHub, but the sweep still wants something" — a red check with no `auto_merge.required_checks` set to call it optional, a hold label, a missing review approval, an intent verdict — with the reason in the tooltip; no tint for dirty / blocked / draft / unknown. A green pill beside a red *optional* check names the check, so green never reads as all-green. A snapshot without verdicts (an older governor, a replayed page) falls back to GitHub's flag and lands on amber, never green. **Queue auto-merge** stays disabled on GitHub's "no" as before. The classifier is extracted from `writeMergeEligible` into `classifyMergeEligibility`, unchanged in what it files where, so the pill and the sweep cannot disagree.
