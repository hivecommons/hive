- A dashboard restart now cancels the agent's pending kick instead of replaying it into the relaunched session ([#7363](https://github.com/hivecommons/hive/issues/7363)). A kick that was still waiting for the CLI's input prompt — the asynchronous dashboard kick or a synchronous `SendKick` — used to carry on waiting through the restart, see the *new* CLI's prompt, and type the same (in the reported case 71 KB) prompt into it; ten seconds later the next restart destroyed that turn too, and `restart_count` climbed 47→53 while the agent produced nothing. Every restart teardown now invalidates the agent's in-flight kicks (they are dropped before typing, their dispatch reads `failed: cancelled: agent restarted …` immediately, and the restart toast says the pending kick was cancelled rather than replayed), and a restart that interrupted a turn the agent was actively producing arms a 60 s breaker during which `POST /api/kick` and scheduler kicks are refused with the reason and remaining time — so a restart can no longer be followed within seconds by a kick that gets restarted in its turn. Resetting the restart counter lifts the hold. A kick's own crash-recovery restart (bare shell / consent screen) is exempt and still delivers.
