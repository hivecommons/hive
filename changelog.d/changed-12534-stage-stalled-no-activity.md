- Stage labels: `stage/regressed` is retired and `stage/stalled` now means "no activity" (#12534). The review loop 050 → 060 → 072 → 070 → 050 is the intended cycle, so a backward move is no longer a label: it stays as the one-line deduped stage comment and as the item's transition history (`stage.history[]` on `/api/review/queue` entries, backed by `/data/stage-labels.json`). The sweep strips `stage/regressed` from every open item it sees and no longer provisions it. `stage/stalled` is applied only when nobody but the hive has touched the item for the stage's dwell (head push, comment, review/verdict, CI state, labels), measured from real timestamps rather than `updated_at` (#12491), and never while required checks are running or the reviewer verdict for the current head is pending — specimen #12417 (6h at 050, CI green, no verdict) is now an explicit test. Any activity clears it at once. When the hive itself holds an item past the dwell the signal is hive-side: one warn log per PR, a `hive_held` count on the review queue and a "waiting on hive Xh" pill, not a label on the PR. New knob `governor.labels.stage.stalled.require_quiet` (default `true`; Settings → Labels) restores the entered-at clock when off. Dashboard: stalled tooltip reads "no activity for Xh", the regressed pill is replaced by the stage history.
