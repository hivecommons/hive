- New, off-by-default isolated GitHub credential sidecar ([#9586](https://github.com/hivecommons/hive/issues/9586), phase 2). `hive credsidecar` is a small server meant to run as its own container: it holds the GitHub App key, mints each agent tier's scoped token, and attaches it only to requests the hive's MITM proxy has HMAC-signed (method, host, request URI, agent, tier, timestamp, nonce and body digest, per-spoke key). It refuses unsigned, badly signed, expired (30s window), replayed and non-GitHub-host requests. With `HIVE_CRED_SIDECAR_URL` set on the hive (it requires `HIVE_PROXY_INJECT_GH_AUTH=true`), the hive process holds no agent token at all: it records only each agent's tier, the in-process token registry stays empty, and agent GitHub requests fail with 502 rather than fall back if the sidecar is unavailable. A spoke with the sidecar configured alongside an in-process agent token source (injection off or unrecognized), or with an unusable sidecar URL or key, refuses to start (exit code 19). Nothing changes unless `HIVE_CRED_SIDECAR_URL` is set; the hosted pod-spec wiring and any rollout are separate steps. See `src/docs/security-model.md` "Isolated credential sidecar" and the `HIVE_CRED_SIDECAR_*` rows in `src/docs/env-vars.md`.
