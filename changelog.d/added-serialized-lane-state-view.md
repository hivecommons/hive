- The dashboard now shows each repository's merge strategy on its card (permitted users can change it there), and `hive-serialized` repositories get a serialized lane panel per target branch: the pull request at the front and its stage, the waiting pull requests in order, the last reason a pull request left the front, every recorded no-merge reason, and whether the branch is server-enforced, Hive-checked or unknown — with a recommendation to turn on GitHub's "require branches to be up to date" rule when it is not server-enforced. The same state is available from `GET /api/repos/merge-lane`; `direct` repositories are unchanged and get no lane panel. The operator reference documents both strategies, the lane's guarantees and remaining one-API-call window, fork handling and branches with GitHub's merge queue. Note for downgrades: a Hive without the serialized lane ignores `merge_strategy`, so opted-in repositories silently go back to `direct` merging ([#10892](https://github.com/hivecommons/hive/issues/10892)).
