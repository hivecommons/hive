- Per-repo **open PRs** setting (`project.repo_policies[].open_prs`: `on`, `off` or `workflow_only`), the sibling of the per-repo auto-merge switch, at every ACMM level. `off` lets agents analyse, comment and file issues in a repo but open no PR there. `workflow_only` lets only workflow hand-off PRs (`workflow.dispatch`) open, so an agent's own cadence work, such as test hardening, files issues instead of PRs and reviews. It is enforced where agent PRs open: the `hive-open-pr` relay, the forge relay, the sandbox PR path and the sidecar callback. Each refusal is audited as `agent_write_refused` with `gate=open-prs`. A workflow PR is recognised from the hive's own hand-off record, never from PR text. Kicks name each limited repo, and the setting survives a reload through the dashboard overlay. Set it on **Settings → Repos** or on the repo card next to auto-merge (`POST /api/repos/open-prs`). `project.open_prs: false` still wins, and it is now enforced on the relay too. (#19870)
