- Dashboard: the green ✓ on a REPOSITORIES PR pill once again means GitHub said the PR is mergeable. #2365 made `PullRequest.Mergeable` a tri-state string (`"yes"` / `"no"` / `""` for not fetched) so that never-fetched could not read as "no", but the frontend kept testing the field for truthiness — and `"no"` is truthy — so every PR whose mergeability had been fetched wore the ✓ and a live **Queue auto-merge** button, DIRTY and BLOCKED ones included (~90% of the pills on a hosted hive). The pill, its tooltip and both "Mergeable" counters now go through one `prMergeable()` helper that compares to `"yes"`; the tooltip carries GitHub's raw `mergeable_state` (new on the wire, omitted when unknown) and says on an `unstable` PR that non-required checks may still be red rather than presenting it as all green; and a PR GitHub reports as not mergeable renders **Queue auto-merge** disabled with that state as the reason instead of offering the action. The Go-side `mergeableCount` stat had the mirror-image bug — it asserted a bool that the string never satisfied, and in production it never even saw the field, because the status payload holds `github.PullRequest` values rather than maps — so the scanner's "Mergeable" sparkline had sat at zero; it now reads both shapes. Tests execute the helper under node against every wire value and pin the string comparison at each reader, so the string/bool mismatch cannot return.
