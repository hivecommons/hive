- `native-queue-policy` no longer fails a PR adopted at the same head with `gate: skipped`. Every Actions workflow shares one App id, so the newest `gate` check on the head could be the skipped `gate` job that `feedback.yml` posts when the original PR closes unmerged, and that skip was read as the PR's own verdict. A completed, unsuccessful run of a required check is now passed over when its own check suite proves it came from a different workflow file than the check's source (`docker.yml` for `gate`); every other run is judged exactly as before, and the chosen run still goes through every provenance check.
