- `just contribute-hive <backend>` (container mode) now runs the contributor container inside the same resource envelope `contribute-k8s` has always applied to this workload — `--memory 4g --memory-swap 4g --cpus 2` by default, overridable with `HIVE_CONTAINER_MEMORY` / `HIVE_CONTAINER_CPUS` (set to `none` to lift a limit) — and a container that dies OOM/exit 137 is now explained ("killed for exceeding its memory limit") with a pointer to the override, instead of surfacing as a bare `exited with code 137` ([#6485](https://github.com/hivecommons/hive/issues/6485)). Previously the local container path set no limits at all, so a growing agent on a contributor's workstation could push the whole host into systemd-oomd territory and lose its assigned task mid-flight.
