- The `auto_merge.human_merge_pin_only` exception no longer admits a major version change as a pin bump. An action pin whose `# vN` comment moved to another major version counted as a pin because only the commit and the comment changed, so Renovate's `actions/checkout` and `actions/upload-artifact` v4 → v7 upgrades were merged by the hive into protected workflows with no person involved ([projectbluefin/dakota-iso#337](https://github.com/projectbluefin/dakota-iso/pull/337), [#342](https://github.com/projectbluefin/dakota-iso/pull/342)). The classifier now compares the major version (the first number, after an optional `v`) on both sides of an `action-sha` line, an `action-sha-ref` companion line and a `version-pin` value, and refuses the pair when it differs, up or down: the pull request gets the usual human-merge-path hold and comment, and the hive's log reason names both versions (`<file>: major version change v4 -> v7 is not a pin`). A companion line that changes major version is refused even when a `uses:` pin carries the same commit move. Bumps within one major version (`# v4` → `# v4.2.0`, `1.2.3` → `1.9.0`) and pins without a version comment are judged exactly as before.
