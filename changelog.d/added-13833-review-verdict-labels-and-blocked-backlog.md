- The review swarm's outcome now shows on the PR, and its follow-up work is tied to the PR it came from ([#13833](https://github.com/hivecommons/hive/issues/13833)). The new `review.verdict_labels` block maps the current head's review state to one label each: `reviewing`, `approve`, `changes_requested`, `requires_human` (`reject` counts as `requires_human`). It works independently of the auto-merge engine's stage labels, so a hive with auto-merge off still shows "in progress / approved / changes requested / needs human" on every PR. Like `human_decision_label`, the labels are never created and never block. With `review_heads`, backlog items are now filed only from the decision step's reconciled findings, never from each head's raw report. That had produced near-duplicate items whose wording defeated the fingerprint check and spent the PR's daily cap. The items are also listed in a "Follow-ups filed" section of the decided review itself, on every head, rather than in a once-per-PR summary comment. Every review-backlog item, in every destination including Linear, is now parked on the PR it was filed from with the `blocked` label and the blocked-on marker, not only when the cited file is missing on the base branch. A new sweep lifts the block with a one-line note when the PR merges. When the PR closes unmerged it also lifts the block and comments "source PR #N closed unmerged — re-triage against current base", leaving the item open for normal triage: a closed PR is often superseded by one that lands the same lines, so backlog items are never closed or cancelled automatically.
