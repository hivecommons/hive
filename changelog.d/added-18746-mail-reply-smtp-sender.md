- **Hub: the sender behind the confirmation reply for mail sent to a hive, off by default ([#18746](https://github.com/hivecommons/hive/issues/18746)).** When the DKIM key file, `From`, selector and the new `HIVE_HUB_MAIL_REPLY_HELO` name are all set, the hub now delivers the "received" and "waiting for approval" replies itself: one plain-text message signed with the key (RSA of at least 2048 bits or Ed25519), a null envelope sender (`MAIL FROM:<>`), one connection to the best-preference MX host of the sender's domain with required STARTTLS, timeouts on every step and no retry (any failure is final and the ledger keeps the claim). The ledger limits are applied before anything is sent; a key that cannot be loaded sends nothing and uses up nothing; a header or address with a control character, a non-ASCII address or a MX host in a private range is refused before any connection; the log holds only ids, a reason class and a server's numeric code. A hub without the key file builds no sender and opens no connection. The owner still has to publish the DKIM and SPF records, confirm outbound TCP 25 and run the two-provider `dmarc=pass` test before turning it on. See [Replies to the sender](src/docs/meetings.md#replies-to-the-sender-off-by-default).
