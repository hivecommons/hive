- **An approved PR keeps its swarm approve when the hive merges the base into it.** The hive's own update-branch (or merge-forward) gave an approved PR a new head with no verdict, so it fell back to `review-gate:no-review-bundle` and waited for a reviewer to read base code already reviewed and merged upstream (projectbluefin/fsdk-containers#482, projectbluefin/finpilot#599). The review planner now re-stamps the prior approve onto the merge head at any delta size, with `delta.base_sync: true`, when every commit since the reviewed head is a GitHub-made merge of the base authored by the hive App and the base's changes miss every file the PR changes. A merge by anyone else, any other commit, a base change to a PR file, or a prior `changes_requested`/`requires_human` keeps the delta review. CI still runs on the merge head, and a negative `review.delta_trivial_lines` turns the carry off. The proof costs two compare calls, made only for a head whose delta is all hive merges.
