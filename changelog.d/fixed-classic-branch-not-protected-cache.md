- **The merge-lane view and the red-main sweep stop asking classic branch protection again on every read for repos that use only rulesets.** GitHub answers `GET /repos/{o}/{r}/branches/{branch}/protection/required_status_checks` with 404 "Branch not protected" for every branch of such a repo, and that answer was never remembered: about 150 calls an hour came from `hive:merge_lane_view` alone on a 13-repo hive that ran out of API budget every hour. `ReadBranchRules` (the dashboard's merge-lane and ACMM views, the merge lane and the red-main sweep) and the native merge-queue observation now remember it per repo and branch for the new `HIVE_CLASSIC_NOT_PROTECTED_TTL` (default 15m, `0` turns it off), so each branch costs about 4 classic calls an hour. Both readers still read the rulesets on every call and still treat a failed rules read as unknown, so a remembered answer gives the same result as a live one. Classic protection added to such a branch is seen within 15 minutes, and GitHub enforces it at merge time meanwhile. The required-check policy used by the merge gates is unchanged and still reads classic protection every time. A 403 or another 404 keeps its own 1h handling, and rate-limit and other errors are still not remembered.
