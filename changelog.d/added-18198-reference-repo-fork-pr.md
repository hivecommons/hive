- A `prs`-tier reference repo now takes PRs through the hive owner's fork ([#18198](https://github.com/hivecommons/hive/issues/18198)). The owner cannot push to a repo they do not own, so the proxy now allows forking the reference repo (`POST /repos/{remote}/forks`) and git pushes to `<ownerlogin>/<name>`, the owner's fork, with the default-branch guard applied to the fork; every other write on the fork is refused with a reason naming the fork flow, and every existing refusal on the remote (labels, reviews, assignees, closing others' items, merges, default-branch pushes) stays. Fork creation and fork pushes carry the reference repo's write credential; reads of the fork go out unauthenticated. The kick's REFERENCE REPOS block tells `prs`-tier agents the exact flow: `gh repo fork <remote> --clone=false`, push the topic branch to the fork, then `gh pr create --repo <remote> --head <ownerlogin>:<branch>`.
