- Park re-check: the note that says the work a decision park waits on has merged or closed is now posted on a park the hive applied itself, even when the issue carries no review opt-in label or is older than the hive's write access. A contributor relay parks an issue with a hub-minted token, so the park label is the hive's own; the note still went through the write-back gate as an ordinary `needs_decision_comment` and was refused on every pass for want of the opt-in label, so a person's issue stayed parked on a blocker that had merged hours earlier and the hive said nothing. The re-check now tells the gate when the label event the park is dated from was made by the hive's own bot, and the gate then skips the opt-in label and the backfill guard for that one note. ACMM L5, a paused repository, `writeback.per_repo` mode and `own_only` still refuse it, a park a person applied is gated as before, and the note still never un-parks the issue.
- Park re-check: a note the write-back gate refuses is now logged (`park re-check note held by writeback gate`, with the repository, issue, reason and detail), once per issue and reason at info level and at debug level on the passes that repeat it. Before, the only trace was the pass summary reading `posted 0`.
- Contributor relay: the question the hub posts for a needs-decision park is tried again when GitHub refuses it for a rate limit, after the limit's reset or `Retry-After` (a minute when GitHub names neither), up to three more times. Each retry first checks that the issue is still open and still carries the decision label, and posts nothing when someone explained the park in the meantime. Before, the one attempt was dropped with a warning and the issue sat parked with no question. When the retries run out the hub logs one warning that the question was not posted. Other errors are not retried, and a hub restart drops a pending retry.
