- A branch-promotion pull request (`main` into `stable`, say, opened by a workflow) can now merge without a person, opt-in per repository with `auto_merge.promotions` (off by default, and only where the self-authored sweep runs). A rule names the `source` and `target` branches, the exact `authors` that open the pull request and its `head_ref_prefix`. A pull request matches only when `source` takes changes only through a pull request (classic protection requiring pull request reviews without force pushes, or an active ruleset `pull_request` rule; any number of approvals), its head commit's tree equals the current tip tree of `source`, read live from GitHub, the head is either the `source` tip (or an ancestor of it) or a single commit on the live `target` tip (a `git commit-tree` promote), and GitHub's test merge onto the live target tip carries that same tree. Trust carries over: `target` inherits exactly `source`'s review guarantee, with the approvals and bypass actors its owner configured. The sentinel then does not flag `sensitive_path` on it (every other rule still applies, and a source that only moved on keeps the exemption) and the self-authored sweep's new `promotion` lane merges it with no linked issue and no author tier, while required checks, holds, `needs-owner-merge`, `human_merge_paths`, the review verdict hold, the intent gate, `squash_only` and the expected head SHA still apply; the review verdict hold and the intent gate can hold a promotion. The hive never updates a branch any rule names: `require_current_base` is replaced by the test-merge check, and a target that requires up-to-date branches, a serialized repository, or a test merge that differs hands the promotion back to a person, shown as a hand merge. Everything is checked again right before the merge or enqueue, a queued promotion that stops matching is withdrawn from the native merge queue, and the landed merge's tree is compared with the verified one. The author is not trusted for anything else and no label is a trust signal. Each decision is audited as `promotion_decision` with the head, source tip and tree SHAs. Edit it in Settings → Features → Auto-merge or with the admin MCP `auto_merge.update` `promotions`, whose preview discloses each added rule as widening.
