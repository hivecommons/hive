- Each per-UID agent now gets its own `XDG_DATA_HOME` and `XDG_STATE_HOME` (`/data/home/agents/<agent>/.local/share` and `.../.local/state`) instead of every agent's `~/.local` being a symlink into the one shared `/data/home/.local` ([#6238](https://github.com/hivecommons/hive/issues/6238)). Backend CLIs keep their session transcripts, run locks, sqlite state and plugin caches there, so the shared tree was a contended resource owned by whichever agent wrote first, held together only by the Dockerfile umask wrappers - a per-CLI allowlist that failed closed for every new backend (muse crash-looped hundreds of times before it was added) and that CLIs which check their state root's permissions refused to trust. The launch environment now exports both variables explicitly, following the per-agent `CODEX_HOME` precedent, and provisioning makes `~/.local` a real agent-owned directory, retiring a legacy symlink bridge when it finds one. Sharing stays explicit and narrow: `~/.config` (`XDG_CONFIG_HOME`, holding gh and goose config) and the credential directories bridged by `SharedAuth` (`.claude`, `.gemini`, `.codex`, `.copilot`, `.bob`) are unchanged, and `~/.local/share/opencode` (where `opencode auth login` writes its credential) is bridged back to the shared tree so one login still reaches the fleet. Nothing is migrated: existing state under the shared tree is left where it is and agents start fresh per-agent state on their next session. `HIVE_SHARED_AGENT_HOME=1` keeps the legacy layout whole.
