- A pull request whose Hive review asks one named person to decide now shows as waiting on that person instead of as your turn. The review's decision question usually names who should decide with an at-mention, for example "at-sign bketelsen should decide whether ...", and the dashboard read every requires_human hold as "Hive's review needs a human decision" for the dashboard owner, even when another maintainer was asked ([projectbluefin/server#666](https://github.com/projectbluefin/server/pull/666), [projectbluefin/actions#740](https://github.com/projectbluefin/actions/pull/740)). Only an at-mention outside code spans counts; a bare name does not. When the question names exactly one login other than the pull request's author, or names only the author and does not ask a maintainer, owner or approver, the row reads "Waits on bketelsen: Hive's review asked on Nov 16" under Waiting on someone else (Waiting on another item, now also a pull request band), and the overview's waiting breakdown counts it as "review asked a named person". Bots, app accounts, the policy's maintainer placeholder and the hive's own logins (the App bot, the additional bot logins and the AI author) are not people. The three days run from the first verdict that asked that person, so a new head asking again does not restart them; after that it is your turn again, with the same `review_requires_human` reason and the text "Hive's review needs a human decision: bketelsen has not answered since Nov 16" (the year is added when it is not the current one). A question that names nobody, two or more people, a team or a dashboard owner, a fix-cycle-cap verdict, a reject, a fix-cap or no-fixer hold, the loop cap and a person's recorded answer on the head all read as before. Pull requests waiting after a person answered the review are now counted in the breakdown as "a person answered the review" instead of "within the adjudicator wait", and a waiting row no rule names as "waiting for another reason". This is display only: the dashboard, its exports, the MCP read-outs and the hive advisor's your-turn counts in the advisory digest follow the new decision, while the hold, the review, the fixer, the merge gates and labels are untouched. There is no new setting.
