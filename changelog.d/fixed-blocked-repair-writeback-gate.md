- Blocked sweep: a `blocked` label the hive applied itself, with nothing naming what the issue waits on, is now turned into a `needs-human` ask on every issue, including one created before the hive could write to the repository and one without the review opt-in label. The repair went through the write-back gate as `gate_comment`, so the backfill guard (`writeback.unsolicited.backfill` off) and the opt-in label requirement refused it on every sweep, although the hive had already labelled the issue; the issue stayed `blocked`, out of every agent's reach and in no inbox, for days. The repair is now its own write-back kind, `blocked_repair` (`writeback.kinds.blocked_repair`, default minimum level 1, shown in Settings → Features → Write-back containment and settable with the admin MCP `writeback.kind_policy`): when the sweep has established that the hive's own bot applied the label, neither of those two checks applies. A paused repository, `writeback.per_repo` mode `off`, `issues-only` or `labels-only`, a repository outside `project.repos`, `own_only`, the kind's minimum level and the notification burst hold still refuse it, and a person's `blocked` is left alone as before. A held repair is logged once per issue and reason (`blocked sweep: needs-human ask held by writeback gate`) instead of on every sweep; repeats go to the debug log.
