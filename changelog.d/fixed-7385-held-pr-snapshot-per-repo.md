- Fixed a deadlock where a spoke tracking more than 100 held PRs permanently disabled its own PR channel. The hold-gated coordination snapshot capped held PRs globally (reusing `maxIssuesPerKick`), so one crowded repo pushing the combined list past the cap emitted a blanket `STAND DOWN this kick` across every tracked repo — and since the agent could no longer open PRs, the backlog causing the overflow could never drain. The cap is now per repository (`maxHeldPRsPerRepoPerKick`) and the stand-down names only the truncated repo, so repos the snapshot lists in full stay workable. Fail-closed behavior is unchanged: the agent still refuses to act wherever the snapshot is incomplete.
