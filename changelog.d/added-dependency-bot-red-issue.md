- New opt-in `auto_merge.dependency_bot_red_issue.enabled` (default off; Settings → Features → Auto-merge, admin MCP `auto_merge.update` field `dependency_bot_red_issue_enabled`). When the dependency-bot sweep's red-CI hand-off fires for a Renovate, Dependabot or mergeraptor PR that adoption did not take, the sweep files one issue in that repository asking for the companion change the bump needs, but only on evidence that this bump is at fault: the failure reproduced, either in-suite (on a head that already contains the base tip, a failing attempt started after an earlier failing attempt in the same check suite had finished, or the hive's transient re-run failed again) or across heads (the same checks failed, never passing and not triaged transient, external, shared or base-red, on the PR's previous head and again on the newer head, which may be behind the tip but contains a base commit the previous head lacks, on which every failing check passed, whether the bot regenerated it or a hive base refresh pushed it), and the check never passed on the head; no other open PR fails the same checks and no open `[shared-ci]` incident names them; the failing runs left failure-level error annotations beyond the exit code; and every failing required check's newest run on the base tip concluded success after the failure started. The issue links the PR and its failing runs, quotes the errors, asks for a repository fix instead of an edit to the bot's branch, and says what then has to happen on the PR for that bot. One issue per PR and failing check set, found again by a first-line body marker the hive itself wrote, through the `issue_file` write-back gate (checked before any read); at most 3 PRs are checked per pass and no hand-off ever waits for the filer. A PR still parked by its own hand-off for an earlier head is checked once for its newer red head and gets the issue only. The hand-off and its `needs-human` label are unchanged apart from a line naming the issue, and the hive posts one note on the issue when the PR merges, closes or goes green, without ever closing it.
