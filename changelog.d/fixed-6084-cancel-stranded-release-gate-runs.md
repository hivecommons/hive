- Automated releases no longer strand ~8 spurious zero-job `failure` runs per release ([#6084](https://github.com/hivecommons/hive/issues/6084)). `tagged-release.yml` opens a PR from the `release-gate/v<VERSION>` scratch branch into `v4`, merges it within seconds, and its cleanup trap deleted the scratch branch immediately - while the pull_request-triggered workflows fired by the PR open (Changelog Reminder, Docs Index Reminder, Build and Push Docker Image, changelog-fragment-guard, Copilot DCO, ...) were still queued. With the head ref gone they zombied out as `conclusion: failure` with an empty jobs list after 10-45 minutes; three releases on one day produced ~24 such runs, which dominated `gh run list --status failure` and masked real regressions. The trap now cancels every `queued`/`in_progress` run on that scratch branch (REST `actions/runs?branch=release-gate/v<VERSION>` then `POST .../cancel`) before deleting it, so stranded runs conclude `cancelled` - the accurate verdict. The cancellation is best-effort (`|| true` throughout, it can never fail a release) and scoped strictly to the ephemeral scratch ref this workflow owns.
