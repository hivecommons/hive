- `runs.triage.clarity_gate` (default off; `enabled`, `threshold` 0-100, default 60; Settings → Features → Incoming issue triage) scores each human-filed, unclaimed issue for goal, acceptance criteria, scope and detail before an agent is kicked on it. An issue under the threshold gets one `<!-- hive:clarity-gate -->` comment with concise questions for its author and the `needs-spec` label (stage/045) instead of a claim, and a park label write that failed is retried on the next kick even across a hive restart; removing `needs-spec` resumes the normal pipeline ([#13577](https://github.com/hivecommons/hive/issues/13577)).
- The clarity gate (`runs.triage.clarity_gate`) now resumes a parked issue on its own: while the gate is on, a periodic sweep removes the hive's own `needs-spec` once the issue author, or a non-hive commenter with write/maintain/admin, replies after the gate's `<!-- hive:clarity-gate -->` question, and records the un-park so the issue re-derives `stage/010-actionable`; a `needs-spec` a person added is never lifted ([#13588](https://github.com/hivecommons/hive/issues/13588)).
