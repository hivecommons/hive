- `just contribute-hive claude` no longer stalls at Claude Code's "Bypass Permissions mode" consent, and the relay now says plainly when the hive has no work for it. The contributor container seeded `~/.claude.json` but never the `skipDangerousModePermissionPrompt` user setting, and its startup auto-dismiss pressed a bare Enter on any screen that says "Enter to confirm", which on this dialog (default selection "No, exit") makes Claude exit to the shell, leaving the relay at "CLI is not ready yet" forever. The entrypoint now merges `skipDangerousModePermissionPrompt: true` into the staged `~/.claude/settings.json` (only for a bypass-mode launch, other keys kept), the dismiss loop and the relay select "Yes, I accept" with Down, a pause and a cursor check before Enter and never press Enter on "No, exit", and a Claude that exits at that prompt is relaunched up to three times with `Claude exited at the permissions prompt` in the log and as `cli_reason` in the relay status. Separately, an empty hive queue is reported as one sentence naming the hive instead of a raw `no_matching_work` line every 30s, with a slower retry (30s up to 5 minutes), a `Work available ... claiming` line when work appears, filters that the hive does name (capability, repo, level, quota) worded as such, a `queue_state` field on the relay status (and per hive), one compact status row and one "all queues are empty" line when a relay holds several hives, internal retry bookkeeping lines moved behind `HIVE_RELAY_DEBUG=1`, and a one-line quota-guard notice that says it can be ignored ([#19049](https://github.com/hivecommons/hive/issues/19049)).
