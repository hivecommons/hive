- In a repository listed in `auto_merge.squash_only`, the maintainer ask on a hive sign-off attribution hold (the `stage/085-needs-decision` note and the adoption-stalled note) no longer tells a maintainer to merge with `gh pr merge N --merge`, which GitHub refuses there. Every refusal other than the squash-only one (unsigned commits, a hive-only head, role, a manual-merge rule, suppressed labels) now keeps its own question and names the routes the repo has: squash by hand with a message that keeps each commit's `Signed-off-by` line (edited in the web UI or passed with `gh pr merge N --squash --body-file`, since GitHub's default squash message and a merge queue can drop them, and once the `Sign-off survives the squash` check passes or is bypassed where it runs); re-author the hive's commits under a maintainer's own sign-off; or lift squash-only, which also needs merge commits allowed on GitHub. A hive-only head leads with re-authoring, because its squash carries no sign-off from the PR author ([projectbluefin/bluefin-bling#200](https://github.com/projectbluefin/bluefin-bling/pull/200)). Repositories that allow merge commits get the same text as before, and the hold itself is unchanged.
