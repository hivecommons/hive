- **PR Verifier no longer fails every open PR when its own image is unreachable** (#6085). The workflow treated the verification itself as advisory (`continue-on-error`) but the GHCR login and image pull as fatal, so any registry-side change — the kubestellar→hivecommons org move left 11 consecutive runs red on `manifest unknown` — failed the check on every PR at once before any PR content was examined. Login and pull are now advisory too, the verifier step runs only when the pull succeeded, and a skipped verification announces itself with a workflow warning naming the unreachable image, so the check reports on PR contents or says plainly that it could not. `src/deploy/test_pr_verifier_advisory.sh` pins the relative invariant — registry access is never treated more harshly than the verification it enables — which permits either coherent posture and forbids only the split that was there. It is a static check on purpose: the workflow runs on `pull_request_target`, so a PR that fixes this executes the base branch's copy and cannot show itself passing.
