- The hive's routine "everything since a time" GitHub reads can now be answered with free `304`s. The un-park sweep's comment reads, the closed-issue stage sweep, the review backlog split, the shared-CI rerun sweep and the same-component check built their `since=` from the current clock, so the URL changed on every pass and the ETag cache (keyed on the full URL) never matched. On a hosted hive with 20 repos on 2026-11-07, untagged issue-comment lists were answered `304` only 51% of the time and issue lists only 28%, against 83% to 91% for the pull-request lists, while the hive needed about 8,250 calls an hour against a 7,000 limit. The `since` sent to GitHub is now rounded down to the hour; each sweep still filters on its exact cutoff, so nothing is missed. The calls the periodic sweeps, the governor cycle, the state cache, the metrics collector, the request watchers, the mention poller and dashboard requests make are now named in `/api/gh-rate-limits` (`hive:<sweep>`) instead of all reading as `hive`.
