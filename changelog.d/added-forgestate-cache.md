- New `pkg/forgestate` per-repo GitHub state cache (Phase 1 of [#13373](https://github.com/hivecommons/hive/issues/13373), [#13374](https://github.com/hivecommons/hive/issues/13374)): one in-process snapshot of open issues and PRs per repo, kept current by an ETag-conditional slow reconcile (a failed reconcile, such as a 403, keeps the last good snapshot and marks it stale instead of showing zero counts), webhook patches that re-fetch only the named item and upsert monotonically by `updated_at`/head SHA (closed and merged items leave at once, out-of-order deliveries settle correctly, delivery ids are kept for audit), and write-through of the hive's own label, comment, merge, close and claim mutations. It also adds a `forgestate_drift` metric, a startup gate that waits for every repo's first reconcile, freshness-bounded read-through for irreversible actions, and a per-minute `search` bucket budget. It is configured under a new `forgestate:` block (`enabled: false` by default) and is not wired to any reader yet, so enabling it changes no behaviour until the follow-up migrations land.
