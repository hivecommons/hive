- A bad operator model id no longer restart-loops an agent silently. On the `claude` backend, a dotted `claude-…` id such as `claude-sonnet-5.5` (the Anthropic id is `claude-sonnet-5-5`) is now refused with a `400` that suggests the dashed spelling, on every path that sets a model: `PUT /api/config/agent/{name}/models`, the settings dialog, `POST /api/model` (card dropdown, `hivectl agent model-set`, admin MCP `agent.model`) and adding an agent. A well-formed id that hive's model list does not know is still saved, with a `warning` in the `PUT .../models` response, because it may be newer than the list. When Claude Code refuses a model anyway ("There's an issue with the selected model (…)"), the agent card now shows `blocked: inference (model_rejected): model <id> rejected by the CLI` instead of a healthy, logged-in agent; kicks and automatic restarts back off (2 minutes, doubling), and after 3 refusals of the same id the agent is paused with trigger `model-rejected` and a reason that names the model. Before, one hive's `guide` agent restarted 502 times in 24 hours with no warning. See [agent-configuration.md](src/docs/agent-configuration.md#model-ids-are-checked-when-you-save-them) and [troubleshooting.md](src/docs/troubleshooting.md#an-agent-shows-model--rejected-by-the-cli).
