- A `hive-serialized` lane no longer keeps a red front pull request for the whole front timeout ([#11023](https://github.com/hivecommons/hive/issues/11023)). When the self-merge or `lgtm` queue sweep rejected the front before the lane (for example as not mergeable once its required check failed after the lane's branch update), the lane was never consulted again, so every pull request behind it — including the fix for a red target branch — waited 60 minutes. The sweeps now hand a rejected front to the lane, which re-evaluates it without merging and lets it leave at once with the real reason (`required check "test" finished as failure on head …`), so the next pull request starts on the same tick. The front timeout stays the fallback for checks that never finish, and its reason now says what the lane last knew instead of always claiming the checks did not finish.
