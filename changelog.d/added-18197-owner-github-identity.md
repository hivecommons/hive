- Write-tier reference repos now write as the hive owner's own GitHub account instead of an App installation token minted on the target org ([#18197](https://github.com/hivecommons/hive/issues/18197), part of [#18196](https://github.com/hivecommons/hive/issues/18196)). A reference repo is outside the hive's org by definition, so the App was rarely installed there and derived grants mostly came up read-only. New owner-only routes `GET`/`DELETE /api/github-owner-identity` and `POST /api/github-owner-identity/start|poll` run a device flow with the spoke's existing `oauth_client_id` asking for `public_repo` (dashboard login stays scope-free), refuse an account other than the signed-in owner's, and store `{login, token, scope, connected_at}` in a 0600 file at `/data/secrets/github-owner-token` (`HIVE_GITHUB_OWNER_TOKEN_FILE` overrides). The path is never written to `hive.yaml` and the token never leaves the spoke. A hand-written write entry uses its `write_token_file` when it has one and the owner's token otherwise. Boot still exits 22 when neither is available, and the message now points to Settings → Reference repos → Connect GitHub account. A derived entry is write-tier while the owner is connected and read-only with "the hive owner has not connected a GitHub account" while not. Its request-issue notice names that cure rather than installing the App. The token is re-checked against `GET /user` at most every 10 minutes; a 401 drops owner-backed entries to read-only with a reconnect reason. Connecting or disconnecting re-resolves the proxy policies without a restart. Each write entry now reports `credential_state` and a new `credential_login` in `/api/status`, and the agent kick shows the login it writes as. Upgrade note: a hive whose hand-written write entries relied on the App installation must connect the owner's account (or set `write_token_file`) before restarting.
