- Push and on-call escalations (ntfy, Pushover, PagerDuty) now pass every operator-visible field through the shared secret/canary scrubber at the surface boundary, instead of relying on each caller to remember to scrub first ([#8048](https://github.com/hivecommons/hive/issues/8048)). A GitHub token, JWT, AWS key, private key, or `ioscan` canary that reached an escalation body used to leave the trust boundary intact — into a third party's push pipeline and onto an on-call phone screen — for any caller that dispatched unscrubbed text; the three call sites in `cmd/hive` scrubbed, and nothing made that a property of the surface. Sink credentials are untouched: they are the authorization to deliver, not event text. A v6 guard-invariant conformance suite (`src/pkg/escalate/conformance_v6_test.go`) pins this for all three providers and fails if the push/on-call surface grows an inbound action path or a state-reaching dependency that would need the `ioscan`, `Converse`, role-floor, and mode-ladder guards it currently has no way to reach.
