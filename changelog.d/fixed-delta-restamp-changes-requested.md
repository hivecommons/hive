- Delta re-review no longer carries a `changes_requested` or `requires_human` verdict onto a new head across a real change. A small fix (under `review.delta_trivial_lines`) in a file other than the one a finding was anchored on used to be re-stamped with the old verdict and no review session; nothing was published for the fix head, and a contributor PR went back to `stage/072-returned-to-contributor` with nothing new to fix. Such a head now gets a delta review; only an identical tree or a PR with no diff against its base carries the verdict, and a `changes_requested` with nothing the author can read is never carried. Verdicts an older hive carried this way are dropped when `review-verdicts.json` is read, so the head goes to review (050) instead of staying at 072. Approve carries, including the base-sync carry, are unchanged. The contributor nudge on a review-swarm `changes_requested` now lists the findings (`review finding: path:line title`), the withheld-fix log and `review_fix_withheld` audit entry name `carried_from` instead of claiming a review was published, and the Activity Monitor's Review track (and `stage_tracker_read`) reads *carried from &lt;head&gt;* for a re-stamped head instead of *not started* beside a full perspective count.
