- The review fix loop no longer pushes to a PR another bot opened and regenerates (a GitHub Actions promotion or release PR, Dependabot, Renovate: any `review.bot_authors` login that is not this hive's App, with no agent attribution). The bot's next run overwrote the fix commit, and until then the PR stayed red, for example on a check that requires the PR's tree to equal its source branch. The fix is withheld (`review_fix_withheld`, `setting=review.bot_authors`, exclusion `other-bot-author`) and spends no fix attempt. The reviewer is told the author cannot apply a fix either, so a defect the PR carries over from its base is reported as one for the base branch. A changes_requested verdict on such a PR now parks it at `stage/085-needs-decision` with reason `bot-author:finding` and one write-back-gated decision comment (fix it on the base branch, merge as is, or close), instead of `071-needs-author` waiting on an author that cannot act. The tracker disables *Give direction* on it.
