- Input Defense settings saved from the dashboard now actually unblock kicks at ACMM L5+ ([#16973](https://github.com/hivecommons/hive/issues/16973)). Saving ioscan fail mode "open" was stored as unset, which at L5+ falls back to the ACMM pack's fail-closed default, so the setting snapped back to "closed" and kicks carrying untrusted text stayed withheld. "open" is now stored as given, and every ioscan save in Settings → Security → Input Defense rebuilds the semantic classifier from the new backend and fail mode immediately, clearing the blocked-kick alert when it no longer applies. A runtime ACMM level change (for example L4 → L5 in the dashboard) rebuilds the classifier the same way, so the level's classifier requirement and fail mode apply without a restart. The alert and the Classifier backend help text no longer tell operators to restart for changes the dashboard now applies live, and the alert names the `ioscan.fail_mode` key the Security tab actually exposes.
