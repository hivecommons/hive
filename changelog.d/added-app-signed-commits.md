- New `github.app_signed_commits: true` makes every agent-opened PR carry a commit GitHub itself signed. Agents commit with plain git and cannot sign — a GitHub App has no account to hold a key — so a base branch with a `required_signatures` ruleset blocked every agent PR from merging no matter who approved it (observed: eight open, approved, green PRs all at mergeable_state "blocked"). With the flag on, the PR-request watcher re-authors the head branch through the `createCommitOnBranch` GraphQL mutation with the App installation token before opening the PR: one commit, GPG-signed by GitHub and shown as Verified, authored by `<app_slug>[bot]`, same tree, the agents' original messages and DCO trailers as its message. Changes the mutation cannot express (file modes, symlinks, submodules), oversized changes, and a head that moved under the rewrite fall back to the agent's own push with the reason in the request's `.result.json` (`signed_skipped`) and the hive log; the PR is never blocked by the step. Off by default. See github-app-setup.md.
