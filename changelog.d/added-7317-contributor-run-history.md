- **Per-contributor run history: `GET /api/contribute/runs?username=<u>`, and durable records for hand-backs** (#7317). The task-run log (`task_runs.jsonl`) already held the per-run evidence an operator needs to troubleshoot a struggling contributor — outcome, `failure_kind`, `reason`, `scenario`, duration — but the only read path was the per-backend aggregate `/api/contribute/run-stats`, so the reason strings were unreachable without shell access to the hub. The new endpoint serves one contributor's records newest-first (`?days=`, `?limit=`), same public read posture as the sibling `/api/contribute*` GETs. And the two hand-back paths that used to write no record at all — the relay re-advertising `ready` while still holding a task, and a connection dropping mid-task — now append a synthetic `abandoned` record (`abandoned: relay re-advertised ready` / `abandoned: connection lost`) with the elapsed duration, so a session that hands back 10 of 11 tasks leaves 11 rows, not 1. `run-stats` counts the new records as failures under their own `abandoned` scenario — the direction #7317 calls out, since totals previously undercounted exactly the sessions most worth investigating.
