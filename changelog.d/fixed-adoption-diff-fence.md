- Stalled contributor PRs whose diff trips the contributor lane's diff fences (tests removed, CI workflow / action files edited) are adopted instead of being refused on every sweep (`adoption due but refused by diff fence`, hivecommons/hive#13212): adoption is not a merge. The fence is carried forward — recorded on the stage record (`adopt_diff_fence`), named in the adoption comment, and stamped into a superseding App PR's body as `<!-- hive:carried-fence reason=… -->` — so the fix lane repairs CI while every merge lane (contributor, self-authored, trusted-author, queued) still routes the green head to `stage/085-needs-decision` for a manual merge. The dco-rehome second takeover carries the fence too instead of releasing the adoption back to 072. Only a head that moved since evaluation or an unreadable / incomplete file list still defers adoption to the next sweep.
