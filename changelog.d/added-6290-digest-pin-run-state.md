- Hosted-spoke rollback is now a first-class hub operation. `POST /api/saas/hives/{id}/pin-digest` (owner-only) holds a spoke at one immutable image digest, given either as `sha256:...` or as the short git SHA the My Hives page shows (the hub resolves it to the manifest digest), and applies it through the same `kubectl set image deployment/hive "*=..."` path the upgrade code uses. The pin is a run-state on the hive record with who/when/digest/reason, so it survives hub restarts, shows on the dashboard as a PINNED pill with its provenance, and is recorded on the hive timeline. While it holds, the tracked-channel re-arm, auto-upgrade, and every armed heartbeat directive leave the hive alone, and the upgrade / branch-switch endpoints refuse with 409 naming the pin; `POST /api/saas/hives/{id}/unpin-digest` lifts it and returns the hive to its channel or branch tag. Previously the only rollback path was a raw `kubectl` bypass with no provenance ([#6268](https://github.com/hivecommons/hive/issues/6268)), and even that was undone on the next heartbeat because the channel re-arm honoured only the admin upgrade pause ([#6267](https://github.com/hivecommons/hive/issues/6267)); together they left rollback effectively unsupported ([#6290](https://github.com/hivecommons/hive/issues/6290)).
