- The Agy (Google) contributor quota adapter now parses agy's real `/usage` output and produces a reading again (kubestellar/hive#6986). #6966 modelled the response on field names described in prose rather than a captured payload — a root `quota` key holding a flat `windows` map with `reset_at`/`duration_mins` — and a live capture on agy 1.2.1 shows none of those exist: `--output-format json` is a print-mode response formatter, so the quota data sits under `command.data.groups[].buckets[]` with `window` ("weekly"/"5h"), `remaining_fraction` and `reset_time`, and carries no plan tier. The adapter therefore rejected every real payload and reported `unknown` on a correctly configured host — safe, but indistinguishable from having no agy credentials installed. The capture now ships as the test fixture, replacing the schema-derived guess. The adapter also learns that agy meters **two independent quota pools** (Gemini models vs third-party Claude/GPT models), each with its own weekly and 5h bucket: `AgyProber.Model` selects the applicable pool, and with no model known the worst bucket across every pool binds, so the guard can hold too often but never admit against an exhausted pool. Capability is detected from the response envelope (`command.name == "usage"` with populated `command.data`) rather than from `--output-format json` being accepted, which says nothing about whether `/usage` exists.
