- A channel or branch switch delivered over heartbeat no longer re-rolls the spoke pod on every beat until it happens to win a race. The hub kept the switch armed until the spoke reported the new image tag, and it is the OLD pod that keeps reporting while the new one initializes, so every beat re-delivered the switch; the spoke then re-patched its Deployment with a fresh restart annotation even though the image already said the target, which is a new pod template, so the ReplicaSet controller killed the pod that was still initializing and started another. A spoke whose pod needs longer than one heartbeat interval to become Ready never converged (observed on a-ks-wec2, 2026-09-08: one hive cycled 18 ReplicaSets in 8 minutes, none reaching Ready, while its neighbour with the image already cached on its node finished in 31s). Three changes close it from both sides: the spoke's self image switch is idempotent and leaves a Deployment that already carries the target alone; the spoke refreshes the image ref it reports the moment its patch lands, instead of serving the pre-switch value from cache for minutes; and the hub re-sends the same switch tag to a hive no more often than the stale-upgrade window, which protects spokes still running a build without the first two fixes. A different tag is still delivered on the very next beat.
