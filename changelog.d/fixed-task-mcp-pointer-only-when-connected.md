- Kicks: the "Task context MCP" pointer is now sent only to agents that have the `hive-task` MCP server. Every kick told its agent "The `hive-task` MCP server is connected for this launch. Call `context_bundle` first", but only a Claude Code launch is given that server, so agents on copilot, codex, gemini, goose, omp, pi, agy, bob, cline and the other non-Claude backends were told on every kick to call a tool they do not have. With `task_mcp.drop_stuffed_context: true` their issue and PR lists were also cut down to bare `repo#N` refs, leaving them with neither the lists nor the server. The pointer and the elision now apply only to an agent that launches as Claude Code (an inference backend or a model gateway counts, and an agent that provider rotation moved to another backend is judged by the backend it runs on) on a hive with a dashboard token; without that token no launch token is minted and the endpoint refuses every call, so no agent on such a hive is pointed at it. Every other agent gets the kick it had before the pointer existed.
