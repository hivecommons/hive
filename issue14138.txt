### clubanderson 2026-10-25T12:01:43Z
/hive decision A

Hive consumes its own `crux serve` API. Separation is the goal; do it in stages so no stage breaks a hosted hive, and keep in-process the default until parity is proven.

**Staging (one PR series per stage, `Refs #14138`, ratchet shrinks only when a stage flips):**

1. **Runtime seam.** A `Runtime` interface in the `crux` root covering what `cmd/hive` and `pkg/dashboard` use today (the 12 host-wiring symbols plus the dashboard's process/pane/kick reads). Two implementations: the existing in-process `*agent.Manager` and `api.Client`. Selected by config (`crux.mode: inprocess|sidecar`), default `inprocess`. No behaviour change.

2. **Credential direction (decide and record in crux.md before coding).** The runtime must not hold the GitHub App key. Hive provides minting via callbacks - the already-inverted `TokenScoper` / `TokenMinter` / `AgentMintIssuer` seams - over a hive-side callback endpoint the runtime calls. Same for `LinearCredential` and `PRCreator`: hive-provided capabilities, not runtime features. `crux/api` stays minimal and engine-shaped; hive-specific capabilities live in hive.

3. **Endpoint families** the current API lacks: streamed turn with cancel (`RunAgyTurn`), resume with busy/gone states (`ResumeHandle`, `ErrResumeBusy`, `ErrResumeSessionGone`), watchdog fleet observe/clear (`WatchdogFleet`), permissions watcher. Each lands with the client method and a parity test asserting every `cli` verb and every `Runtime` method has an API route.

4. **Failure semantics + supervision.** Define and test what governor, kicks, stall/crash-loop detection do when the socket is gone (proposal: agents enter `unknown`, no new dispatch, existing holds kept, reconnect with backoff, alarm in the fleet quadrant). Supervision: hive execs and supervises `crux serve` in the same container by default; k8s sidecar container as an option in the chart. Health on `/v1/health`.

5. **Dashboard via the client.** Pane/log/kick state through SSE instead of in-memory reads; keep the existing hidden/collapsed polling guards. Measure against the #13764 baseline before flipping.

6. **Flip.** Default `sidecar`, remove the in-process construction from `cmd/hive`, inbound ratchet → 0, move `cmd/crux` into the nested module, first `crux/vX.Y.Z` tag, record the `go get` path caveat. v6 top-up per stage.

Guardrails: outbound ratchet stays empty throughout; no stage merges without the parity test green; in-process path is deleted only in stage 6. The generic MITM tool policy stays a separate `kind/spec` child - please file it.
