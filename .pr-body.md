## Investigation

The probe rejection in the issue happens at push time, which means the token minted fine but carried no workflows permission. Two independent layers were missing:

1. **Ops (App settings, not repo code):** the hive GitHub App installation lacks the **Workflows: Read and write** grant. Only the App owner can flip this, and each existing installation must then **re-accept** the updated permission.
2. **Repo code:** `ScopedTokenForRepos` never *requested* `workflows` for any tier — an installation token's permissions are `requested ∩ granted`, so even after the maintainer flips the App setting, trusted-tier tokens would still mint without workflows and pushes would keep failing. This half is fixed here.

There is no silent failure in the sandboxed contributor path: the pushbroker already rejects `.github/workflows/` as a protected path with an explicit error before push. The direct trusted-tier push path also fails loudly (git's remote-rejected message, quoted in the issue). What was missing was the ability to succeed at all.

## Change

- `trusted`/`merger` tier mints now request `workflows:write`.
- **Graceful fallback:** on installations that haven't accepted the grant, the mint is refused by GitHub — the broker retries once without workflows and logs a warning naming the exact operator action, instead of breaking every trusted-tier token. (Verified by test simulating GitHub's refusal.)
- `contributor`/`newcomer`/`advisor` deliberately never request it: the pushbroker's protected-path boundary for sandboxed contributors only means something if their tokens cannot write workflows either. Test pins the full per-tier matrix.
- `src/docs/github-app-setup.md` permission table gains the Workflows row, including the re-accept-per-installation step (the PAT section already says to mirror the App table, so fine-grained PATs are covered by the same row).

## What the maintainer must still click (ops half of #4677)

1. GitHub → Settings → Developer settings → GitHub Apps → *hive app* → **Permissions & events** → Repository permissions → **Workflows → Read and write** → Save.
2. On the kubestellar org installation: Settings → GitHub Apps → *hive app* → review/accept the updated permission request.

Until then, the new fallback keeps trusted mints working and logs the missing grant on every mint.
