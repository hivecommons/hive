# ACMM Level 4 — Security-Aware (Adaptive)

Use this fragment with the authoritative [ACMM policy matrix](../../src/docs/acmm-policy-matrix.md). Level 4 allows all implementation lanes to surface findings, while only selected lanes may open hold-gated PRs.

## Lane permissions

- **scanner** and **guide** — measured mode: may create GitHub issues, but not PRs.
- **ci-maintainer**, **quality**, and **sec-check** — hold-gated mode: may create issues and PRs with the required hold/review gate.
- **supervisor** and **brainstorm** — advisory only.
- **reviewer** — advisory with the converse capability: posts PR review comments on the hold-gated queue using `reviewer-queue.md`. No approve, lgtm, or merge.

## What all agents MUST NOT do

- **DO NOT merge pull requests** — L4 is not an auto-merge level.
- **DO NOT remove hold/review labels from your own PRs**.
- **DO NOT delete branches** — branch cleanup is a post-merge human action.
- **DO NOT push directly to main** — feature branches only for lanes that may create PRs.
- **DO NOT close issues without evidence** — link a merged PR or document why the issue is invalid/duplicate.

## Reviewer (review-only, no merge power)

The pack includes the `reviewer` agent (community vote 2026-10-22: the reviewer ships at L2 and every level above). It wakes every 30 minutes, works the open PR queue at the PR head, and posts review comments with file:line evidence so the human who lifts the `hold` label has repo-grounded evidence. It routes `requires_human` / `reject` verdicts to a maintainer via the triage label.

The reviewer gets exactly the authority this level already grants to review and nothing more: it never approves, applies `lgtm`, merges, closes, pushes, removes a hold label, or dispatches a fixer. The `hold` gate on agent PRs is lifted by a human, not by a reviewer verdict.

## Hold-gated PR workflow

1. Create a signed commit on a feature branch.
2. Open a PR with a clear description and `Fixes #N` references where applicable.
3. Ensure the PR remains review-gated for humans or higher-trust automation.
4. Stop after opening/updating the PR; do not merge it.
